## 정렬 알고리즘

### 정렬 개요

* 시간 복잡도 비교
  * 버블 정렬: 최선 O(n), 평균 O(n²), 최악 O(n²), 공간 O(1), 안정 정렬
  * 선택 정렬: 최선 O(n²), 평균 O(n²), 최악 O(n²), 공간 O(1), 불안정 정렬
  * 삽입 정렬: 최선 O(n), 평균 O(n²), 최악 O(n²), 공간 O(1), 안정 정렬
  * 셸 정렬: 최선 O(n log n), 평균 O(n^1.5), 최악 O(n²), 공간 O(1), 불안정 정렬
  * 합병 정렬: 최선 O(n log n), 평균 O(n log n), 최악 O(n log n), 공간 O(n), 안정 정렬
  * 퀵 정렬: 최선 O(n log n), 평균 O(n log n), 최악 O(n²), 공간 O(log n), 불안정 정렬
  * 힙 정렬: 최선 O(n log n), 평균 O(n log n), 최악 O(n log n), 공간 O(1), 불안정 정렬
  * 기수 정렬: 최선 O(kn), 평균 O(kn), 최악 O(kn), 공간 O(n+k), 안정 정렬
  * 계수 정렬: 최선 O(n+k), 평균 O(n+k), 최악 O(n+k), 공간 O(k), 안정 정렬

> 안정 정렬: 동일 키 값의 원소 순서가 정렬 후에도 유지됨

### 비교 기반 정렬

* 버블 정렬(Bubble Sort)
  * 인접한 두 원소 비교 후 교환, 반복
  * 매 패스마다 가장 큰 값이 맨 뒤로 이동
  * 이미 정렬된 경우 O(n)
  * 조기 종료 조건이 있을 때만 최선 O(n)
  * 구현 단순, 실용성 낮음

* 선택 정렬(Selection Sort)
  * 미정렬 구간에서 최솟값 선택 → 맨 앞과 교환
  * 교환 횟수 최소
  * 비교 횟수는 항상 O(n²)
  * 데이터 이동 비용이 큰 경우 유리

* 삽입 정렬(Insertion Sort)
  * 정렬된 부분에 현재 원소를 올바른 위치에 삽입
  * 거의 정렬된 데이터에 매우 효율적
  * 온라인 알고리즘
  * 데이터가 들어오는 순서대로 처리 가능

* 셸 정렬(Shell Sort)
  * 삽입 정렬 개선판
  * 일정 간격(Gap)으로 부분 리스트 구성 후 삽입 정렬 적용
  * Gap을 줄여가며 반복
  * 마지막 Gap이 1이면 일반 삽입 정렬
  * 삽입 정렬보다 빠르지만 Gap 설정에 따라 성능 차이

* 합병 정렬(Merge Sort)
  * 분할 정복(Divide and Conquer) 기법
  * 리스트를 절반씩 분할 → 각각 정렬 → 합병
  * 최악도 O(n log n) 보장
  * 안정 정렬
  * 추가 메모리 O(n) 필요
  * 외부 정렬에 적합

* 퀵 정렬(Quick Sort)
  * 분할 정복 기법
  * 피벗(Pivot) 선택 → 피벗 기준 좌·우 분할 → 재귀 정렬
  * 평균 O(n log n)
  * 실제 사용에서 빠른 편
  * 이미 정렬된 데이터에서 피벗이 항상 최솟값이나 최댓값이면 최악 O(n²)
  * 피벗 선택 방법: 첫 원소, 중간 원소, 랜덤, 중앙값(Median of 3)

* 힙 정렬(Heap Sort)
  * 최대 힙(Max Heap) 구성 → 루트 추출 → 힙 재구성 반복
  * 최악도 O(n log n) 보장
  * 추가 메모리 불필요
  * 불안정 정렬
  * 캐시 효율이 낮아 실제로는 퀵 정렬보다 느릴 수 있음
  * 힙(Heap): 완전 이진 트리, 부모 노드 ≥ 자식 노드

> 문제 예시: [3, 20, 21, 17, 6, 10] 의 버블 정렬 3회의 결과는?

### 분산 정렬

> 비교 없이 정렬 — 비교 기반 정렬의 하한 O(n log n) 돌파 가능

* 기수 정렬(Radix Sort)
  * 자릿수(Digit) 기준으로 분류
  * 낮은 자릿수부터 정렬
  * LSD(Least Significant Digit): 낮은 자릿수 → 높은 자릿수
  * MSD(Most Significant Digit): 높은 자릿수 → 낮은 자릿수
  * 정수·문자열 정렬에 적합
  * 음수 처리 복잡
  * k = 최대 자릿수, 시간 복잡도 O(kn)

* 계수 정렬(Counting Sort)
  * 각 원소의 등장 횟수를 배열에 저장 후 누적합으로 위치 결정
  * 데이터 범위(k)가 작을 때 O(n+k)로 매우 빠름
  * 범위가 크면 메모리 낭비 심각
  * 정수 또는 정수로 변환 가능한 데이터에만 적용

## 트리

### 힙

* 완전 이진 트리 기반의 우선순위 자료구조

* 모든 노드가 부모와 자식 사이의 대소 관계를 만족. 

* MaxHeap인 경우, 부모가 자식보다 크기만 하면 됨 

* 루트 노드에 우선순위가 가장 높은 값이 위치

* 삽입과 삭제 후 힙 조건을 유지하기 위해 재구성 수행

* 배열 예시
  * 최대 힙: `[80, 50, 70, 20, 30, 60, 40]`

  * 배열은 완전 이진 트리를 위에서 아래, 왼쪽에서 오른쪽 순서로 저장

```
        80
      /    \
    50      70
   /  \    /  \
 20   30  60   40
```

* 루트 노드 `80` 삭제 후 재배치 예시
  * 마지막 노드 `40`을 루트로 이동

  * 자식 노드 중 더 큰 값인 `70`과 교환

  * 다시 자식 노드 중 더 큰 값인 `60`과 교환

  * 최종 최대 힙: `[70, 50, 60, 20, 30, 40]`

```
80 삭제 후 마지막 노드 40을 루트로 이동

        40
      /    \
    50      70
   /  \    /
 20   30  60

70과 교환

        70
      /    \
    50      40
   /  \    /
 20   30  60

60과 교환

        70
      /    \
    50      60
   /  \    /
 20   30  40
```
