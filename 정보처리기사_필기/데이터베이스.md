## DB 개요 (6)

### 용어 

* 자료: 발생된 사실 그 자체. 가공되지 않은 상태 
* 정보: 데이터를 가공한 것. 주관적 가치 판단 개입. 

* 관계형 데이터 모델(Relational Data Model): 데이터를 2차원 테이블인 릴레이션(Relation)으로 표현하는 데이터 모델

* Attribute: 테이블의 열
* Tuple: 테이블의 행 
* degree: 하나의 릴레이션에 속성의 전체 개수 
* cardinality: 하나의 릴레이션에서 튜플의 전체 개수

### DB의 특징 

* 실시간 접근성 
* 계속적인 변화 
* 동시공유 
* 내용에 의한 참조

### DBMS의 장단점 

* 장점 
  * 데이터 중복 최소화 
  * 데이터 공유 
  * 데이터 무결성 유지 
  * 데이터의 일관성 유지 
  * 데이터 보안 보장 
  * 응용 프로그램과 데이터의 독립성 유지 
  * 표준화의 달성 

* 단점
  * 운영비의 증대 
  * DB tj

### 시스템 카탈로그

* DB 시스템 자체의 정보와 관련이 있는 시스템 데이터베이스. 메타데이터를 저장

* 메타데이터: 시스템 카탈로그에 저장된 정보
  * DB 객체 정보: 테이블, 인덱스, 뷰 등
  * 사용자 정보: 아이디, 패스워드, 접근 권한 등
  * 테이블 무결성 제약 조건 정보: 기본키, 외래키 등
  * 함수, 프로시저, 트리거 등의 정보

* 데이터 디렉토리(Data Directory)
  * 시스템 카탈로그에 저장된 메타데이터 중 DBMS가 내부적으로 사용하는 정보
  * 데이터의 위치, 저장 구조, 접근 경로 등 DB 운용에 필요한 정보를 저장
  * 사용자가 직접 검색하거나 갱신하지 않음
  * 시스템 카탈로그보다 사용자 접근성이 제한된 내부 관리 정보

* 특징
  * 일반 이용자도 SQL을 사용해 내용 검색 가능
  * DBMS가 스스로 생성 및 유지. 사용자에 의한 갱신 불가능.

### 스키마

* 스키마(Schema)
  * 데이터베이스의 구조, 제약 조건, 데이터 간 관계를 정의한 명세
  * 데이터의 실제 값인 인스턴스(Instance)와 구분됨

* 외부 스키마(External Schema)
  * 사용자가 필요한 데이터베이스의 논리적 구조를 정의

* 개념 스키마(Conceptual Schema)
  * DB의 전체적 논리적 구조
  * 하나만 존재 
  * 개체 간의 관계와 제약 조건. 데이터베이스의 접근 권한. 보안 및 무결성 규칙에 관한 명세. 

* 내부 스키마(Internal Schema)
  * 물리적인 데이터베이스 구조
  * 데이터베이스에 저장될 레코드의 형식. 저장 데이터 항목의 표현 방법. 내부 레코드의 물리적 순서

### 무결성 제약

* 무결성(Integrity)
  * 데이터베이스에 저장된 데이터의 정확성, 일관성, 유효성을 유지하는 성질

* 무결성 제약(Integrity Constraint)
  * 잘못된 데이터 삽입, 수정, 삭제를 방지하기 위해 DBMS가 강제하는 규칙
  * 트랜잭션 수행 전후 데이터베이스가 일관된 상태를 유지하도록 보장

* 개체 무결성(Entity Integrity)
  * 기본키(Primary Key)는 NULL 값을 가질 수 없음
  * 기본키 값은 릴레이션 내에서 중복될 수 없음
  * 각 튜플을 유일하게 식별하기 위한 제약

* 참조 무결성(Referential Integrity)
  * 외래키(Foreign Key)는 참조하는 릴레이션의 기본키 값과 일치해야 함
  * 외래키 값은 참조 대상에 존재하는 값이거나 NULL이어야 함
  * 관련 없는 데이터를 참조하는 현상 방지

* 도메인 무결성(Domain Integrity)
  * 속성 값은 정의된 도메인 범위 안의 값이어야 함
  * 데이터 타입, 길이, 형식, 기본값, 허용 범위 등을 제한

* 사용자 정의 무결성(User-defined Integrity)
  * 업무 규칙에 따라 사용자가 정의하는 제약
  * 예: 재고 수량은 0 이상, 종료일은 시작일보다 늦어야 함

* 키 무결성(Key Integrity)
  * 후보키, 기본키, 대체키 등 키 값은 튜플을 유일하게 식별해야 함
  * 중복된 키 값 허용 불가

* NULL 무결성(NULL Integrity)
  * 특정 속성에 NULL 값 입력을 허용하지 않는 제약
  * 필수 입력 값 보장

* 고유 무결성(Unique Integrity)
  * 특정 속성 값이 릴레이션 내에서 중복되지 않도록 제한
  * 후보키나 대체키 성격의 속성에 사용

* 관계 무결성(Relationship Integrity)
  * 릴레이션 간 관계의 논리적 일관성을 유지하는 제약
  * 참조 무결성을 포함하는 넓은 의미로 사용

```sql
CREATE TABLE 학생 (
    학번 CHAR(10) PRIMARY KEY,
    이름 VARCHAR(20) NOT NULL,
    이메일 VARCHAR(50) UNIQUE,
    학년 INT DEFAULT 1 CHECK (학년 BETWEEN 1 AND 4),
    학과코드 CHAR(5),
    FOREIGN KEY (학과코드) REFERENCES 학과(학과코드)
);
```

### ER 다이어그램

#### 개요

* Entity-Relationship Diagram. 데이터베이스 논리적 설계 단계 산출물
* Peter Chen이 1976년 제안
* 개체(Entity), 속성(Attribute), 관계(Relationship)로 데이터 구조 표현

#### 구성 요소

* **개체(Entity)**: 저장할 데이터 대상. 사각형(`□`)으로 표현
    * 강개체(Strong Entity): 독립적으로 존재 가능
    * 약개체(Weak Entity): 다른 개체에 의존. 이중 사각형(`□□`)으로 표현

* **속성(Attribute)**: 개체의 특성·성질. 타원(`○`)으로 표현
    * 기본 속성: 단순 값
    * 키 속성: 개체 유일 식별. 밑줄 표시
    * 다중값 속성: 값 여러 개 가능. 이중 타원으로 표현
    * 복합 속성: 여러 속성으로 구성
    * 유도 속성: 다른 속성으로 계산 가능. 점선 타원으로 표현

* **관계(Relationship)**: 개체 간 연관. 마름모(`◇`)로 표현
    * 식별 관계: 약개체가 강개체의 키에 의존. 이중 마름모
    * 비식별 관계: 독립적 기본키 보유

#### 관계의 차수(Cardinality)

* **1:1**: 한 개체가 다른 개체 하나와만 대응
* **1:N**: 한 개체가 다른 개체 여러 개와 대응
* **N:M**: 양쪽 개체 모두 여러 개와 대응 → 구현 시 중간 테이블로 분해

#### ERD 표기법

| 표기법 | 특징 |
|--------|------|
| **Chen** | 원조 표기법. 사각형·타원·마름모 사용. 학술적 |
| **IE(Information Engineering)** | 새발(Crow's Foot) 기호로 카디널리티 표현. 실무 多 사용 |
| **Barker** | Oracle 주로 사용. IE와 유사 |

### 이상(Anomaly)

* 이상(Anomaly)
  * 정규화가 충분하지 않은 릴레이션에서 데이터 중복으로 인해 발생하는 논리적 문제
  * 삽입, 삭제, 갱신 작업 시 의도하지 않은 부작용이 생김
  * 함수적 종속 관계를 적절히 분리하지 않았을 때 주로 발생

* 삽입 이상(Insertion Anomaly)
  * 새 데이터를 삽입하려면 불필요한 데이터까지 함께 입력해야 하는 문제
  * 일부 속성 값이 아직 없으면 필요한 데이터 자체를 삽입하지 못할 수 있음
  * 예: 학생 정보와 수강 정보가 같은 테이블에 있을 때, 수강 과목이 없는 신입생 정보를 입력하지 못함

* 삭제 이상(Deletion Anomaly)
  * 특정 데이터를 삭제할 때 보존해야 할 데이터까지 함께 삭제되는 문제
  * 예: 학생의 마지막 수강 기록을 삭제했더니 학생 기본 정보까지 사라짐

* 갱신 이상(Update Anomaly)
  * 중복 저장된 데이터 중 일부만 수정되어 데이터 불일치가 발생하는 문제
  * 예: 같은 학과명이 여러 튜플에 반복 저장되어 있을 때 일부 튜플만 수정되어 학과명이 서로 달라짐

* 이상 발생 원인
  * 하나의 릴레이션에 서로 다른 주제의 데이터가 함께 저장됨
  * 부분 함수 종속, 이행적 함수 종속이 제거되지 않음
  * 같은 의미의 데이터가 여러 튜플에 중복 저장됨

* 해결 방법
  * 정규화를 통해 릴레이션을 적절히 분해
  * 데이터 중복을 줄이고 함수적 종속 관계를 명확히 분리
  * 필요 시 기본키와 외래키로 분해된 릴레이션 사이의 참조 무결성 유지

### 정규화 개요

* 데이터 중복 제거 및 이상(Anomaly) 방지를 위해 릴레이션을 분해하는 과정

* 함수적 종속성(Functional Dependency) 이론 기반

* 정규형 단계가 높을수록 중복 감소, 무결성 향상 — 단, 조인 연산 증가로 성능 저하 가능

* 함수적 종속(FD; Functional Dependency)
  * 속성 X 값이 결정되면 속성 Y 값이 유일하게 결정되는 관계
  * `X → Y`: X가 Y를 함수적으로 결정

* 결정자(Determinant)
  * 함수적 종속 관계 `X → Y`에서 다른 속성 값을 결정하는 속성
  * 예: `학번 → 이름`에서 학번은 결정자

* 종속자(Dependent)
  * 함수적 종속 관계 `X → Y`에서 결정자에 의해 값이 결정되는 속성
  * 예: `학번 → 이름`에서 이름은 종속자

### 정규화

* 제1정규형(1NF; First Normal Form)
  * 모든 속성값이 원자값(Atomic Value)이어야 함
  * 반복 그룹, 다중값 속성 제거

* 제2정규형(2NF; Second Normal Form)
  * 1NF 만족 + 부분 함수 종속 제거
  * 기본키가 복합키일 때, 기본키의 일부에만 종속된 속성 분리

> 완전 함수 종속: 기본키 전체에 종속

* 제3정규형(3NF; Third Normal Form)
  * 2NF 만족 + 이행적 함수 종속 제거
  * 이행 종속: `A → B → C` 관계에서 `A → C` 도출

* 보이스-코드 정규형(BCNF; Boyce-Codd Normal Form)
  * 3NF 강화판
  * 모든 결정자(Determinant)가 후보키여야 함
  * 3NF를 만족해도 BCNF 위반 가능
  * 후보키가 여러 개이거나 복합키가 중첩될 때 발생 가능

* 제4정규형(4NF; Fourth Normal Form)
  * BCNF 만족 + 다치 종속(Multi-valued Dependency) 제거

* 제5정규형(5NF; Fifth Normal Form)
  * 4NF 만족 + 조인 종속(Join Depende ncy) 제거

* 정규형 순서
  * 1NF: 원자값
  * 2NF: 1NF + 부분 함수 종속 제거
  * 3NF: 2NF + 이행적 종속 제거
  * BCNF: 3NF + 모든 결정자가 후보키
  * 4NF: BCNF + 다치 종속 제거
  * 5NF: 4NF + 조인 종속 제거

### 정규화 예제

* 1NF 위반 — 비원자값 존재

| 학번 | 이름 | 수강과목 |
|------|------|----------|
| 001 | 김철수 | 수학, 영어, 과학 |
| 002 | 이영희 | 국어 |

`수강과목` 컬럼에 다중값 → 1NF 위반

**1NF 적용 후**

| 학번 | 이름 | 수강과목 |
|------|------|----------|
| 001 | 김철수 | 수학 |
| 001 | 김철수 | 영어 |
| 001 | 김철수 | 과학 |
| 002 | 이영희 | 국어 |

* 2NF 위반 — 부분 함수 종속

기본키: (학번, 과목코드) 복합키

| 학번 | 과목코드 | 성적 | 학생이름 |
|------|----------|------|----------|
| 001 | C01 | A | 김철수 |
| 001 | C02 | B | 김철수 |
| 002 | C01 | A | 이영희 |

`학생이름`은 `학번`만으로 결정 → 기본키 일부에 종속 → 2NF 위반

**2NF 적용 후** — 분리

| 학번 | 과목코드 | 성적 |
|------|----------|------|
| 001 | C01 | A |
| 001 | C02 | B |
| 002 | C01 | A |

| 학번 | 학생이름 |
|------|----------|
| 001 | 김철수 |
| 002 | 이영희 |

* 3NF 위반 — 이행적 함수 종속

| 학번 | 학과코드 | 학과명 |
|------|----------|--------|
| 001 | D01 | 컴퓨터공학과 |
| 002 | D02 | 전기공학과 |
| 003 | D01 | 컴퓨터공학과 |

`학번 → 학과코드 → 학과명` 이행 종속 → `학과명`이 기본키 아닌 `학과코드`에 종속 → 3NF 위반

**3NF 적용 후** — 분리

| 학번 | 학과코드 |
|------|----------|
| 001 | D01 |
| 002 | D02 |
| 003 | D01 |

| 학과코드 | 학과명 |
|----------|--------|
| D01 | 컴퓨터공학과 |
| D02 | 전기공학과 |

* BCNF 위반 — 결정자가 후보키 아님

수강 테이블. 한 교수는 한 과목만 담당. 학생은 과목당 교수 한 명.

기본키: (학번, 과목명) / 후보키: (학번, 교수명)

| 학번 | 과목명 | 교수명 |
|------|--------|--------|
| 001 | DB | 홍교수 |
| 002 | DB | 홍교수 |
| 001 | OS | 김교수 |

`교수명 → 과목명` 성립 — 교수명이 결정자이나 후보키 아님 → BCNF 위반

**BCNF 적용 후** — 분리

| 교수명 | 과목명 |
|--------|--------|
| 홍교수 | DB |
| 김교수 | OS |

| 학번 | 교수명 |
|------|--------|
| 001 | 홍교수 |
| 002 | 홍교수 |
| 001 | 김교수 |

### 반정규화

* 정규화로 인한 과도한 조인 성능 저하를 해소하기 위해 의도적으로 중복 허용

* 읽기 성능 ↑, 데이터 무결성 관리 부담 ↑

### 반정규화-테이블 관리

* 테이블 합병
  * 자주 함께 조회되는 테이블을 하나로 합쳐 조인 횟수를 줄이는 방법

* 테이블 분할
  * 하나의 큰 테이블을 업무 특성이나 접근 빈도에 따라 여러 테이블로 나누는 방법
  * 수직 분할: 속성을 기준으로 테이블 분할
  * 수평 분할: 레코드를 기준으로 테이블 분할

- 중복 테이블로 작업의 효율 향상 
  - 여러 테이블에서 데이터를 추출하는 경우 
  - 다른 서버에 저장된 테이블을 이용하는 경우 

- 방법
  - 집계 테이블 추가: 집계 데이터를 위한 테이블 생성. 원본 테이블에 트리거를 설정.  
  - 진행 테이블 추가: 이력 관리 등의 목적
  - 특정 부분만을 포함하는 테이블 추가: 데이터가 많은 테이블에서 특정 부분만을 사용하는 경우

## 트랜잭션 관리 (4)

### 트랜잭션의 상태

* 활성(Active)
  * 트랜잭션이 실행 중인 상태

* 부분 완료(Partially Committed)
  * 마지막 명령문 실행이 끝났지만 아직 Commit 전인 상태

* 완료(Committed)
  * 트랜잭션이 성공적으로 끝나고 변경 내용이 DB에 영구 반영된 상태

* 실패(Failed)
  * 오류나 장애로 트랜잭션 실행을 계속할 수 없는 상태

* 철회(Aborted)
  * 트랜잭션 실패 후 Rollback으로 실행 이전 상태로 되돌린 상태

```
Active → Partially Committed → Committed
  ↓             |
Failed ←────────┘
  ↓
Aborted
```

### 트랜잭션의 특성

* 원자성(Atomicity)
  * 트랜잭션 연산은 모두 수행되거나 모두 수행되지 않아야 함
  * 일부만 실행된 상태는 허용하지 않음

* 일관성(Consistency)
  * 트랜잭션 수행 전후 데이터베이스는 일관된 상태를 유지해야 함
  * 무결성 제약 조건을 위반하지 않아야 함

* 격리성(Isolation)
  * 동시에 실행되는 트랜잭션은 서로 간섭하지 않아야 함
  * 각 트랜잭션은 독립적으로 실행되는 것처럼 보여야 함

* 지속성(Durability)
  * Commit된 결과는 장애가 발생해도 영구적으로 보존되어야 함
  * 회복 기법과 로그를 통해 보장

### 병행 제어 기법

* 여러 트랜잭션을 동시에 실행하면서 데이터베이스 일관성을 유지하는 기법

* 로킹(Locking)
  * 트랜잭션이 데이터에 접근하기 전 잠금을 설정하고 작업 완료 후 해제
  * 다른 트랜잭션의 동시 접근을 제한해 충돌 방지
  * 교착 상태가 발생할 수 있음

* 2단계 로킹(2PL; Two-Phase Locking)
  * 확장 단계: 잠금 획득만 가능하고 해제 불가
  * 축소 단계: 잠금 해제만 가능하고 획득 불가
  * 직렬 가능성을 보장하지만 교착 상태가 발생할 수 있음

* 타임스탬프 순서 기법(Timestamp Ordering)
  * 트랜잭션에 시간표를 부여
  * 시간 순서대로 실행 결과를 검증
  * 오래된 트랜잭션이 최신 데이터에 부적절하게 접근하면 철회
  * 교착 상태는 발생하지 않지만 Rollback 증가 가능

* 낙관적 병행 제어(Optimistic Concurrency Control)
  * 충돌이 적다고 가정하고 먼저 실행한 뒤 검증 단계에서 충돌 여부 확인
  * 읽기 단계 → 검증 단계 → 쓰기 단계 순서로 수행
  * 충돌이 적은 환경에서 효율적

* 다중 버전 병행 제어(MVCC; Multi-Version Concurrency Control)
  * 데이터 여러 버전을 유지해 읽기와 쓰기 충돌을 줄이는 기법
  * 읽기 작업은 이전 버전을 보고 쓰기 작업은 새 버전을 생성
  * 동시성은 높지만 저장 공간과 버전 관리 비용 증가

### 회복(Recovery)

* 트랜잭션 수행 중 장애로 데이터베이스 손상되었을 때 정상 상태로 복구하는 작업

* 검사점 기법(Check point)
  * 트랙잭션 단계별 로그에 기록
  * 장애 발생 시 전체 트랜잭션 철회가 아닌 검사점부터 회복 진행

* 그림자 페이지 대체 기법(Shadow Paging)
  * 갱신 전 데이터 베이스를 페이징 단위로 복제
  * 갱신이 복제한 그림자 페이지 사용
  * 로그, Undo, Redo 불필요

* 연기 갱신 기법(Deferred Update)
  * 갱신 내용 Log에 저장
  * 트랜잭션 성공 직전에 Log에 보관한 내용을 실제 DB에 기록
  * Undo 불필요, Redo 가능

* 즉각 갱신 기법(Immediate Update)
  * 트랜잭션 내용을 바로 실제 DB에 반영
  * 갱신 내용 Log에 보관
  * Redo, Undo 가능

## 데이터베이스 운용 (3)

### 파티션

#### 파티션 개요

* 대용량 테이블이나 인덱스를 논리적 단위로 나누는 것
* 데이터 처리는 테이블 단위, 저장은 파티션별로 수행

* 장점
  * 시스템 장애 영향 최소화
  * 쿼리, 디스크, 복구 성능, 데이터 가용성 향상
  * 파티션 단위로 입출력 분산

* 단점
  * 관리의 어려움
  * 작은 테이블 파티셔닝 시 성능 저하
  * 조인 비용 증가

#### 파티션 종류

* 범위 분할: 지정한 열의 값을 기준으로 범위 지정

* 해시 분할
  * 해시 함수를 적용한 결과 값에 따른 분할
  * 데이터가 고르게 분산되어 있을 때 유용
  * 데이터 위치 판단 불가

* 조합 분할
  * 범위 분할 + 해시 분할
  * 범위 분할 파티션이 큰 경우 사용

* 목록 분할
  * 지정한 열 값에 대한 목록 생성
  * ex: 국가라는 열에서 한국, 일본을 묶기 위해 아시아 목록 생성

* 라운드 로빈 분할
  * 레코드 균일 분배
  * 레코드 순차적 분배
  * 기본키 불필요

### 분산 데이터베이스

* 물리적으로 분산된 여러 사이트에 데이터를 저장하고, 네트워크로 연결하여 논리적으로 하나의 DB처럼 운영

#### 분산 DB 목표

| 목표 | 설명 |
|------|------|
| **위치 투명성(Location Transparency)** | 데이터가 어느 사이트에 있는지 몰라도 접근 가능 |
| **중복 투명성(Replication Transparency)** | 데이터가 여러 곳에 복제되어 있어도 단일 데이터처럼 사용 |
| **병행 투명성(Concurrency Transparency)** | 여러 트랜잭션 동시 실행 시 결과 일관성 보장 |
| **장애 투명성(Failure Transparency)** | 일부 사이트 장애 시에도 정상 동작 |
| **분할 투명성(Division Transparency)** | 데이터가 분할 저장되어 있어도 전체로 인식 |

> 투명성 = 사용자가 분산 사실을 **의식하지 않아도 됨**

---

### DB 보안 - 접근 제어

* DB 보안
  * 데이터베이스에 저장된 데이터를 무단 접근, 변조, 삭제, 유출로부터 보호하는 활동
  * 기밀성, 무결성, 가용성 유지를 목표로 함

* 접근 제어
  * 사용자별로 데이터 접근 권한을 제한하는 방법
  * DBMS 계정, 역할(Role), 권한(Privilege)을 이용해 허가된 사용자만 데이터에 접근하게 함
  * GRANT로 권한 부여, REVOKE로 권한 회수

* 임의 접근 제어(DAC; Discretionary Access Control)
  * 데이터 소유자가 사용자에게 접근 권한을 부여하거나 회수하는 방식
  * 권한 관리가 유연하지만 권한 전파로 보안 통제가 약해질 수 있음

* 강제 접근 제어(MAC; Mandatory Access Control)
  * 보안 등급과 규칙에 따라 접근을 강제 통제하는 방식
  * 사용자가 임의로 권한을 부여할 수 없음
  * 높은 보안이 필요한 환경에 적합

* 역할 기반 접근 제어(RBAC; Role-Based Access Control)
  * 사용자에게 직접 권한을 주지 않고 역할에 권한을 부여하는 방식
  * 사용자는 배정된 역할을 통해 권한을 획득
  * 조직 단위 권한 관리에 적합

## 관계 데이터 연산 (4)

### 관계대수 정의

* 관계대수(Relational Algebra)
  * 관계형 데이터베이스에서 원하는 데이터를 얻기 위해 릴레이션을 연산하는 절차적 질의 언어
  * 연산의 순서와 방법을 명시
  * 하나 이상의 릴레이션을 입력으로 받아 새로운 릴레이션을 결과로 반환

### 순수 관계 연산자 (4)

* 관계형 데이터 모델을 위해 새로 정의된 연산자

* 셀렉트(Select; σ)
  * 조건을 만족하는 튜플을 선택
  * 예: 학생 릴레이션에서 학년이 3인 튜플 검색

```text
학생
(1, 김철수, 3)
(2, 이영희, 2)
(3, 박민수, 3)

σ 학년=3 (학생)
→ (1, 김철수, 3)
→ (3, 박민수, 3)
```

* 프로젝트(Project; π)
  * 원하는 속성만 선택
  * 예: 학생 릴레이션에서 이름 속성만 검색

```text
학생
(1, 김철수, 3)
(2, 이영희, 2)

π 이름 (학생)
→ (김철수)
→ (이영희)
```

* 조인(Join; ⋈)
  * 공통 속성을 기준으로 릴레이션을 결합
  * 예: 학생 릴레이션과 학과 릴레이션을 학과코드로 결합

```text
학생
(1, 김철수, C01)
(2, 이영희, C02)

학과
(C01, 컴퓨터공학과)
(C02, 전기공학과)

학생 ⋈ 학과
→ (1, 김철수, C01, 컴퓨터공학과)
→ (2, 이영희, C02, 전기공학과)
```

* 디비전(Division; ÷)
  * 특정 조건을 모두 만족하는 튜플을 검색
  * 예: 모든 필수 과목을 수강한 학생 검색

```text
수강
(김철수, DB)
(김철수, OS)
(이영희, DB)

필수과목
(DB)
(OS)

수강 ÷ 필수과목
→ (김철수)
```

### 일반 집합 연산자 (4)

* 수학의 집합 연산을 릴레이션에 적용한 연산자

* 합집합(Union; ∪)
  * 두 릴레이션의 튜플을 합침
  * 두 릴레이션은 합병 가능해야 함

* 교집합(Intersection; ∩)
  * 두 릴레이션에 공통으로 존재하는 튜플 검색
  * 두 릴레이션은 합병 가능해야 함

* 차집합(Difference; -)
  * 한 릴레이션에는 있고 다른 릴레이션에는 없는 튜플 검색
  * 두 릴레이션은 합병 가능해야 함

* 카티션 프로덕트(Cartesian Product; ×)
  * 두 릴레이션의 모든 튜플 조합 생성
  * 결과 릴레이션의 차수는 두 릴레이션 차수의 합
  * 결과 릴레이션의 카디널리티는 두 릴레이션 카디널리티의 곱

### 관계해석

* 관계해석(Relational Calculus)
  * 원하는 데이터의 조건을 논리식으로 표현하는 비절차적 질의 언어
  * 원하는 결과를 명시하고 처리 방법은 명시하지 않음

## SQL (5)

**SQL 명령어 분류**

| 분류 | 명령어 | 설명 |
|------|--------|------|
| DDL | CREATE, ALTER, DROP, TRUNCATE, RENAME | 데이터 구조 정의 |
| DML | SELECT, INSERT, UPDATE, DELETE | 데이터 조작 |
| DCL | GRANT, REVOKE | 접근 권한 제어 |
| TCL | COMMIT, ROLLBACK, SAVEPOINT | 트랜잭션 제어 |

---

### DDL (Data Definition Language)

* 데이터베이스 객체(테이블, 인덱스, 뷰 등) 구조 정의·변경·삭제

* **자동 COMMIT** — 실행 즉시 반영, 롤백 불가

| 명령어 | 설명 |
|--------|------|
| `CREATE` | 객체 생성 |
| `ALTER` | 객체 구조 변경 |
| `DROP` | 객체 삭제 (구조 + 데이터 모두) |
| `TRUNCATE` | 테이블 데이터 전체 삭제 (구조 유지, DELETE보다 빠름) |
| `RENAME` | 객체 이름 변경 |

```sql
-- 테이블 생성
CREATE TABLE 학생 (
    학번   CHAR(10)    PRIMARY KEY,
    이름   VARCHAR(20) NOT NULL,
    학과   VARCHAR(30),
    학년   INT         DEFAULT 1
);

-- 컬럼 추가
ALTER TABLE 학생 ADD 이메일 VARCHAR(50);

-- 컬럼 삭제
ALTER TABLE 학생 DROP COLUMN 이메일;

-- 테이블 삭제
DROP TABLE 학생;

-- 데이터만 전체 삭제 (구조 유지)
TRUNCATE TABLE 학생;
```

---

### DML (Data Manipulation Language)

* 데이터 조회·삽입·수정·삭제

* **자동 COMMIT 아님** — TCL로 트랜잭션 제어 가능

| 명령어 | 설명 |
|--------|------|
| `SELECT` | 데이터 조회 |
| `INSERT` | 데이터 삽입 |
| `UPDATE` | 데이터 수정 |
| `DELETE` | 데이터 삭제 (구조 유지, 롤백 가능) |

```sql
-- 조회
SELECT 이름, 학과 FROM 학생 WHERE 학년 = 2 ORDER BY 이름;

-- 삽입
INSERT INTO 학생 (학번, 이름, 학과, 학년) VALUES ('20240001', '김철수', '컴공', 1);

-- 수정
UPDATE 학생 SET 학년 = 2 WHERE 학번 = '20240001';

-- 삭제
DELETE FROM 학생 WHERE 학번 = '20240001';
```

**SELECT 절 실행 순서**

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
```

### 집계 함수

* 집계 함수
  * 여러 행의 값을 하나의 결과값으로 요약하는 함수

  * `GROUP BY`와 함께 사용하면 그룹별 집계 가능

* COUNT
  * 행이나 컬럼 값의 개수를 계산하는 집계 함수

* `COUNT(*)`
  * 조건에 맞는 전체 행 수를 계산

  * 특정 컬럼 값이 NULL이어도 행 개수에 포함

* `COUNT(컬럼)`
  * 지정한 컬럼 값이 NULL이 아닌 행만 계산

  * NULL 값은 개수에서 제외

* SUM
  * 숫자 컬럼 값의 합계를 계산

  * NULL 값은 제외하고 계산

* AVG
  * 숫자 컬럼 값의 평균을 계산

  * NULL 값은 제외하고 계산

* MAX
  * 컬럼 값 중 최댓값을 계산

* MIN
  * 컬럼 값 중 최솟값을 계산

```text
학생
+------+--------+----------+------+
| 학번 | 이름   | 학과코드 | 점수 |
+------+--------+----------+------+
| 1    | 김철수 | C01      | 90   |
| 2    | 이영희 | C02      | 80   |
| 3    | 박민수 | NULL     | NULL |
+------+--------+----------+------+
```

```sql
SELECT COUNT(*) FROM 학생;
-- 결과: 3

SELECT COUNT(학과코드) FROM 학생;
-- 결과: 2

SELECT SUM(점수) FROM 학생;
-- 결과: 170

SELECT AVG(점수) FROM 학생;
-- 결과: 85

SELECT MAX(점수) FROM 학생;
-- 결과: 90

SELECT MIN(점수) FROM 학생;
-- 결과: 80
```

> `COUNT(*)`는 행 수, `COUNT(컬럼)`은 NULL이 아닌 값 수. `SUM`, `AVG`, `MAX`, `MIN`도 NULL 값은 제외하고 계산

### 조인

* 조인(Join)
  * 두 개 이상의 테이블을 공통 속성이나 조건을 기준으로 연결하여 데이터를 조회하는 연산
  * 정규화로 분리된 테이블의 관련 데이터를 함께 조회할 때 사용

* 예제 테이블

```text
학생
+------+--------+----------+
| 학번 | 이름   | 학과코드 |
+------+--------+----------+
| 1    | 김철수 | C01      |
| 2    | 이영희 | C02      |
| 3    | 박민수 | NULL     |
+------+--------+----------+

학과
+----------+----------+
| 학과코드 | 학과명   |
+----------+----------+
| C01      | 컴퓨터   |
| C02      | 전자     |
| C03      | 기계     |
+----------+----------+
```

* 내부 조인(Inner Join)
  * 조인 조건을 만족하는 행만 조회
  * 두 테이블 모두에 일치하는 값이 있는 데이터만 결과에 포함

```sql
SELECT 학생.이름, 학과.학과명
FROM 학생
INNER JOIN 학과
ON 학생.학과코드 = 학과.학과코드;
```

```text
+--------+--------+
| 이름   | 학과명 |
+--------+--------+
| 김철수 | 컴퓨터 |
| 이영희 | 전자   |
+--------+--------+
```

* 왼쪽 외부 조인(Left Outer Join)
  * 왼쪽 테이블의 모든 행을 조회하고, 오른쪽 테이블은 조건에 맞는 행만 연결
  * 오른쪽 테이블에 일치하는 값이 없으면 NULL로 표시

```sql
SELECT 학생.이름, 학과.학과명
FROM 학생
LEFT OUTER JOIN 학과
ON 학생.학과코드 = 학과.학과코드;
```

```text
+--------+--------+
| 이름   | 학과명 |
+--------+--------+
| 김철수 | 컴퓨터 |
| 이영희 | 전자   |
| 박민수 | NULL   |
+--------+--------+
```

* 오른쪽 외부 조인(Right Outer Join)
  * 오른쪽 테이블의 모든 행을 조회하고, 왼쪽 테이블은 조건에 맞는 행만 연결
  * 왼쪽 테이블에 일치하는 값이 없으면 NULL로 표시

```sql
SELECT 학생.이름, 학과.학과명
FROM 학생
RIGHT OUTER JOIN 학과
ON 학생.학과코드 = 학과.학과코드;
```

```text
+--------+--------+
| 이름   | 학과명 |
+--------+--------+
| 김철수 | 컴퓨터 |
| 이영희 | 전자   |
| NULL   | 기계   |
+--------+--------+
```

* 완전 외부 조인(Full Outer Join)
  * 양쪽 테이블의 모든 행을 조회
  * 한쪽에만 존재하는 데이터는 반대쪽 속성을 NULL로 표시

```sql
SELECT 학생.이름, 학과.학과명
FROM 학생
FULL OUTER JOIN 학과
ON 학생.학과코드 = 학과.학과코드;
```

```text
+--------+--------+
| 이름   | 학과명 |
+--------+--------+
| 김철수 | 컴퓨터 |
| 이영희 | 전자   |
| 박민수 | NULL   |
| NULL   | 기계   |
+--------+--------+
```

* 교차 조인(Cross Join)
  * 두 테이블의 모든 행 조합을 생성
  * 결과 행 수 = 첫 번째 테이블 행 수 × 두 번째 테이블 행 수

```sql
SELECT 학생.이름, 학과.학과명
FROM 학생
CROSS JOIN 학과;
```

```text
+--------+--------+
| 이름   | 학과명 |
+--------+--------+
| 김철수 | 컴퓨터 |
| 김철수 | 전자   |
| 김철수 | 기계   |
| 이영희 | 컴퓨터 |
| 이영희 | 전자   |
| 이영희 | 기계   |
| 박민수 | 컴퓨터 |
| 박민수 | 전자   |
| 박민수 | 기계   |
+--------+--------+
```

* 자기 조인(Self Join)
  * 같은 테이블을 두 번 사용하여 자기 자신과 조인
  * 같은 테이블 안의 계층 관계나 비교 관계를 조회할 때 사용

```sql
SELECT 사원.이름, 관리자.이름 AS 관리자명
FROM 사원
INNER JOIN 사원 AS 관리자
ON 사원.관리자번호 = 관리자.사원번호;
```

```text
사원
+----------+--------+------------+
| 사원번호 | 이름   | 관리자번호 |
+----------+--------+------------+
| 1        | 김부장 | NULL       |
| 2        | 이대리 | 1          |
| 3        | 박사원 | 2          |
+----------+--------+------------+

결과
+--------+----------+
| 이름   | 관리자명 |
+--------+----------+
| 이대리 | 김부장   |
| 박사원 | 이대리   |
+--------+----------+
```

* 자연 조인(Natural Join)
  * 두 테이블에서 이름이 같은 속성을 자동으로 기준 삼아 조인
  * 같은 이름의 속성이 의도와 다르면 잘못된 결과가 나올 수 있음

```sql
SELECT *
FROM 학생
NATURAL JOIN 학과;
```

```text
+----------+------+--------+--------+
| 학과코드 | 학번 | 이름   | 학과명 |
+----------+------+--------+--------+
| C01      | 1    | 김철수 | 컴퓨터 |
| C02      | 2    | 이영희 | 전자   |
+----------+------+--------+--------+
```

* 동등 조인(Equi Join)
  * 조인 조건에 `=` 연산자를 사용하는 조인
  * 내부 조인의 가장 일반적인 형태

```sql
SELECT 학생.이름, 학과.학과명
FROM 학생, 학과
WHERE 학생.학과코드 = 학과.학과코드;
```

```text
+--------+--------+
| 이름   | 학과명 |
+--------+--------+
| 김철수 | 컴퓨터 |
| 이영희 | 전자   |
+--------+--------+
```

* 비동등 조인(Non-Equi Join)
  * 조인 조건에 `=`, 이외의 비교 연산자(`<`, `>`, `BETWEEN` 등)를 사용하는 조인
  * 범위 비교가 필요한 경우 사용

```sql
SELECT 학생.이름, 성적등급.등급
FROM 학생
INNER JOIN 성적등급
ON 학생.점수 BETWEEN 성적등급.최소점수 AND 성적등급.최대점수;
```

```text
점수 포함 학생
+--------+------+
| 이름   | 점수 |
+--------+------+
| 김철수 | 95   |
| 이영희 | 82   |
| 박민수 | 71   |
+--------+------+

성적등급
+------+----------+----------+
| 등급 | 최소점수 | 최대점수 |
+------+----------+----------+
| A    | 90       | 100      |
| B    | 80       | 89       |
| C    | 70       | 79       |
+------+----------+----------+

결과
+--------+------+
| 이름   | 등급 |
+--------+------+
| 김철수 | A    |
| 이영희 | B    |
| 박민수 | C    |
+--------+------+
```

### DCL (Data Control Language)

* 사용자 접근 권한 부여·회수

| 명령어 | 설명 |
|--------|------|
| `GRANT` | 권한 부여 |
| `REVOKE` | 권한 회수 |

```sql
-- 권한 부여
GRANT SELECT, INSERT ON 학생 TO user1;

-- 모든 권한 부여
GRANT ALL PRIVILEGES ON 학생 TO user1;

-- 권한 위임 허용 (다른 사용자에게 재부여 가능)
GRANT SELECT ON 학생 TO user1 WITH GRANT OPTION;

-- 권한 회수
REVOKE INSERT ON 학생 FROM user1;
```
