## OSI 7계층

### OSI 7계층 구조

* ISO가 제정한 네트워크 통신 표준 모델. 통신 기능을 7개 계층으로 분리

* 7 응용(Application): 사용자와 직접 상호작용. 네트워크 서비스 제공 / HTTP, FTP, SMTP, DNS
* 6 표현(Presentation): 데이터 형식 변환, 암호화, 압축 / SSL/TLS, JPEG, MPEG
* 5 세션(Session): 통신 세션 수립·유지·종료 / NetBIOS, RPC
* 4 전송(Transport): 종단간 신뢰성 있는 데이터 전송, 흐름·오류 제어 / TCP, UDP — PDU: 세그먼트(TCP) / 데이터그램(UDP)
* 3 네트워크(Network): 논리 주소(IP) 기반 경로 설정 / IP, ICMP, 라우터 — PDU: 패킷
* 2 데이터 링크(Data Link): MAC 주소 기반 프레임 전송, 오류 감지 / Ethernet, 스위치, 브리지 — PDU: 프레임
* 1 물리(Physical): 비트 신호 전기·광·무선으로 전송 / 케이블, 허브, 리피터 — PDU: 비트

### Application 계층 주요 프로토콜

> 포트 0~1023: Well-Known Port. IANA(Internet Assigned Numbers Authority)에서 공식 할당한 주요 포트

* 20 — FTP(File Transfer Protocol) Data: 파일 전송 데이터 채널
* 21 — FTP(File Transfer Protocol) Control: 파일 전송 제어 채널
* 22 — SSH(Secure Shell): 암호화 원격 접속
* 23 — Telnet(Teletype Network): 평문 원격 접속
* 25 — SMTP(Simple Mail Transfer Protocol): 이메일 송신
* 53 — DNS(Domain Name System): 도메인 이름을 IP 주소로 변환
* 67/68 — DHCP(Dynamic Host Configuration Protocol): IP 주소 자동 할당. 67은 서버, 68은 클라이언트
* 80 — HTTP(HyperText Transfer Protocol): 웹 통신
* 110 — POP3(Post Office Protocol version 3): 이메일 수신. 서버에서 내려받은 뒤 삭제하는 방식
* 143 — IMAP(Internet Message Access Protocol): 이메일 수신. 서버에 메일을 보관하고 동기화하는 방식
* 161/162 — SNMP(Simple Network Management Protocol): 네트워크 장비 모니터링·관리. 161은 요청, 162는 트랩
* 443 — HTTPS(HyperText Transfer Protocol Secure): HTTP에 TLS(Transport Layer Security)를 적용한 암호화 웹 통신
* 1883 — MQTT(Message Queuing Telemetry Transport): IoT 환경에서 사용하는 경량 메시지 브로커 프로토콜
* 3306 — MySQL: MySQL 데이터베이스 접속

### Transport 계층 주요 프로토콜

* TCP(Transmission Control Protocol)
  * 연결 지향 전송 프로토콜

  * 신뢰성 보장

  * 3-way handshake로 연결 수립, 4-way handshake로 연결 해제

  * 흐름 제어·혼잡 제어·오류 제어 지원

  * 순서 보장, 재전송 가능

* UDP(User Datagram Protocol)
  * 비연결 지향 전송 프로토콜

  * 신뢰성 미보장

  * 오버헤드 최소화, 빠른 전송

  * DNS(Domain Name System), DHCP(Dynamic Host Configuration Protocol), 스트리밍, VoIP(Voice over Internet Protocol)에 사용

* RTCP(Real-Time Control Protocol)
  * RTP(Real-time Transport Protocol)의 제어 프로토콜

  * 미디어 스트림 품질 모니터링·통계 제공

  * QoS(Quality of Service) 피드백 전송

### Network 계층 주요 프로토콜

* IP(Internet Protocol)
  * 비연결, 비신뢰성 패킷 전달

  * 논리 주소(IP) 기반 경로 지정

* ICMP(Internet Control Message Protocol)
  * IP 오류 보고·네트워크 진단 메시지 전송

  * ping, traceroute에 사용

* IGMP(Internet Group Management Protocol)
  * 멀티캐스트 그룹 관리

  * 호스트가 멀티캐스트 그룹 가입·탈퇴 라우터에 알림

* ARP(Address Resolution Protocol)
  * IP(Internet Protocol) 주소 → MAC(Media Access Control) 주소 변환

  * 브로드캐스트로 MAC 주소 질의

* RARP(Reverse Address Resolution Protocol)
  * MAC(Media Access Control) 주소 → IP(Internet Protocol) 주소 변환

  * 디스크 없는 장치가 자신의 IP 주소 획득에 사용 (현재 DHCP로 대체)

### Data Link 계층 주요 프로토콜

* Ethernet
  * 유선 LAN 표준. CSMA/CD 방식

  * MAC 주소 기반 프레임 전송

* HDLC(High-level Data Link Control)
  * ISO(International Organization for Standardization) 표준 비트 지향 데이터 링크 프로토콜

  * 점대점·멀티포인트 링크 지원

  * 프레임 구조는 플래그, 주소, 제어, 데이터, FCS(Frame Check Sequence)로 구성

* IEEE(Institute of Electrical and Electronics Engineers) 802
  * LAN(Local Area Network), MAN(Metropolitan Area Network) 표준 시리즈
  * 802.3: Ethernet
  * 802.11: Wi-Fi 무선 LAN 표준
  * 802.15: Bluetooth 개인 영역 네트워크 표준
  * 802.16: WiMAX(Worldwide Interoperability for Microwave Access) 광대역 무선 접속 표준

* **RS-232C**
  * 직렬 통신 표준 (EIA 규격)
  * 컴퓨터·모뎀·단말기 간 점대점 연결
  * 물리 계층에 해당하나 데이터 링크 기능 포함

* **X.25**
  * 패킷 교환 WAN 프로토콜
  * 물리·데이터 링크·패킷 계층 3계층 정의
  * 오류 제어·흐름 제어 내장. 현재 Frame Relay·ATM으로 대체

## TCP/IP

* 인터넷 표준 프로토콜 스택. OSI 7계층을 실용적으로 4계층으로 단순화

### TCP/IP 계층 구조

* 응용(Application) — OSI 5·6·7계층 대응. 
* 전송(Transport) — OSI 4계층 대응. 
* 인터넷(Internet) — OSI 3계층 대응. 
* 네트워크 접근(Network Access) — OSI 1·2계층 대응.

### TCP vs UDP

**TCP**
* 연결 지향 (3-way handshake로 연결 수립)
* 신뢰성 보장: 순서·오류·재전송 제어
* 흐름 제어·혼잡 제어 있음
* 속도 느림
* 용도: 웹, 이메일, 파일 전송

**UDP**
* 비연결. 연결 수립 없이 즉시 전송
* 신뢰성 미보장. 순서·재전송 없음
* 흐름·혼잡 제어 없음
* 속도 빠름
* 용도: 스트리밍, DNS, VoIP

## TCP Handshake

### TCP 3-way Handshake (연결 수립)

```
클라이언트 →  SYN         → 서버
클라이언트 ←  SYN + ACK   ← 서버
클라이언트 →  ACK         → 서버
```

### TCP 4-way Handshake (연결 종료)

```
클라이언트 →  FIN         → 서버
클라이언트 ←  ACK         ← 서버
클라이언트 ←  FIN         ← 서버
클라이언트 →  ACK         → 서버
```

## 네트워크 접근 제어

### 매체 접근 제어 방식

* 매체 접근 제어
  * 여러 장치가 같은 전송 매체를 공유할 때 데이터 전송 권한을 제어하는 방식
  * 충돌을 방지하거나 충돌 발생 시 복구해 통신 효율을 높임

* CSMA/CD(Carrier Sense Multiple Access with Collision Detection)
  * 반송파 감지 다중 접근/충돌 검출 방식
  * 데이터를 전송하기 전에 전송 매체가 사용 중인지 확인
  * 매체가 비어 있으면 데이터를 전송
  * 전송 중 충돌이 발생하면 충돌을 감지하고 전송 중단
  * 충돌 후 임의 시간 대기한 뒤 재전송
  * 유선 Ethernet에서 사용

* CSMA/CA(Carrier Sense Multiple Access with Collision Avoidance)
  * 반송파 감지 다중 접근/충돌 회피 방식
  * 충돌을 검출하기보다 사전에 회피하는 방식
  * 무선 LAN에서 주로 사용

* Token Passing
  * 토큰을 가진 장치만 데이터를 전송할 수 있는 방식
  * 충돌이 발생하지 않지만 토큰 관리 오버헤드 존재

### 루프 방지

* STA(Spanning Tree Algorithm)
  * 브리지나 스위치로 구성된 LAN에서 루프를 방지하는 알고리즘
  * 중복 경로 중 일부를 차단해 전체 연결을 트리 구조로 유지
  * 프레임이 네트워크 안에서 무한 순환하는 현상 방지
  * 장애 발생 시 기존에 차단된 경로를 활성화해 통신 경로 재구성 가능

## IP 주소

### IPv4

* 32비트 주소 체계. 8비트씩 4개 옥텟, 점(`.`)으로 구분
* 표현: `192.168.0.1`
* 주소 공간: 약 43억 개 (2³²)

* 서브넷 마스크
  * 네트워크 부분과 호스트 부분 구분
  * `192.168.1.0/24` → 앞 24비트 네트워크, 뒤 8비트 호스트
  * `/24`에서 사용 가능한 호스트 수는 254개


### IPv4 클래스

* 클래스 분류
  * IPv4 주소를 첫 번째 옥텟 값과 선행 비트에 따라 A~E Class로 나눈 방식
  * 현재는 CIDR(Classless Inter-Domain Routing)을 주로 사용하지만, 기본 주소 체계 이해에 필요

* A Class
  * 선행 비트: 0
  * 주소 범위: `0.0.0.0 ~ 127.255.255.255`
  * 기본 서브넷 마스크: `255.0.0.0` 또는 `/8`
  * 네트워크 수는 적고 호스트 수가 많음
  * 대형 네트워크에 사용
  * `0.x.x.x`는 특수 용도, `127.x.x.x`는 루프백 주소로 사용

* B Class
  * 선행 비트: 10
  * 주소 범위: `128.0.0.0 ~ 191.255.255.255`
  * 기본 서브넷 마스크: `255.255.0.0` 또는 `/16`
  * 중형 네트워크에 사용

* C Class
  * 선행 비트: 110
  * 주소 범위: `192.0.0.0 ~ 223.255.255.255`
  * 기본 서브넷 마스크: `255.255.255.0` 또는 `/24`
  * 네트워크 수는 많고 호스트 수가 적음
  * 소형 네트워크에 사용

* D Class
  * 선행 비트: 1110
  * 주소 범위: `224.0.0.0 ~ 239.255.255.255`
  * 멀티캐스트용 주소
  * 일반 호스트 주소로 사용하지 않음

* E Class
  * 선행 비트: 1111
  * 주소 범위: `240.0.0.0 ~ 255.255.255.255`
  * 예약 주소
  * 실험용으로 분류되며 일반 호스트 주소로 사용하지 않음

### IPv6

* 128비트 주소 체계. 16비트씩 8개 그룹, 콜론(`:`)으로 구분
* 표현: `2001:0DB8:85A3:0000:0000:8A2E:0370:7334`
* 주소 공간: 약 3.4 × 10³⁸ 개 (2¹²⁸)

**특징**

* **주소 자동 설정**: DHCP 없이 SLAAC로 자동 구성 가능
* **헤더 단순화**: 고정 40바이트 헤더. 단편화 헤더 분리
* **보안 내장**: IPSec 기본 지원
* **멀티캐스트**: 브로드캐스트 없음, 멀티캐스트·애니캐스트로 대체
* **QoS**: Flow Label 필드로 트래픽 우선순위 지원

**주소 축약 규칙**

* 연속 0 그룹 → `::` (1회만 사용 가능)
* 각 그룹 앞 0 생략 가능
* `2001:0DB8:0000:0000:0000:0000:0000:0001` → `2001:DB8::1`

---

### IPv4 vs IPv6 비교

* **주소 길이**: IPv4 32비트 / IPv6 128비트
* **표기법**: IPv4 10진수 `.` 구분 / IPv6 16진수 `:` 구분
* **주소 수**: IPv4 약 43억 / IPv6 약 3.4 × 10³⁸
* **헤더 크기**: IPv4 가변(20~60 byte) / IPv6 고정(40 byte)
* **브로드캐스트**: IPv4 지원 / IPv6 없음 (멀티캐스트·애니캐스트 대체)
* **보안**: IPv4 IPSec 선택 / IPv6 IPSec 기본 내장
* **주소 설정**: IPv4 수동·DHCP / IPv6 자동(SLAAC)·DHCPv6
* **단편화**: IPv4 라우터·송신측 모두 / IPv6 송신측만

## 네트워크 장비

| 장비 | OSI 계층 | 특징 |
|------|----------|------|
| 리피터 | 1계층(물리) | 신호 증폭·재생 |
| 허브 | 1계층(물리) | 신호 분배, 모든 포트에 브로드캐스트 |
| 브리지 | 2계층(데이터 링크) | MAC 주소 기반 프레임 필터링 |
| 스위치 | 2계층(데이터 링크) | 포트별 MAC 테이블, 전용 대역폭 |
| 라우터 | 3계층(네트워크) | IP 주소 기반 최적 경로 선택 |

### 리피터(Repeater)

* 물리 계층에서 신호 감쇠 복원·증폭

* 데이터 내용 해석 불가, 단순 신호 재생

* 네트워크 거리 연장 목적

### 허브(Hub)

* 여러 장치를 연결하는 집선 장치

* 수신 신호를 연결된 모든 포트에 전송(브로드캐스트)

* 충돌 도메인 공유 → 트래픽 증가 시 성능 저하

* 스위치로 대체되어 현재 거의 미사용

### 브리지(Bridge)

* MAC 주소 학습하여 목적지 포트로만 프레임 전달

* 충돌 도메인 분리 가능

* LAN과 LAN 연결

### 스위치(Switch)

* 브리지 기능 + 각 포트에 전용 대역폭 제공

* MAC 주소 테이블로 유니캐스트 전송

* 충돌 도메인 포트별 분리

* L2 스위치(MAC), L3 스위치(IP 라우팅 기능 포함)

### 라우터(Router)

* IP 주소 기반 최적 경로 계산·선택

* 브로드캐스트 도메인 분리

* 서로 다른 네트워크(LAN-WAN) 연결

* 라우팅 프로토콜: RIP, OSPF, BGP

### 게이트웨이

* 서로 다른 프로토콜·네트워크 간 변환·연결
* OSI 전 계층(1~7) 관여 가능
* 예: 사내망 ↔ 인터넷, VoIP 게이트웨이


### FEP; Front End Processor

* 호스트(메인프레임) 앞단에서 통신 처리 담당하는 전처리 장치
* 호스트 부담 경감: 폴링, 오류 제어, 코드 변환, 속도 변환 수행
* 여러 단말기 접속을 하나의 호스트로 집중

## 경로 제어

### 라우팅 프로토콜

| 구분 | 설명 | 프로토콜 |
|------|------|----------|
| IGP(Interior Gateway Protocol) | 동일 AS 내부 라우팅 | RIP, OSPF, EIGRP |
| EGP(Exterior Gateway Protocol) | AS 간 라우팅. 구형 프로토콜, 현재 사용 안 함 | EGP |
| BGP(Border Gateway Protocol) | EGP 대체. 현재 인터넷 AS 간 표준 | BGP |

> **AS(Autonomous System)**: 단일 관리 체계 하의 네트워크 집합

---

### IGP (내부 게이트웨이 프로토콜)

#### RIP (Routing Information Protocol)

* **거리 벡터(Distance Vector)** 알고리즘 기반 — 벨만-포드(Bellman-Ford) 알고리즘 사용

* 홉 수(Hop Count)를 메트릭으로 사용, 최대 15홉 (16 = 무한대)

* 30초마다 인접 라우터에 전체 라우팅 테이블 브로드캐스트

#### OSPF (Open Shortest Path First)

* **링크 상태(Link State)** 알고리즘 기반

* 다익스트라(Dijkstra) 알고리즘으로 최단 경로 계산

* 변경 발생 시에만 LSA(Link State Advertisement) 전송 → 트래픽 효율적

* 계층적 구조: **백본 영역(Area 0)** 중심으로 여러 Area 구성

---

### EGP (외부 게이트웨이 프로토콜)

* AS 간 라우팅을 위한 초기 프로토콜 (RFC 904, 1984)

* 단순 도달 가능성 정보만 교환, 경로 선택 기능 없음

* 현재 **사용되지 않음** — BGP로 대체

---

### BGP (Border Gateway Protocol)

* **경로 벡터(Path Vector)** 알고리즘 기반

* 인터넷 AS 간 라우팅 담당 (인터넷 핵심 프로토콜)

* TCP 179번 포트 사용, 신뢰성 보장

* 정책 기반 라우팅 가능

---

## 트래픽 제어

> 네트워크 내 데이터 흐름을 조절하여 혼잡·오류 방지

### 흐름 제어

* 송신 측과 수신 측 간 데이터 전송 속도 조절

* 수신 측 버퍼 오버플로 방지 목적

* 정지-대기(Stop and Wait)
  * 프레임 전송 후 ACK(Acknowledgement) 수신까지 대기

  * 구현이 단순하지만 전송 효율 낮음

* 슬라이딩 윈도우(Sliding Window)
  * 윈도우 크기만큼 연속 전송

  * ACK(Acknowledgement) 수신 시 윈도우 이동

  * 정지-대기보다 전송 효율 높음

### 혼잡 제어

* 네트워크 전체의 패킷 수 조절 → 라우터 큐 오버플로 방지

* 느린 시작(Slow Start)
  * 전송량을 1에서 시작해 지수적으로 증가

* 혼잡 회피(Congestion Avoidance)
  * 임계값(Threshold) 도달 후 선형 증가

* 빠른 재전송(Fast Retransmit)
  * 3번 중복 ACK(Acknowledgement) 수신 시 타임아웃을 기다리지 않고 즉시 재전송

* 빠른 회복(Fast Recovery)
  * 빠른 재전송 후 Slow Start를 생략하고 혼잡 회피로 전환

### 오류 제어

* 데이터 전송 중 발생한 오류를 감지·복구하는 기법

* ARQ(Automatic Repeat reQuest)
  * 오류 감지 시 송신 측에 재전송 요청하는 오류 제어 방식

* Stop-and-Wait ARQ(Automatic Repeat reQuest)
  * 프레임 하나 전송 후 ACK(Acknowledgement) 수신까지 대기

  * 오류 발생 시 해당 프레임 재전송

  * 구현 단순. 효율 낮음

* Go-Back-N ARQ(Automatic Repeat reQuest)
  * 슬라이딩 윈도우 기반. 오류 발생 프레임부터 이후 모든 프레임 재전송

  * 오류 없으면 연속 전송 가능. 오류 시 불필요한 재전송 발생

* Selective Repeat ARQ(Automatic Repeat reQuest)
  * 오류 발생한 프레임만 선택적 재전송

  * 효율 가장 높음. 수신 측에 별도 버퍼 필요

  * Go-Back-N보다 구현 복잡

* Adaptive ARQ(Automatic Repeat reQuest)
  * 전송 효율 최대화를 위해 네트워크 상태에 따라 프레임 크기 동적 조절

  * 오류 많으면 프레임 크기 줄이고, 오류 적으면 늘림
