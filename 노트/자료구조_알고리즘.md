## 정렬 알고리즘

### 정렬 개요

**시간 복잡도 비교**

| 알고리즘 | 최선 | 평균 | 최악 | 공간 | 안정성 |
|----------|------|------|------|------|--------|
| 버블 정렬 | O(n) | O(n²) | O(n²) | O(1) | 안정 |
| 선택 정렬 | O(n²) | O(n²) | O(n²) | O(1) | 불안정 |
| 삽입 정렬 | O(n) | O(n²) | O(n²) | O(1) | 안정 |
| 셸 정렬 | O(n log n) | O(n^1.5) | O(n²) | O(1) | 불안정 |
| 합병 정렬 | O(n log n) | O(n log n) | O(n log n) | O(n) | 안정 |
| 퀵 정렬 | O(n log n) | O(n log n) | O(n²) | O(log n) | 불안정 |
| 힙 정렬 | O(n log n) | O(n log n) | O(n log n) | O(1) | 불안정 |
| 기수 정렬 | O(kn) | O(kn) | O(kn) | O(n+k) | 안정 |
| 계수 정렬 | O(n+k) | O(n+k) | O(n+k) | O(k) | 안정 |

> **안정 정렬**: 동일 키 값의 원소 순서가 정렬 후에도 유지됨

### 비교 기반 정렬

#### 버블 정렬 (Bubble Sort)

* 인접한 두 원소 비교 후 교환, 반복

* 매 패스마다 가장 큰 값이 맨 뒤로 이동

* 이미 정렬된 경우 O(n) (조기 종료 조건 있을 때)

* 구현 단순, 실용성 낮음

#### 선택 정렬 (Selection Sort)

* 미정렬 구간에서 최솟값 선택 → 맨 앞과 교환

* 교환 횟수 최소 (n-1번), 비교 횟수는 항상 O(n²)

* 데이터 이동 비용이 큰 경우 유리

#### 삽입 정렬 (Insertion Sort)

* 정렬된 부분에 현재 원소를 올바른 위치에 삽입

* 거의 정렬된 데이터에 매우 효율적

* 온라인 알고리즘 — 데이터가 들어오는 순서대로 처리 가능

#### 셸 정렬 (Shell Sort)

* 삽입 정렬 개선판

* 일정 간격(Gap)으로 부분 리스트 구성 후 삽입 정렬 적용

* Gap을 줄여가며 반복, 마지막 Gap=1이면 일반 삽입 정렬

* 삽입 정렬보다 빠르지만 Gap 설정에 따라 성능 차이

#### 합병 정렬 (Merge Sort)

* **분할 정복(Divide and Conquer)** 기법

* 리스트를 절반씩 분할 → 각각 정렬 → 합병

* 최악도 O(n log n) 보장, 안정 정렬

* 단점: 추가 메모리 O(n) 필요 (외부 정렬에 적합)

#### 퀵 정렬 (Quick Sort)

* **분할 정복** 기법

* 피벗(Pivot) 선택 → 피벗 기준 좌·우 분할 → 재귀 정렬

* 평균 O(n log n), 실제 가장 빠른 정렬

* 최악: 이미 정렬된 데이터에서 피벗이 항상 최솟값/최댓값일 때 O(n²)

* 피벗 선택 방법: 첫 원소, 중간 원소, 랜덤, 중앙값(Median of 3)

#### 힙 정렬 (Heap Sort)

* 최대 힙(Max Heap) 구성 → 루트(최댓값) 추출 → 힙 재구성 반복

* 최악도 O(n log n) 보장, 추가 메모리 불필요

* 불안정 정렬, 캐시 효율 낮아 실제로는 퀵 정렬보다 느림

* **힙(Heap)**: 완전 이진 트리, 부모 노드 ≥ 자식 노드 (최대 힙)

### 분산 정렬

> 비교 없이 정렬 — 비교 기반 정렬의 하한 O(n log n) 돌파 가능

#### 기수 정렬 (Radix Sort)

* 자릿수(Digit) 기준으로 분류, 낮은 자릿수부터 정렬

* LSD(Least Significant Digit): 낮은 자릿수 → 높은 자릿수

* MSD(Most Significant Digit): 높은 자릿수 → 낮은 자릿수

* 정수·문자열 정렬에 적합, 음수 처리 복잡

* k = 최대 자릿수, 시간 복잡도 O(kn)

#### 계수 정렬 (Counting Sort)

* 각 원소의 등장 횟수를 배열에 저장 후 누적합으로 위치 결정

* 데이터 범위(k)가 작을 때 O(n+k)로 매우 빠름

* 범위가 크면 메모리 낭비 심각

* 정수 또는 정수로 변환 가능한 데이터에만 적용
