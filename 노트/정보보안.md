## 네트워크 보안

### 세션 하이재킹(Session Hijacking)

* 공격 과정
    1. 공격자가 클라이언트-서버 간 통신 스니핑
    2. 세션 ID 또는 TCP 시퀀스 번호 탈취
    3. 정상 클라이언트 연결 끊기(RST 패킷 전송)
    4. 탈취한 세션으로 서버에 접속

* 대응 방법
    * HTTPS(TLS) 사용으로 세션 암호화
    * 세션 ID 재발급(로그인 후 세션 ID 변경)
    * 세션 타임아웃 설정
    * IP·User-Agent 검증 추가

## 웹 보안

### SQL 인젝션

* 사용자 입력값을 검증 없이 SQL 쿼리에 직접 삽입할 때 발생하는 공격
* 입력란에 SQL 코드를 넣으면 DB가 그것을 명령으로 실행함

* **공격 원리**

    서버가 아이디·비밀번호를 이렇게 조합한다고 가정:
    ```sql
    SELECT * FROM users WHERE id='[입력]' AND pw='[입력]'
    ```

* **공격 유형 1: 로그인 우회**

    아이디 입력란에 `' OR '1'='1` 입력 시:
    ```sql
    SELECT * FROM users WHERE id='' OR '1'='1' AND pw='...'
    ```
    * `'1'='1'`은 항상 참 → WHERE 조건 전체가 참
    * 비밀번호 몰라도 로그인 성공

* **공격 유형 2: 데이터 추출 (UNION 공격)**

    ```sql
    ' UNION SELECT id, pw FROM users --
    ```
    * `UNION`: 두 SELECT 결과를 합쳐 반환
    * 원래 쿼리 결과에 `users` 테이블 전체를 붙여서 화면에 출력
    * `--`: 뒤따라오는 SQL을 전부 주석 처리 → 나머지 조건 무력화
    * 결과: DB의 아이디·비밀번호 전부 노출

* **피해**: 인증 우회, 데이터 유출·변조·삭제, DB 서버 장악

* **대응 방법**

    | 방법 | 이유 |
    |------|------|
    | 준비된 구문(Prepared Statement) / 파라미터 바인딩 | 입력값을 "데이터"로만 처리, SQL 명령으로 해석 안 함 |
    | 특수문자 이스케이프 | `'` → `\'` 변환, SQL 구조 깨는 문자 무력화 |
    | 입력값 유효성 검사 | 허용된 형식(숫자·영문 등)만 통과 |
    | 최소 권한 DB 계정 사용 | 해킹당해도 SELECT만 가능 → DELETE·DROP 불가 |
    | ORM 사용 | 프레임워크가 안전한 쿼리 자동 생성 |

## 침입 탐지 시스템

### IDS(Intrusion Detection System)

* 네트워크·시스템의 비정상적 행위 탐지 후 **관리자에게 알림**

* 탐지만 수행, 차단 불가

* 유형
    * 오용 탐지(Misuse Detection): 알려진 공격 패턴(시그니처)과 비교. 알려진 공격에 정확, 신종 공격 탐지 불가
    * 이상 탐지(Anomaly Detection): 정상 행위 프로파일 기준 편차 탐지. 신종 공격 탐지 가능, 오탐률 높음

* 설치 위치
    * NIDS(Network-based): 네트워크 트래픽 모니터링
    * HIDS(Host-based): 개별 호스트 로그·시스템 콜 모니터링

### IPS(Intrusion Prevention System)

* IDS + 차단 기능. 탐지 즉시 **자동 차단** 수행

* 인라인(Inline) 방식으로 트래픽 경로에 직접 삽입

* 오탐 시 정상 트래픽 차단 위험 존재

| 구분 | IDS | IPS |
|------|-----|-----|
| 역할 | 탐지·알림 | 탐지·차단 |
| 위치 | 네트워크 탭/스팬 | 인라인 |
| 오탐 영향 | 알림만 발생 | 정상 트래픽 차단 가능 |
