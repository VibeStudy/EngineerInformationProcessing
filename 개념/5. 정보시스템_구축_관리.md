## 네트워크 및 보안

## IP 주소 체계

---

### IPv4

- **32비트** 주소 체계. 점(.)으로 구분된 4개의 옥텟(Octet)
- 표기: `192.168.0.1` (각 옥텟 0~255)
- 총 주소 수: 2³² ≈ 약 43억 개

#### 클래스 분류 (시험 빈출)

| 클래스 | 첫 비트 | 범위 (첫 옥텟) | 기본 서브넷 마스크 | 용도 |
|--------|---------|--------------|-----------------|------|
| **A** | 0 | 0 ~ 127 | 255.0.0.0 (/8) | 대형 네트워크 |
| **B** | 10 | 128 ~ 191 | 255.255.0.0 (/16) | 중형 네트워크 |
| **C** | 110 | 192 ~ 223 | 255.255.255.0 (/24) | 소형 네트워크 |
| **D** | 1110 | 224 ~ 239 | — | 멀티캐스트 |
| **E** | 1111 | 240 ~ 255 | — | 실험용 (예약) |

#### 사설 IP (Private IP)

인터넷에서 라우팅되지 않는 내부 전용 주소. NAT로 공인 IP 변환 후 인터넷 접속.

| 클래스 | 사설 IP 범위 |
|--------|------------|
| A | 10.0.0.0 ~ 10.255.255.255 |
| B | 172.16.0.0 ~ 172.31.255.255 |
| C | 192.168.0.0 ~ 192.168.255.255 |

---

### IPv6

- **128비트** 주소 체계. 콜론(:)으로 구분된 8개의 16진수 그룹
- 표기: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`
- 총 주소 수: 2¹²⁸ (사실상 무한)
- IPv4 고갈 문제 해결 위해 개발

#### 표기 단축 규칙

1. 각 그룹의 앞자리 0 생략: `0db8` → `db8`
2. 연속된 0 그룹은 `::` 로 한 번만 생략: `0000:0000:0000` → `::`

```
2001:0db8:0000:0000:0000:0000:0000:0001
→ 2001:db8::1
```

#### 주요 특징

| 특징 | 내용 |
|------|------|
| **자동 주소 설정** | SLAAC로 수동 설정 불필요 |
| **보안** | IPSec 기본 내장 |
| **헤더 단순화** | 고정 40바이트, 라우팅 효율 향상 |
| **멀티캐스트 강화** | 브로드캐스트 없음, 멀티캐스트·애니캐스트 사용 |

---

### IPv4 vs IPv6 비교

| 구분 | IPv4 | IPv6 |
|------|------|------|
| **주소 길이** | 32비트 | 128비트 |
| **표기** | 10진수, 점(.) 구분 | 16진수, 콜론(:) 구분 |
| **주소 수** | 약 43억 | 사실상 무한 |
| **헤더 크기** | 가변 (20~60바이트) | 고정 (40바이트) |
| **보안** | 별도 설정 필요 | IPSec 기본 내장 |
| **브로드캐스트** | 있음 | 없음 (멀티캐스트 대체) |
| **NAT** | 필요 | 불필요 |
| **자동 설정** | DHCP 필요 | SLAAC 가능 |

### 서브넷 마스크 & CIDR

**서브넷 마스크**: 네트워크 부분과 호스트 부분을 구분하는 32비트 값

```
IP:   192.168.1.0
마스크: 255.255.255.0
      = 11111111.11111111.11111111.00000000
         ↑ 네트워크 부분 (24비트)  ↑ 호스트 부분 (8비트)
```

**CIDR (Classless Inter-Domain Routing)**: `/비트수` 로 서브넷 마스크 표현

| CIDR | 서브넷 마스크 | 호스트 수 |
|------|-------------|---------|
| /8 | 255.0.0.0 | 2²⁴ - 2 = 약 1677만 |
| /16 | 255.255.0.0 | 2¹⁶ - 2 = 65,534 |
| /24 | 255.255.255.0 | 2⁸ - 2 = 254 |
| /25 | 255.255.255.128 | 2⁷ - 2 = 126 |

> 호스트 수 = 2^(호스트 비트 수) - 2  
> (-2 이유: 네트워크 주소·브로드캐스트 주소 제외)

---

### 특수 IP 주소

| 주소 | 용도 |
|------|------|
| **127.0.0.1** | 루프백(Loopback). 자기 자신. `localhost` |
| **0.0.0.0** | 모든 인터페이스 / 기본 경로 |
| **255.255.255.255** | 제한된 브로드캐스트 (로컬 네트워크 전체) |
| **네트워크 주소** | 호스트 부분 전부 0 (예: 192.168.1.0/24) |
| **브로드캐스트 주소** | 호스트 부분 전부 1 (예: 192.168.1.255/24) |

---

### NAT (Network Address Translation)

**개념**: 사설 IP ↔ 공인 IP 변환. 내부 네트워크가 하나의 공인 IP로 인터넷 접속 가능.

```
[사설 IP: 192.168.0.10]
        ↓
[NAT 라우터] → 공인 IP: 203.0.113.1 → 인터넷
        ↓
[사설 IP: 192.168.0.20]
```

| 종류 | 설명 |
|------|------|
| **정적 NAT** | 사설 IP 1개 ↔ 공인 IP 1개 고정 매핑 |
| **동적 NAT** | 사설 IP → 공인 IP 풀에서 동적 할당 |
| **PAT (포트 NAT / NAPT)** | 여러 사설 IP → 공인 IP 1개 + 포트 번호로 구분. 가장 일반적 |

> **핵심 암기**
> - IPv4 = 32비트, 클래스 A(0~127)·B(128~191)·C(192~223)
> - IPv6 = 128비트, IPSec 내장, 브로드캐스트 없음
> - 사설 IP: 10.x.x.x / 172.16~31.x.x / 192.168.x.x
> - CIDR /24 = 255.255.255.0 = 호스트 254개
> - 루프백 = 127.0.0.1
> - NAT = 사설↔공인 IP 변환, PAT = 포트까지 구분

## 주요 프로토콜

---

### 보안 프로토콜

> IPSec / SSL·TLS / S-HTTP / HTTPS

**IPSec (IP Security)**
- 계층: 네트워크 (Layer 3) / 목적: IP 패킷 암호화·인증, VPN 구현
- AH(인증만) · ESP(암호화+인증) · IKE(키 교환)
- 전송 모드: 페이로드만 암호화 / 터널 모드: 패킷 전체 암호화 (VPN)

**SSL / TLS (Secure Sockets Layer / Transport Layer Security)**
- 계층: 전송~응용 사이 (Layer 4~7) / 목적: 채널 전체 암호화
- SSL 3.0 → TLS 1.0 → TLS 1.3 으로 발전
- 기밀성(대칭키) · 무결성(MAC) · 인증(X.509 인증서)
- HTTPS = HTTP + TLS / 포트 443

**S-HTTP (Secure HyperText Transfer Protocol)**
- 계층: 응용 (Layer 7) / 목적: HTTP 메시지 단위 개별 암호화·서명
- SSL = 채널 전체 암호화 / S-HTTP = 메시지 개별 암호화 (현재 거의 미사용)

| 구분 | SSL/TLS | S-HTTP |
|------|---------|--------|
| 암호화 단위 | 연결(세션) 전체 | 메시지 개별 |
| 계층 | 전송~응용 | 응용 |
| 사용 현황 | 광범위 (HTTPS) | 거의 미사용 |

---

### 메일 프로토콜

> SMTP / POP3 / IMAP

**SMTP (Simple Mail Transfer Protocol)** — 송신
- 포트: 25 (일반) · 587 (STARTTLS) · 465 (SMTPS)
- 발신자 → 메일 서버, 서버 간 전달. 푸시 방식

**POP3 (Post Office Protocol 3)** — 수신 + 삭제
- 포트: 110 (일반) · 995 (POP3S)
- 서버에서 다운로드 후 삭제 (기본). 단일 기기에 적합

**IMAP (Internet Message Access Protocol)** — 수신 + 서버 유지
- 포트: 143 (일반) · 993 (IMAPS)
- 서버에 메일 유지 → 다중 기기 동기화 가능

| 구분 | SMTP | POP3 | IMAP |
|------|------|------|------|
| 방향 | 송신 | 수신 | 수신 |
| 포트 | 25/587 | 110 | 143 |
| 서버 저장 | - | 삭제 | 유지 |
| 다중 기기 | - | 불편 | 가능 |

---

### 기타 주요 프로토콜

| 프로토콜 | 계층 | 포트 | 역할 |
|----------|------|------|------|
| **FTP** | 응용 | 20(데이터)/21(제어) | 파일 전송 |
| **SSH** | 응용 | 22 | 암호화 원격 접속 |
| **Telnet** | 응용 | 23 | 원격 접속 (암호화 없음) |
| **DNS** | 응용 | 53 | 도메인 → IP 변환 |
| **HTTP** | 응용 | 80 | 웹 통신 |
| **HTTPS** | 응용 | 443 | 암호화 웹 통신 |
| **SNMP** | 응용 | 161 | 네트워크 장비 관리 |
| **DHCP** | 응용 | 67/68 | IP 자동 할당 |
| **ARP** | 네트워크 | - | IP → MAC 주소 변환 |
| **ICMP** | 네트워크 | - | 오류 보고 (ping) |

---

> **핵심 암기**
> - IPSec = 네트워크 계층, VPN, AH(인증)/ESP(암호화+인증)
> - SSL/TLS = 채널 암호화, HTTPS에 사용, 포트 443
> - S-HTTP = 메시지 단위 암호화, 현재 거의 미사용
> - SMTP = 송신(25), POP3 = 수신+삭제(110), IMAP = 수신+유지(143)
> - SSH = 암호화 원격(22), Telnet = 비암호화 원격(23)

## 저작권 관리

---

### DRM (Digital Rights Management, 디지털 저작권 관리)

> 개념 / 구성 요소 / 흐름

디지털 콘텐츠의 **무단 복제·배포 방지** 및 사용 권한 통제 기술.

**개념**
- 콘텐츠 암호화 + 라이선스 기반 접근 제어
- 콘텐츠 생성~소비 전 과정에서 저작권자 권리 보호

**구성 요소**

| 구성 요소 | 역할 |
|-----------|------|
| **콘텐츠 제공자 (Contents Provider)** | 저작권자. 원본 콘텐츠 제공 |
| **콘텐츠 분배자 (Contents Distributor)** | 암호화된 콘텐츠 유통·배포 |
| **패키저 (Packager)** | 콘텐츠 암호화 + 메타데이터 패키징 |
| **보안 컨테이너 (Security Container)** | 암호화된 콘텐츠 저장 단위 |
| **클리어링 하우스 (Clearing House)** | 라이선스 발급·관리. 키 분배 |
| **DRM 컨트롤러** | 사용자 단에서 콘텐츠 사용 권한 제어 |
| **소비자 (Consumer)** | 라이선스 취득 후 콘텐츠 이용 |

**콘텐츠 흐름**

```
콘텐츠 제공자
    ↓ (원본)
패키저 → 암호화·패키징 → 보안 컨테이너
    ↓
콘텐츠 분배자 → 배포
    ↓
소비자 → 클리어링 하우스에 라이선스 요청
    ↓
DRM 컨트롤러 → 라이선스 확인 후 콘텐츠 복호화·재생
```

### 저작권 관련 기술 요소

> 워터마킹 / 핑거프린팅 / 암호화

**워터마킹 (Watermarking)**
- 콘텐츠에 저작권 정보(소유자 정보)를 **눈에 보이지 않게 삽입**
- 목적: 저작권 소유 증명, 불법 복제 추적
- 콘텐츠 변형 후에도 워터마크 유지

**핑거프린팅 (Fingerprinting)**
- 콘텐츠에 **구매자 정보**를 삽입
- 목적: 불법 유포자 식별·추적
- 워터마킹과 차이: 워터마킹=저작권자 정보 / 핑거프린팅=구매자 정보

| 구분 | 워터마킹 | 핑거프린팅 |
|------|----------|------------|
| 삽입 정보 | 저작권자·소유자 | 구매자·사용자 |
| 목적 | 소유권 증명 | 유포자 추적 |
| 가시성 | 비가시적 | 비가시적 |

**암호화 (Encryption)**
- 콘텐츠 자체를 암호화 → 라이선스(키) 없이 재생 불가
- DRM 핵심 기술

### 오픈소스 라이선스

> GPL / LGPL / MIT / Apache / BSD

**라이선스 비교**

| 라이선스 | 소스 공개 의무 | 상업적 이용 | 특징 |
|----------|--------------|------------|------|
| **GPL** | 강제 (파생물 포함) | 가능 | 카피레프트 가장 강함 |
| **LGPL** | 라이브러리 수정분만 공개 | 가능 | GPL 완화판. 링크 허용 |
| **MIT** | 없음 | 가능 | 가장 자유로움. 저작권 표시만 |
| **Apache 2.0** | 없음 | 가능 | 특허권 명시적 허용 |
| **BSD** | 없음 | 가능 | MIT와 유사. 광고 조항 여부로 구분 |

**카피레프트(Copyleft)**: 오픈소스 사용 시 파생 저작물도 동일 라이선스 적용 강제
- 강한 카피레프트: GPL
- 약한 카피레프트: LGPL
- 카피레프트 없음: MIT, Apache, BSD

> **핵심 암기**
> - DRM = 디지털 저작권 관리. 암호화 + 라이선스 기반
> - 클리어링 하우스 = 라이선스 발급·키 분배 기관
> - 워터마킹 = 저작권자 정보 삽입 / 핑거프린팅 = 구매자 정보 삽입
> - GPL = 카피레프트 강함 / MIT·Apache = 가장 자유로움
> - 패키저 = 콘텐츠 암호화·패키징 담당
