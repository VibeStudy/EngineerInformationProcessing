## 네트워크

## OSI 7계층

**개념**: 네트워크 통신을 7단계로 표준화한 참조 모델 (ISO 제정). 계층별 독립 설계·교체 가능.

---

### 계층별 요약 (시험 빈출)

| 계층 | 이름 | 역할 | 프로토콜/장비 | PDU |
|------|------|------|-------------|-----|
| 7 | **응용 (Application)** | 사용자·앱 인터페이스 | HTTP, FTP, DNS, SMTP | 메시지 |
| 6 | **표현 (Presentation)** | 데이터 형식 변환·암호화·압축 | SSL/TLS, JPEG, ASCII | 메시지 |
| 5 | **세션 (Session)** | 통신 세션 수립·유지·종료 | NetBIOS, RPC | 메시지 |
| 4 | **전송 (Transport)** | 종단 간 신뢰성·흐름 제어 | TCP, UDP | 세그먼트 |
| 3 | **네트워크 (Network)** | 논리 주소(IP) 지정·라우팅 | IP, ICMP, ARP, 라우터 | 패킷 |
| 2 | **데이터링크 (Data Link)** | 물리 주소(MAC) 프레임화·오류 검출 | Ethernet, PPP, 스위치 | 프레임 |
| 1 | **물리 (Physical)** | 비트 → 전기/광 신호 변환 | 케이블, 허브, 리피터 | 비트 |

> 암기법: **아파세전네데물** (응용·표현·세션·전송·네트워크·데이터링크·물리)

---

### 각 계층 상세

**7계층 — 응용 (Application)**
- 사용자가 직접 사용하는 서비스 제공
- HTTP(80), HTTPS(443), FTP(20/21), DNS(53), SMTP(25), POP3(110), IMAP(143)

**6계층 — 표현 (Presentation)**
- 데이터 형식 변환: 인코딩/디코딩
- 암호화/복호화 (SSL/TLS)
- 압축/해제 (JPEG, MPEG, ZIP)

**5계층 — 세션 (Session)**
- 프로세스 간 논리적 연결(세션) 관리
- 동기화: 체크포인트로 재전송 범위 최소화
- 전이중(Full-Duplex) / 반이중(Half-Duplex) 결정

**4계층 — 전송 (Transport)**
- 포트 번호로 프로세스 식별
- **TCP**: 연결 지향, 신뢰성, 순서 보장, 흐름·혼잡 제어
- **UDP**: 비연결, 빠름, 신뢰성 없음 (스트리밍·DNS에 사용)

| 구분 | TCP | UDP |
|------|-----|-----|
| 연결 | 3-way handshake | 없음 |
| 신뢰성 | 보장 | 미보장 |
| 순서 보장 | O | X |
| 속도 | 느림 | 빠름 |
| 사용 | HTTP, FTP, SMTP | DNS, 스트리밍, VoIP |

**3계층 — 네트워크 (Network)**
- 논리 주소(IP)로 최적 경로 결정 (라우팅)
- 장비: **라우터**
- 프로토콜: IP, ICMP(오류보고), ARP(IP→MAC)

**2계층 — 데이터링크 (Data Link)**
- 물리 주소(MAC)로 같은 네트워크 내 통신
- 프레임 단위 전송, CRC로 오류 검출
- 장비: **스위치, 브리지**

**1계층 — 물리 (Physical)**
- 비트(0/1)를 전기·빛·전파 신호로 변환
- 장비: **허브, 리피터, 케이블**
- 데이터 내용 무관, 신호 전달만

---

### PDU (Protocol Data Unit)

각 계층에서 데이터 단위 명칭.

| 계층 | PDU 명칭 |
|------|---------|
| 7·6·5계층 | **메시지 (Message)** |
| 4계층 | **세그먼트 (Segment)** — TCP / **데이터그램** — UDP |
| 3계층 | **패킷 (Packet)** |
| 2계층 | **프레임 (Frame)** |
| 1계층 | **비트 (Bit)** |

---

### OSI vs TCP/IP 비교

| OSI 7계층 | TCP/IP 4계층 | 프로토콜 예시 |
|-----------|------------|------------|
| 응용·표현·세션 (7·6·5) | **응용 계층** | HTTP, FTP, DNS, SMTP |
| 전송 (4) | **전송 계층** | TCP, UDP |
| 네트워크 (3) | **인터넷 계층** | IP, ICMP, ARP |
| 데이터링크·물리 (2·1) | **네트워크 액세스 계층** | Ethernet, Wi-Fi |

> **핵심 암기**
> - OSI 7계층 순서: 아파세전네데물
> - PDU: 세그먼트(4) → 패킷(3) → 프레임(2) → 비트(1)
> - 라우터 = 3계층 / 스위치 = 2계층 / 허브 = 1계층
> - TCP = 신뢰성·순서보장 / UDP = 빠름·비신뢰
> - TCP/IP는 OSI를 4계층으로 단순화한 실용 모델

## IP 주소 체계

---

### IPv4

- **32비트** 주소 체계. 점(.)으로 구분된 4개의 옥텟(Octet)
- 표기: `192.168.0.1` (각 옥텟 0~255)
- 총 주소 수: 2³² ≈ 약 43억 개

#### 클래스 분류 (시험 빈출)

| 클래스 | 첫 비트 | 범위 (첫 옥텟) | 기본 서브넷 마스크 | 용도 |
|--------|---------|--------------|-----------------|------|
| **A** | 0 | 0 ~ 127 | 255.0.0.0 (/8) | 대형 네트워크 |
| **B** | 10 | 128 ~ 191 | 255.255.0.0 (/16) | 중형 네트워크 |
| **C** | 110 | 192 ~ 223 | 255.255.255.0 (/24) | 소형 네트워크 |
| **D** | 1110 | 224 ~ 239 | — | 멀티캐스트 |
| **E** | 1111 | 240 ~ 255 | — | 실험용 (예약) |

#### 사설 IP (Private IP)

인터넷에서 라우팅되지 않는 내부 전용 주소. NAT로 공인 IP 변환 후 인터넷 접속.

| 클래스 | 사설 IP 범위 |
|--------|------------|
| A | 10.0.0.0 ~ 10.255.255.255 |
| B | 172.16.0.0 ~ 172.31.255.255 |
| C | 192.168.0.0 ~ 192.168.255.255 |

---

### IPv6

- **128비트** 주소 체계. 콜론(:)으로 구분된 8개의 16진수 그룹
- 표기: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`
- 총 주소 수: 2¹²⁸ (사실상 무한)
- IPv4 고갈 문제 해결 위해 개발

#### 표기 단축 규칙

1. 각 그룹의 앞자리 0 생략: `0db8` → `db8`
2. 연속된 0 그룹은 `::` 로 한 번만 생략: `0000:0000:0000` → `::`

```
2001:0db8:0000:0000:0000:0000:0000:0001
→ 2001:db8::1
```

#### 주요 특징

| 특징 | 내용 |
|------|------|
| **자동 주소 설정** | SLAAC로 수동 설정 불필요 |
| **보안** | IPSec 기본 내장 |
| **헤더 단순화** | 고정 40바이트, 라우팅 효율 향상 |
| **멀티캐스트 강화** | 브로드캐스트 없음, 멀티캐스트·애니캐스트 사용 |

---

### IPv4 vs IPv6 비교

| 구분 | IPv4 | IPv6 |
|------|------|------|
| **주소 길이** | 32비트 | 128비트 |
| **표기** | 10진수, 점(.) 구분 | 16진수, 콜론(:) 구분 |
| **주소 수** | 약 43억 | 사실상 무한 |
| **헤더 크기** | 가변 (20~60바이트) | 고정 (40바이트) |
| **보안** | 별도 설정 필요 | IPSec 기본 내장 |
| **브로드캐스트** | 있음 | 없음 (멀티캐스트 대체) |
| **NAT** | 필요 | 불필요 |
| **자동 설정** | DHCP 필요 | SLAAC 가능 |

---

### 서브넷 마스크 & CIDR

**서브넷 마스크**: 네트워크 부분과 호스트 부분을 구분하는 32비트 값

```
IP:   192.168.1.0
마스크: 255.255.255.0
      = 11111111.11111111.11111111.00000000
         ↑ 네트워크 부분 (24비트)  ↑ 호스트 부분 (8비트)
```

**CIDR (Classless Inter-Domain Routing)**: `/비트수` 로 서브넷 마스크 표현

| CIDR | 서브넷 마스크 | 호스트 수 |
|------|-------------|---------|
| /8 | 255.0.0.0 | 2²⁴ - 2 = 약 1677만 |
| /16 | 255.255.0.0 | 2¹⁶ - 2 = 65,534 |
| /24 | 255.255.255.0 | 2⁸ - 2 = 254 |
| /25 | 255.255.255.128 | 2⁷ - 2 = 126 |

> 호스트 수 = 2^(호스트 비트 수) - 2  
> (-2 이유: 네트워크 주소·브로드캐스트 주소 제외)

---

### 특수 IP 주소

| 주소 | 용도 |
|------|------|
| **127.0.0.1** | 루프백(Loopback). 자기 자신. `localhost` |
| **0.0.0.0** | 모든 인터페이스 / 기본 경로 |
| **255.255.255.255** | 제한된 브로드캐스트 (로컬 네트워크 전체) |
| **네트워크 주소** | 호스트 부분 전부 0 (예: 192.168.1.0/24) |
| **브로드캐스트 주소** | 호스트 부분 전부 1 (예: 192.168.1.255/24) |

---

### NAT (Network Address Translation)

**개념**: 사설 IP ↔ 공인 IP 변환. 내부 네트워크가 하나의 공인 IP로 인터넷 접속 가능.

```
[사설 IP: 192.168.0.10]
        ↓
[NAT 라우터] → 공인 IP: 203.0.113.1 → 인터넷
        ↓
[사설 IP: 192.168.0.20]
```

| 종류 | 설명 |
|------|------|
| **정적 NAT** | 사설 IP 1개 ↔ 공인 IP 1개 고정 매핑 |
| **동적 NAT** | 사설 IP → 공인 IP 풀에서 동적 할당 |
| **PAT (포트 NAT / NAPT)** | 여러 사설 IP → 공인 IP 1개 + 포트 번호로 구분. 가장 일반적 |

> **핵심 암기**
> - IPv4 = 32비트, 클래스 A(0~127)·B(128~191)·C(192~223)
> - IPv6 = 128비트, IPSec 내장, 브로드캐스트 없음
> - 사설 IP: 10.x.x.x / 172.16~31.x.x / 192.168.x.x
> - CIDR /24 = 255.255.255.0 = 호스트 254개
> - 루프백 = 127.0.0.1
> - NAT = 사설↔공인 IP 변환, PAT = 포트까지 구분

## 주요 프로토콜

---

### 메일 프로토콜

> SMTP / POP3 / IMAP

**SMTP (Simple Mail Transfer Protocol)** — 송신
- 포트: 25 (일반) · 587 (STARTTLS) · 465 (SMTPS)
- 발신자 → 메일 서버, 서버 간 전달. 푸시 방식

**POP3 (Post Office Protocol 3)** — 수신 + 삭제
- 포트: 110 (일반) · 995 (POP3S)
- 서버에서 다운로드 후 삭제 (기본). 단일 기기에 적합

**IMAP (Internet Message Access Protocol)** — 수신 + 서버 유지
- 포트: 143 (일반) · 993 (IMAPS)
- 서버에 메일 유지 → 다중 기기 동기화 가능

| 구분 | SMTP | POP3 | IMAP |
|------|------|------|------|
| 방향 | 송신 | 수신 | 수신 |
| 포트 | 25/587 | 110 | 143 |
| 서버 저장 | - | 삭제 | 유지 |
| 다중 기기 | - | 불편 | 가능 |

---

### 기타 주요 프로토콜

| 프로토콜 | 계층 | 포트 | 역할 |
|----------|------|------|------|
| **FTP** | 응용 | 20(데이터)/21(제어) | 파일 전송 |
| **SSH** | 응용 | 22 | 암호화 원격 접속 |
| **Telnet** | 응용 | 23 | 원격 접속 (암호화 없음) |
| **DNS** | 응용 | 53 | 도메인 → IP 변환 |
| **HTTP** | 응용 | 80 | 웹 통신 |
| **HTTPS** | 응용 | 443 | 암호화 웹 통신 |
| **SNMP** | 응용 | 161 | 네트워크 장비 관리 |
| **DHCP** | 응용 | 67/68 | IP 자동 할당 |
| **ARP** | 네트워크 | - | IP → MAC 주소 변환 |
| **ICMP** | 네트워크 | - | 오류 보고 (ping) |

---

> **핵심 암기**
> - SMTP = 송신(25), POP3 = 수신+삭제(110), IMAP = 수신+유지(143)
> - SSH = 암호화 원격(22), Telnet = 비암호화 원격(23)

## 라우팅 프로토콜

출발지 → 목적지까지 **최적 경로**를 결정하는 프로토콜. OSI 3계층(네트워크).

---

### 정적 vs 동적 라우팅

| 구분 | 정적 라우팅 (Static) | 동적 라우팅 (Dynamic) |
|------|---------------------|----------------------|
| 경로 설정 | 관리자가 수동 설정 | 라우터가 자동으로 경로 학습·갱신 |
| 변화 대응 | 불가 (수동 수정 필요) | 자동 대응 |
| 오버헤드 | 없음 | 라우팅 정보 교환 트래픽 발생 |
| 보안 | 높음 (외부 정보 수신 없음) | 상대적으로 낮음 |
| 규모 | 소규모 네트워크 | 중·대규모 네트워크 |

---

### IGP vs EGP

| 구분 | IGP (내부 게이트웨이 프로토콜) | EGP (외부 게이트웨이 프로토콜) |
|------|-------------------------------|-------------------------------|
| 사용 범위 | **AS 내부** (같은 자율 시스템) | **AS 간** (다른 자율 시스템) |
| 대표 프로토콜 | RIP, OSPF, EIGRP | BGP |

> **AS (Autonomous System, 자율 시스템)**: 하나의 라우팅 정책으로 운영되는 네트워크 집합 (ISP, 대기업 등)

---

### 거리 벡터 vs 링크 상태

| 구분 | 거리 벡터 (Distance Vector) | 링크 상태 (Link State) |
|------|----------------------------|----------------------|
| 경로 결정 기준 | 거리(홉 수, 메트릭) + 방향 | 네트워크 전체 토폴로지 |
| 정보 교환 | 인접 라우터에만 라우팅 테이블 전달 | 전체 라우터에 링크 상태 정보 플러딩 |
| 수렴 속도 | 느림 | 빠름 |
| 루프 방지 | 스플릿 호라이즌, 홉 제한 | SPF 알고리즘으로 루프 없음 |
| 메모리·CPU | 적게 사용 | 많이 사용 |
| 대표 프로토콜 | RIP, EIGRP | OSPF, IS-IS |

> **수렴(Convergence)**: 네트워크 변화 후 모든 라우터가 동일한 라우팅 정보를 가지는 상태

---

### 주요 라우팅 프로토콜

#### RIP (Routing Information Protocol)

- 분류: IGP / 거리 벡터
- 메트릭: **홉 수 (Hop Count)** — 라우터 통과 횟수
- 최대 홉 수: **15** (16 = 도달 불가)
- 갱신 주기: **30초**마다 브로드캐스트
- 버전: RIPv1 (클래스 기반), RIPv2 (CIDR 지원, 멀티캐스트)
- 단점: 소규모 네트워크용, 수렴 느림, 최대 15홉 제한

#### OSPF (Open Shortest Path First)

- 분류: IGP / 링크 상태
- 메트릭: **코스트 (Cost)** — 대역폭 기반 (`10^8 / 대역폭`)
- 알고리즘: **다익스트라 (Dijkstra) SPF**
- 변화 발생 시에만 LSA(링크 상태 광고) 전송 → 효율적
- **Area** 개념으로 계층적 설계 가능 (Area 0 = 백본)
- 대규모 네트워크에 적합, 빠른 수렴

#### EIGRP (Enhanced Interior Gateway Routing Protocol)

- 분류: IGP / 고급 거리 벡터 (하이브리드)
- 시스코(Cisco) 개발 → 현재 공개 표준
- 메트릭: **대역폭 + 지연(Delay)** 복합
- 알고리즘: **DUAL (Diffusing Update Algorithm)**
- 빠른 수렴, 부분 업데이트 (변경분만 전송)

#### BGP (Border Gateway Protocol)

- 분류: EGP
- AS 간 라우팅 — **인터넷 백본 라우팅 프로토콜**
- 메트릭: **경로 속성 (Path Attribute)** — AS 경로 길이, 정책 기반
- 유형: eBGP (AS 간) / iBGP (AS 내부)
- TCP 179포트 사용 → 신뢰성 있는 연결 기반
- 수렴 느리지만 대규모 인터넷 라우팅에 최적

---

### 라우팅 프로토콜 비교 암기표

| 프로토콜 | 유형 | 분류 | 메트릭 | 최대 홉 | 특징 |
|----------|------|------|--------|---------|------|
| **RIP** | IGP | 거리 벡터 | 홉 수 | 15 | 단순, 소규모 |
| **OSPF** | IGP | 링크 상태 | 코스트(대역폭) | 무제한 | 다익스트라, Area 계층화 |
| **EIGRP** | IGP | 하이브리드 | 대역폭+지연 | 무제한 | DUAL 알고리즘, 시스코 |
| **BGP** | EGP | 경로 벡터 | 경로 속성 | 무제한 | 인터넷 AS 간, TCP 179 |

> **핵심 암기**
> - RIP = 홉 수, 최대 15홉, 30초 갱신
> - OSPF = 링크 상태, 다익스트라, 코스트(대역폭), Area 구조
> - EIGRP = 하이브리드, DUAL, 시스코
> - BGP = AS 간 EGP, 인터넷 백본, TCP 179
> - 거리 벡터(RIP) 수렴 느림 / 링크 상태(OSPF) 수렴 빠름

## 정보보안

---

### 정보보안 기본 목표

데이터 송수신 과정에서 보호해야 할 핵심 속성.

| 목표 | 영문 | 설명 | 위협 |
|------|------|------|------|
| **기밀성** | Confidentiality | 인가된 사용자만 데이터 접근 가능 | 도청, 스니핑 |
| **무결성** | Integrity | 데이터가 전송 중 변조되지 않음 | 변조, 위조 |
| **가용성** | Availability | 인가된 사용자가 필요 시 항상 접근 가능 | DoS/DDoS 공격 |
| **부인방지** | Non-Repudiation | 송수신 사실을 나중에 부인 불가 | 서명 위조 |
| **인증** | Authentication | 통신 상대방의 신원 확인 | 스푸핑, 피싱 |

> **CIA 3대 목표**: 기밀성·무결성·가용성 — 정보보안의 핵심

**각 목표별 보호 수단**

| 목표 | 주요 수단 |
|------|---------|
| 기밀성 | 암호화(AES·RSA), SSL/TLS |
| 무결성 | 해시(SHA-256), MAC, 전자서명 |
| 가용성 | 이중화·백업, 방화벽, DDoS 방어 |
| 부인방지 | 전자서명, 공인인증서(PKI) |
| 인증 | 인증서(X.509), OTP, 생체인식 |

> **핵심 암기**
> - CIA = 기밀성(도청 방지) · 무결성(변조 방지) · 가용성(DoS 방지)
> - 부인방지 = 전자서명으로 구현
> - 기밀성 ≠ 무결성 — 암호화해도 변조는 별도 보호 필요

---

### 보안 생명주기 방법론

정보보안을 **지속적·체계적**으로 관리하는 순환 프로세스.

#### PDCA (Plan-Do-Check-Act)

```
Plan (계획)
    ↓ 보안 목표·정책 수립, 위험 분석
Do (실행)
    ↓ 보안 통제 구현·운영
Check (검토)
    ↓ 모니터링·감사·성과 측정
Act (개선)
    ↓ 결함 수정·예방조치 → 다시 Plan
```

ISO/IEC 27001 (ISMS) 기반 순환 모델.

---

#### 정보보안 관리체계 (ISMS)

**ISMS (Information Security Management System)**
- 조직의 정보자산 보호를 위한 **체계적 보안 관리 프레임워크**
- 국내: **ISMS-P** (개인정보보호 포함) — 과기정통부·개인정보보호위원회 인증
- 국제: **ISO/IEC 27001**

---

#### 위험 관리 프로세스

```
자산 식별
    ↓
위협·취약점 분석
    ↓
위험 평가 (위험 = 자산가치 × 위협 × 취약성)
    ↓
위험 처리 전략 선택
    ↓
보안 통제 구현
    ↓
잔여 위험 수용
```

**위험 처리 전략**

| 전략 | 설명 | 예시 |
|------|------|------|
| **위험 감소 (Reduction)** | 보안 통제 적용해 위험 낮춤 | 방화벽·암호화 도입 |
| **위험 회피 (Avoidance)** | 위험 유발 활동 중단 | 취약한 서비스 폐지 |
| **위험 전가 (Transfer)** | 보험·외주로 위험 이전 | 사이버 보험 가입 |
| **위험 수용 (Acceptance)** | 비용 대비 수용 가능한 위험 그대로 유지 | 저위험 항목 허용 |

---

#### 보안 평가 기준

| 기준 | 설명 |
|------|------|
| **CC (Common Criteria)** | IT 제품·시스템 보안 평가 국제 표준 (ISO 15408). EAL1~EAL7 등급 |
| **TCSEC** | 미국 국방부 보안 평가 기준 (오렌지북). D·C1·C2·B1·B2·B3·A1 |
| **ITSEC** | 유럽 보안 평가 기준. E0~E6 |

> **핵심 암기**
> - PDCA = 계획→실행→검토→개선 순환 (ISO 27001 기반)
> - 위험 = 자산가치 × 위협 × 취약성
> - 위험 처리 4가지: 감소·회피·전가·수용
> - CC(Common Criteria) = IT 보안 평가 국제 표준, EAL 등급

---

### 보안 프로토콜

> IPSec / SSL·TLS / S-HTTP / HTTPS

**IPSec (IP Security)**
- 계층: 네트워크 (Layer 3) / 목적: IP 패킷 암호화·인증, VPN 구현
- AH(인증만) · ESP(암호화+인증) · IKE(키 교환)
- 전송 모드: 페이로드만 암호화 / 터널 모드: 패킷 전체 암호화 (VPN)

**SSL / TLS (Secure Sockets Layer / Transport Layer Security)**
- 계층: 전송~응용 사이 (Layer 4~7) / 목적: 채널 전체 암호화
- SSL 3.0 → TLS 1.0 → TLS 1.3 으로 발전
- 기밀성(대칭키) · 무결성(MAC) · 인증(X.509 인증서)
- HTTPS = HTTP + TLS / 포트 443

**S-HTTP (Secure HyperText Transfer Protocol)**
- 계층: 응용 (Layer 7) / 목적: HTTP 메시지 단위 개별 암호화·서명
- SSL = 채널 전체 암호화 / S-HTTP = 메시지 개별 암호화 (현재 거의 미사용)

| 구분 | SSL/TLS | S-HTTP |
|------|---------|--------|
| 암호화 단위 | 연결(세션) 전체 | 메시지 개별 |
| 계층 | 전송~응용 | 응용 |
| 사용 현황 | 광범위 (HTTPS) | 거의 미사용 |

> **핵심 암기**
> - IPSec = 네트워크 계층, VPN, AH(인증)/ESP(암호화+인증)
> - SSL/TLS = 채널 암호화, HTTPS에 사용, 포트 443
> - S-HTTP = 메시지 단위 암호화, 현재 거의 미사용

시스템·네트워크에 악의적 행위를 수행하는 소프트웨어 총칭.

| 구분 | 바이러스 | 웜 | 트로이목마 |
|------|---------|-----|----------|
| 자가복제 | O | O | X |

| 주요 피해 | 파일 감염·파괴 | 대역폭 소모·시스템 부하 | 정보 탈취·백도어 |

### 네트워크 공격

**DoS / DDoS**

| 구분 | DoS (Denial of Service) | DDoS (Distributed DoS) |
|------|------------------------|------------------------|
| 공격 주체 | 단일 시스템 | 다수 좀비 PC (봇넷) |
| 추적 난이도 | 낮음 | 높음 |
| 피해 규모 | 상대적으로 작음 | 대규모 |

**주요 DoS 공격 유형**

| 공격 | 설명 |
|------|------|
| **SYN Flooding** | TCP 3-way handshake에서 SYN만 대량 전송 → 연결 대기 큐 포화 |
| **Smurf** | 출발지 IP를 피해자로 위조 → 브로드캐스트 ICMP → 응답 폭주 |
| **Ping of Death** | 규격 초과(65535바이트↑) ICMP 패킷 전송 → 시스템 충돌 |
| **Teardrop** | IP 단편화 패킷 오프셋 조작 → 재조합 실패로 시스템 크래시 |
| **Land Attack** | 출발지·목적지 IP/포트를 동일하게 위조 → 무한 루프 |

**스니핑 vs 스푸핑**

| 구분 | 스니핑 (Sniffing) | 스푸핑 (Spoofing) |
|------|-----------------|-----------------|
| 개념 | 네트워크 패킷 **도청** (수동) | 신원·주소를 **위장** (능동) |
| 종류 | 패킷 스니핑 | IP 스푸핑, ARP 스푸핑, DNS 스푸핑 |
| 대응 | 암호화(SSL/TLS) | 인증, 패킷 필터링 |

**기타 네트워크 공격**

| 공격 | 설명 |
|------|------|
| **ARP 스푸핑** | ARP 응답 위조 → MAC 주소 테이블 오염 → 트래픽 가로채기 |
| **DNS 스푸핑** | DNS 응답 위조 → 악성 사이트로 리다이렉트 |
| **세션 하이재킹** | 인증된 세션 탈취 → 재인증 없이 서비스 사용 |
| **중간자 공격 (MITM)** | 통신 중간에 개입 → 도청·변조 |
| **포트 스캐닝** | 열린 포트 탐지 → 공격 사전 정찰 |

---

### 사회공학 공격

기술이 아닌 **사람의 심리**를 이용해 정보 탈취.

| 공격 | 설명 |
|------|------|
| **피싱 (Phishing)** | 신뢰 기관 사칭 이메일·사이트로 개인정보 탈취 |
| **스피어 피싱 (Spear Phishing)** | 특정 개인·조직 대상 맞춤형 피싱 |
| **스미싱 (Smishing)** | SMS 문자 기반 피싱 |
| **보이스 피싱 (Vishing)** | 전화 통화 기반 피싱 |
| **파밍 (Pharming)** | DNS 변조로 정상 URL 접속 시 악성 사이트로 유도 |
| **큐싱 (Qshing)** | QR코드를 통한 피싱 |
| **워터링 홀 (Watering Hole)** | 표적이 자주 방문하는 사이트에 악성코드 삽입 |

> **핵심 암기**
> - 바이러스=숙주O 복제O / 웜=숙주X 복제O / 트로이목마=숙주X 복제X
> - 랜섬웨어 = 파일 암호화 + 금전 요구
> - 루트킷 = 관리자 권한 탈취 + 자신 은닉
> - SYN Flooding = 3-way handshake 악용
> - 피싱(이메일) / 스미싱(SMS) / 파밍(DNS 변조) 구분

## 암호화 (Encryption)

평문(Plaintext)을 알아볼 수 없는 암호문(Ciphertext)으로 변환하는 기술.  
목적: **기밀성(Confidentiality)** 보장.

---

### 대칭키 암호화 (Symmetric Key)

**동일한 키**로 암호화·복호화.

```
평문 → [암호화: 비밀키 K] → 암호문 → [복호화: 비밀키 K] → 평문
```

**특징**
- 속도 빠름 → 대용량 데이터 암호화에 적합
- 키 배송 문제: 수신자에게 키를 안전하게 전달하기 어려움
- n명이 서로 통신 시 필요한 키 수: **n(n-1)/2**

**주요 알고리즘**

| 알고리즘 | 키 길이 | 블록 크기 | 특징 |
|----------|---------|----------|------|
| **DES** | 56비트 | 64비트 | 구식, 현재 안전하지 않음 |
| **3DES (Triple DES)** | 112/168비트 | 64비트 | DES 3회 적용, 느림 |
| **AES** | 128/192/256비트 | 128비트 | 현재 표준, 빠르고 안전 |
| **ARIA** | 128/192/256비트 | 128비트 | 국내 표준 (KS) |
| **SEED** | 128/256비트 | 128비트 | 국내 개발 표준 |
| **RC4** | 가변 | 스트림 | 스트림 암호, WEP에 사용 (취약) |

> 블록 암호: 데이터를 고정 크기 블록 단위로 암호화  
> 스트림 암호: 비트/바이트 단위로 연속 암호화

---

### 비대칭키 암호화 (Asymmetric Key, 공개키)

**공개키(Public Key)** 로 암호화, **개인키(Private Key)** 로 복호화.  
두 키는 수학적으로 쌍을 이루며 한 키로 암호화하면 반드시 다른 키로만 복호화 가능.

```
송신자:  평문 → [암호화: 수신자 공개키] → 암호문
수신자:  암호문 → [복호화: 수신자 개인키] → 평문
```

**전자서명 (Digital Signature)**
```
서명자:  해시값 → [서명: 서명자 개인키] → 서명값
검증자:  서명값 → [검증: 서명자 공개키] → 해시값 일치 여부 확인
```

**특징**
- 키 배송 문제 해결 (공개키는 공개해도 됨)
- 속도 느림 → 대용량 데이터에 부적합
- n명 통신 시 필요한 키 수: **2n** (각자 공개키·개인키 1쌍)

**주요 알고리즘**

| 알고리즘 | 기반 수학 | 특징 |
|----------|----------|------|
| **RSA** | 큰 수 소인수분해 어려움 | 가장 널리 사용. 암호화·전자서명 모두 가능 |
| **ECC** | 타원 곡선 이산로그 | RSA보다 짧은 키로 동등 보안. 모바일에 적합 |
| **Diffie-Hellman** | 이산로그 | 키 교환 전용 (암호화 불가). 최초 공개키 알고리즘 |
| **ElGamal** | 이산로그 | Diffie-Hellman 기반. 암호화·서명 가능 |
| **DSA** | 이산로그 | 전자서명 전용 (미국 표준 FIPS) |

---

### 대칭 vs 비대칭 비교

| 구분 | 대칭키 | 비대칭키 |
|------|--------|---------|
| **키** | 동일한 키 1개 | 공개키·개인키 쌍 |
| **속도** | 빠름 | 느림 |
| **키 배송** | 어려움 (문제) | 용이 (공개키 공개) |
| **키 수 (n명)** | n(n-1)/2 | 2n |
| **용도** | 대용량 데이터 암호화 | 키 교환, 전자서명 |
| **대표 알고리즘** | AES, SEED, ARIA | RSA, ECC |

> **혼합 암호 시스템**: 비대칭키로 세션키(대칭키)를 안전하게 교환 → 이후 대칭키로 빠르게 통신  
> (SSL/TLS 동작 방식)

---

### 해시 함수 (Hash Function)

임의 길이 데이터 → **고정 길이 해시값(다이제스트)** 변환. 단방향(역산 불가).

**특징**
- **일방향성**: 해시값으로 원본 복원 불가
- **충돌 저항성**: 같은 해시값을 갖는 다른 입력 찾기 어려움
- 입력 1비트 변경 → 출력 완전히 다름 (눈사태 효과)
- 암호화 아님 — 복호화 개념 없음

**주요 해시 알고리즘**

| 알고리즘 | 출력 길이 | 특징 |
|----------|---------|------|
| **MD5** | 128비트 | 충돌 취약, 현재 보안용 부적합 |
| **SHA-1** | 160비트 | 충돌 발견, 현재 사용 지양 |
| **SHA-256** | 256비트 | 현재 표준. SSL/TLS, 블록체인 |
| **SHA-512** | 512비트 | SHA-256보다 강한 보안 |
| **HAS-160** | 160비트 | 국내 표준 |

**활용**
- 비밀번호 저장 (해시+솔트)
- 데이터 무결성 검증
- 전자서명 (메시지 해시 후 서명)
- 블록체인

---

### PKI (Public Key Infrastructure, 공개키 기반 구조)

공개키 암호화의 **신뢰 체계** — 공개키가 진짜인지 인증하는 기반 시설.

**구성 요소**

| 구성 요소 | 역할 |
|-----------|------|
| **CA (인증 기관)** | 인증서 발급·폐지·관리. 최상위 신뢰 기관 |
| **RA (등록 기관)** | 사용자 신원 확인 후 CA에 인증서 발급 요청 |
| **인증서 (Certificate)** | 공개키 + 소유자 정보 + CA 서명. X.509 형식 |
| **CRL (인증서 폐지 목록)** | 폐지된 인증서 목록 |
| **OCSP** | 실시간 인증서 유효성 확인 프로토콜 |

**인증서 발급 흐름**

```
사용자 → [키쌍 생성] → 공개키 + 신원정보 → RA → CA
CA → [CA 개인키로 서명] → 인증서 발급 → 사용자
```

**인증서 검증 흐름**

```
수신자 → 인증서 수신 → CA 공개키로 서명 검증 → 공개키 신뢰 확보
```

> **핵심 암기**
> - 대칭키: 같은 키, 빠름, AES·SEED·ARIA (국내 표준)
> - 비대칭키: 공개키·개인키 쌍, 느림, RSA·ECC
> - 해시: 단방향, 고정 길이, MD5(취약)/SHA-256(현재 표준)
> - 혼합 암호 = 비대칭(키 교환) + 대칭(데이터 암호화) → SSL/TLS
> - PKI = CA가 공개키 신뢰 보증, X.509 인증서 형식
> - SEED·ARIA·HAS-160 = 국내 표준 알고리즘

## 메모리 관리

프로그램 실행 시 논리 주소(프로세스가 사용하는 주소) → 물리 주소(실제 RAM 주소) 변환.

---

### 페이징 (Paging)

메모리를 **고정 크기** 블록으로 분할.

- **페이지 (Page)**: 논리 메모리의 고정 크기 블록
- **프레임 (Frame)**: 물리 메모리의 동일 크기 블록
- **페이지 테이블**: 페이지 번호 → 프레임 번호 매핑

**주소 변환**

```
논리 주소 = (페이지 번호 p, 오프셋 d)
         ↓ 페이지 테이블[p] → 프레임 번호 f
물리 주소 = (프레임 번호 f, 오프셋 d)
```

**페이지 테이블 예시**

| 페이지 번호 (p) | 프레임 번호 (f) |
|---------------|---------------|
| 0 | 3 |
| 1 | 7 |
| 2 | 1 |
| 3 | 5 |

> 논리 주소 (p=1, d=100) → 프레임 7 → 물리 주소 = 7×프레임크기 + 100

- **내부 단편화**: 페이지 마지막 부분 남는 공간 낭비 (고정 크기라 발생)
- 외부 단편화 없음

---

### 세그먼테이션 (Segmentation)

메모리를 **가변 크기** 논리 단위(세그먼트)로 분할.  
세그먼트 = 코드·데이터·스택 등 의미 있는 단위.

- **세그먼트 테이블**: 세그먼트 번호 → (기준 주소, 한계값) 매핑
  - **기준(Base)**: 물리 메모리 시작 주소
  - **한계(Limit)**: 세그먼트 크기 (초과 접근 시 트랩 발생)

**주소 변환**

```
논리 주소 = (세그먼트 번호 s, 오프셋 d)
         ↓ 세그먼트 테이블[s] → base, limit
         ↓ d < limit 확인 (초과 시 세그먼테이션 폴트)
물리 주소 = base + d
```

**세그먼트 테이블 예시**

| 세그먼트 번호 (s) | 기준(Base) | 한계(Limit) |
|----------------|-----------|------------|
| 0 (코드) | 1000 | 400 |
| 1 (데이터) | 2000 | 300 |
| 2 (스택) | 3500 | 500 |

> 논리 주소 (s=1, d=200) → base=2000, limit=300 → d<limit OK → 물리 주소 2200

- **외부 단편화**: 가변 크기로 빈 공간이 조각남
- 내부 단편화 없음

---

### 페이징 vs 세그먼테이션

| 구분 | 페이징 | 세그먼테이션 |
|------|--------|------------|
| 분할 크기 | 고정 (페이지) | 가변 (세그먼트) |
| 논리 주소 | (페이지 번호, 오프셋) | (세그먼트 번호, 오프셋) |
| 변환 테이블 | 페이지 테이블 | 세그먼트 테이블 (Base+Limit) |
| 내부 단편화 | 발생 | 없음 |
| 외부 단편화 | 없음 | 발생 |
| 보호·공유 | 어려움 | 용이 (의미 단위) |

---

### 가상 메모리

실제 물리 메모리보다 큰 주소 공간을 제공하는 기법.  
보조기억장치(디스크)를 메모리처럼 사용.

**요구 페이징 (Demand Paging)**
- 필요한 페이지만 메모리에 적재
- 접근 시 페이지 없으면 **페이지 폴트(Page Fault)** 발생 → 디스크에서 로드

**스래싱 (Thrashing)**
- 페이지 폴트가 너무 자주 발생 → CPU가 페이지 교체만 반복 → 실제 작업 거의 못 함
- 원인: 다중 프로그래밍 정도 과도, 프레임 수 부족
- 해결: 워킹셋(Working Set) 모델, 프레임 추가 할당

---

### 페이지 교체 알고리즘

물리 메모리 꽉 찼을 때 어떤 페이지를 내보낼지 결정.

| 알고리즘 | 설명 | 특징 |
|----------|------|------|
| **OPT (최적)** | 앞으로 가장 오래 사용 안 할 페이지 교체 | 이론상 최적. 실제 구현 불가 |
| **FIFO** | 가장 먼저 들어온 페이지 교체 | 구현 단순. Belady's Anomaly 발생 가능 |
| **LRU** | 가장 오래 전에 사용된 페이지 교체 | 현실적 최선. 구현 비용 높음 |
| **LFU** | 사용 빈도 가장 낮은 페이지 교체 | 최근성 반영 못함 |
| **NUR (NRU)** | 최근 미사용 페이지 교체 (참조·수정 비트 활용) | LRU 근사. 구현 용이 |
| **Clock** | 원형 큐 + 참조 비트로 FIFO 개선 | NUR의 구현 방식 |

> **Belady's Anomaly**: FIFO에서 프레임 수 늘려도 페이지 폴트 증가하는 현상 (LRU·OPT는 해당 없음)

---

## 프로세스 스케줄링

CPU를 어떤 프로세스에 할당할지 결정.

**스케줄링 단계**
- **장기 (Long-term)**: 어떤 프로세스를 준비 큐에 넣을지
- **중기 (Medium-term)**: 스와핑 — 메모리↔디스크 이동
- **단기 (Short-term)**: CPU 스케줄러 — 준비 큐에서 실행할 프로세스 선택

**선점 vs 비선점**

| 구분 | 선점 (Preemptive) | 비선점 (Non-preemptive) |
|------|-----------------|----------------------|
| 의미 | 실행 중 CPU 강제 회수 가능 | 프로세스가 스스로 반납할 때까지 유지 |
| 응답성 | 높음 | 낮음 |
| 오버헤드 | 높음 | 낮음 |
| 대표 알고리즘 | Round Robin, SRT, 다단계 큐 | FCFS, SJF, 우선순위 |

---

### 스케줄링 알고리즘

| 알고리즘 | 선점 | 설명 | 단점 |
|----------|------|------|------|
| **FCFS** | X | 도착 순서대로 처리 | 호위 효과 (Convoy Effect) — 긴 작업 뒤 짧은 작업 대기 |
| **SJF** | X | 실행 시간 짧은 것 먼저 | 기아(Starvation) — 긴 작업 무한 대기 가능 |
| **SRT** | O | 남은 시간 짧은 것 먼저 (SJF 선점판) | 기아 발생 가능 |
| **Round Robin** | O | 시간 할당량(퀀텀)씩 순환 | 퀀텀 크기가 성능 결정 |
| **우선순위** | 선택 | 우선순위 높은 것 먼저 | 기아 → 에이징(Aging)으로 해결 |
| **다단계 큐** | O | 우선순위별 큐 분리, 큐 간 이동 없음 | 큐 간 이동 불가 |
| **다단계 피드백 큐** | O | 다단계 큐 + 큐 간 이동 가능 | 구현 복잡 |

> **에이징(Aging)**: 오래 대기한 프로세스의 우선순위를 점진적으로 높여 기아 방지

> **핵심 암기**
> - 페이징 = 고정 크기, 내부 단편화, 페이지 테이블(p→f)
> - 세그먼테이션 = 가변 크기, 외부 단편화, 세그먼트 테이블(base+limit)
> - LRU = 가장 오래 전 사용 교체 / FIFO = Belady's Anomaly
> - Round Robin = 선점, 시간 할당량 순환
> - 기아(Starvation) → 에이징(Aging)으로 해결

---

## 파일 시스템

OS가 보조기억장치의 파일을 **생성·저장·접근·삭제** 관리하는 체계.

---

### 파일 디스크립터

프로세스가 파일을 열 때 OS가 부여하는 **비음수 정수(Index)**.  
프로세스별 **파일 디스크립터 테이블** 의 인덱스로, 실제 파일 정보(FCB)를 가리킴.

```
프로세스
└─ 파일 디스크립터 테이블
   ├─ 0 → 표준 입력 (stdin)
   ├─ 1 → 표준 출력 (stdout)
   ├─ 2 → 표준 오류 (stderr)
   ├─ 3 → open("data.txt") 시 반환
   └─ 4 → open("log.txt") 시 반환
```

**기본 파일 디스크립터**

| 번호 | 이름 | 설명 |
|------|------|------|
| **0** | stdin | 표준 입력 (키보드) |
| **1** | stdout | 표준 출력 (화면) |
| **2** | stderr | 표준 오류 출력 |

**특징**

- 파일 열기(`open`) → OS가 FD 반환, 닫기(`close`) → FD 반환·해제
- FD는 프로세스 내에서만 유효 — 다른 프로세스와 공유 불가 (단, `fork` 시 자식 상속)
- FD를 통해 파일의 현재 위치(오프셋) 추적

**FCB (File Control Block, 파일 제어 블록)**

파일의 메타데이터를 저장하는 OS 내부 자료구조.

| 항목 | 내용 |
|------|------|
| 파일명 | 파일 이름 |
| 파일 크기 | 바이트 단위 |
| 파일 위치 | 디스크 상 저장 위치 |
| 접근 권한 | 읽기·쓰기·실행 권한 |
| 생성·수정 시각 | 타임스탬프 |
| 파일 유형 | 일반·디렉터리·링크 등 |

> Unix/Linux에서 FCB = **inode**

**파일 접근 방법**

| 방법 | 설명 |
|------|------|
| **순차 접근 (Sequential)** | 처음부터 순서대로 읽기. 테이프 방식 |
| **직접 접근 (Direct/Random)** | 임의 위치 직접 접근. 디스크 방식 |
| **색인 접근 (Indexed)** | 색인(Index) 참조 후 해당 위치 접근 |

> **핵심 암기**
> - FD = 열린 파일을 가리키는 정수 인덱스
> - 0=stdin / 1=stdout / 2=stderr 기본 고정
> - FCB(inode) = 파일 메타데이터 저장 구조
> - FD → FCB 참조 → 실제 디스크 접근

## 저작권 관리

---

### DRM (Digital Rights Management, 디지털 저작권 관리)

> 개념 / 구성 요소 / 흐름

디지털 콘텐츠의 **무단 복제·배포 방지** 및 사용 권한 통제 기술.

**개념**
- 콘텐츠 암호화 + 라이선스 기반 접근 제어
- 콘텐츠 생성~소비 전 과정에서 저작권자 권리 보호

**구성 요소**

| 구성 요소 | 역할 |
|-----------|------|
| **콘텐츠 제공자 (Contents Provider)** | 저작권자. 원본 콘텐츠 제공 |
| **콘텐츠 분배자 (Contents Distributor)** | 암호화된 콘텐츠 유통·배포 |
| **패키저 (Packager)** | 콘텐츠 암호화 + 메타데이터 패키징 |
| **보안 컨테이너 (Security Container)** | 암호화된 콘텐츠 저장 단위 |
| **클리어링 하우스 (Clearing House)** | 라이선스 발급·관리. 키 분배 |
| **DRM 컨트롤러** | 사용자 단에서 콘텐츠 사용 권한 제어 |
| **소비자 (Consumer)** | 라이선스 취득 후 콘텐츠 이용 |

**콘텐츠 흐름**

```
콘텐츠 제공자
    ↓ (원본)
패키저 → 암호화·패키징 → 보안 컨테이너
    ↓
콘텐츠 분배자 → 배포
    ↓
소비자 → 클리어링 하우스에 라이선스 요청
    ↓
DRM 컨트롤러 → 라이선스 확인 후 콘텐츠 복호화·재생
```

### 저작권 관련 기술 요소

> 워터마킹 / 핑거프린팅 / 암호화

**워터마킹 (Watermarking)**
- 콘텐츠에 저작권 정보(소유자 정보)를 **눈에 보이지 않게 삽입**
- 목적: 저작권 소유 증명, 불법 복제 추적
- 콘텐츠 변형 후에도 워터마크 유지

**핑거프린팅 (Fingerprinting)**
- 콘텐츠에 **구매자 정보**를 삽입
- 목적: 불법 유포자 식별·추적
- 워터마킹과 차이: 워터마킹=저작권자 정보 / 핑거프린팅=구매자 정보

| 구분 | 워터마킹 | 핑거프린팅 |
|------|----------|------------|
| 삽입 정보 | 저작권자·소유자 | 구매자·사용자 |
| 목적 | 소유권 증명 | 유포자 추적 |
| 가시성 | 비가시적 | 비가시적 |

**암호화 (Encryption)**
- 콘텐츠 자체를 암호화 → 라이선스(키) 없이 재생 불가
- DRM 핵심 기술

### 오픈소스 라이선스

> GPL / LGPL / MIT / Apache / BSD

**라이선스 비교**

| 라이선스 | 소스 공개 의무 | 상업적 이용 | 특징 |
|----------|--------------|------------|------|
| **GPL** | 강제 (파생물 포함) | 가능 | 카피레프트 가장 강함 |
| **LGPL** | 라이브러리 수정분만 공개 | 가능 | GPL 완화판. 링크 허용 |
| **MIT** | 없음 | 가능 | 가장 자유로움. 저작권 표시만 |
| **Apache 2.0** | 없음 | 가능 | 특허권 명시적 허용 |
| **BSD** | 없음 | 가능 | MIT와 유사. 광고 조항 여부로 구분 |

**카피레프트(Copyleft)**: 오픈소스 사용 시 파생 저작물도 동일 라이선스 적용 강제
- 강한 카피레프트: GPL
- 약한 카피레프트: LGPL
- 카피레프트 없음: MIT, Apache, BSD

> **핵심 암기**
> - DRM = 디지털 저작권 관리. 암호화 + 라이선스 기반
> - 클리어링 하우스 = 라이선스 발급·키 분배 기관
> - 워터마킹 = 저작권자 정보 삽입 / 핑거프린팅 = 구매자 정보 삽입
> - GPL = 카피레프트 강함 / MIT·Apache = 가장 자유로움
> - 패키저 = 콘텐츠 암호화·패키징 담당
