## 자료구조

### 스택 (Stack)

**개념**: 후입선출(LIFO, Last In First Out) 구조. 마지막에 넣은 데이터가 먼저 나옴.

```
push →  [ D ]  ← top
        [ C ]
        [ B ]
        [ A ]
```

| 연산 | 설명 |
|------|------|
| **push** | 스택 상단에 데이터 삽입 |
| **pop** | 스택 상단에서 데이터 제거·반환 |
| **peek / top** | 상단 데이터 조회 (제거 없음) |
| **isEmpty** | 스택 비었는지 확인 |

**활용 사례**:
- 함수 호출 스택 (재귀)
- 수식의 괄호 검사
- 후위 표기식(Postfix) 계산
- 브라우저 뒤로가기

---

### 힙 (Heap)

**개념**: 완전 이진 트리 기반의 자료구조. 항상 최솟값 또는 최댓값을 루트에 유지.

| 종류 | 특징 |
|------|------|
| **최소 힙 (Min Heap)** | 부모 ≤ 자식. 루트 = 최솟값 |
| **최대 힙 (Max Heap)** | 부모 ≥ 자식. 루트 = 최댓값 |

```
최소 힙 예시:
        1
       / \
      3   2
     / \
    7   4
```

| 연산 | 시간복잡도 |
|------|-----------|
| **삽입** | O(log n) |
| **삭제 (루트 제거)** | O(log n) |
| **최솟값/최댓값 조회** | O(1) |

**활용 사례**:
- 우선순위 큐 (Priority Queue) 구현
- 힙 정렬 (Heap Sort)
- 다익스트라 알고리즘

> ※ 자료구조 힙 ≠ 메모리 힙 영역 (이름만 같음)

---

### 트리 (Tree)

**개념**: 노드(Node)와 간선(Edge)으로 구성된 계층적 비선형 자료구조. 사이클 없음.

```
        A          ← 루트 (Root)
       / \
      B   C
     / \   \
    D   E   F
```

---

#### 용어 정리 (시험 빈출)

| 용어 | 설명 | 예시 (위 그림) |
|------|------|----------------|
| **루트 (Root)** | 최상위 노드, 부모 없음 | A |
| **단말 노드 (Leaf)** | 자식 없는 노드 | D, E, F |
| **내부 노드** | 자식 있는 노드 | A, B, C |
| **부모 (Parent)** | 상위 연결 노드 | B의 부모 = A |
| **자식 (Child)** | 하위 연결 노드 | A의 자식 = B, C |
| **형제 (Sibling)** | 같은 부모를 가진 노드 | B와 C |
| **조상 (Ancestor)** | 루트까지의 경로 상 노드 | D의 조상 = B, A |
| **자손 (Descendant)** | 해당 노드 아래 모든 노드 | B의 자손 = D, E |

#### 차수·깊이·높이

| 용어 | 설명 | 예시 (위 그림) |
|------|------|----------------|
| **차수 (Degree)** | 노드의 **자식 수** | A의 차수 = 2, B의 차수 = 2, F의 차수 = 0 |
| **트리의 차수** | 트리 내 **최대 차수** | 위 그림 = 2 |
| **레벨 (Level)** | 루트 = 1, 아래로 +1 | A=1, B·C=2, D·E·F=3 |
| **깊이 (Depth)** | 루트에서 해당 노드까지 간선 수 | D의 깊이 = 2 |
| **높이 (Height)** | 트리의 **최대 레벨** | 위 그림 = 3 |

---

#### 이진 트리 (Binary Tree)

- 모든 노드의 차수 ≤ 2 (자식 최대 2개)
- 왼쪽 자식 / 오른쪽 자식 구분

| 종류 | 설명 |
|------|------|
| **포화 이진 트리** | 모든 레벨이 꽉 찬 트리. 노드 수 = 2ⁿ - 1 |
| **완전 이진 트리** | 마지막 레벨 제외 모두 차 있고, 마지막은 왼쪽부터 채움 |
| **편향 이진 트리** | 모든 노드가 한쪽으로만 연결 (최악의 경우) |

---

#### 이진 탐색 트리 (BST)

- **왼쪽 자식 < 부모 < 오른쪽 자식** 항상 만족
- 탐색·삽입·삭제 평균 O(log n)
- 편향 시 최악 O(n)

```
      5
     / \
    3   7
   / \   \
  2   4   8
```

---

#### 트리 순회 (Traversal)

| 순회 | 순서 | 방법 |
|------|------|------|
| **전위 (Preorder)** | 루트 → 왼쪽 → 오른쪽 | **루**왼오 |
| **중위 (Inorder)** | 왼쪽 → 루트 → 오른쪽 | 왼**루**오 |
| **후위 (Postorder)** | 왼쪽 → 오른쪽 → 루트 | 왼오**루** |

**예시** (위 BST 그림):
- 전위: 5 → 3 → 2 → 4 → 7 → 8
- 중위: 2 → 3 → 4 → 5 → 7 → 8 ← **정렬된 순서**
- 후위: 2 → 4 → 3 → 8 → 7 → 5

---

#### 노드 수 공식

| 공식 | 내용 |
|------|------|
| n레벨의 노드 수 | 2^(n-1) |
| 포화 이진 트리 전체 노드 수 | 2^h - 1 (h = 높이) |
| 단말 노드 수 = 차수 2인 노드 수 + 1 | n₀ = n₂ + 1 |

---

> **핵심 암기**
> - 스택 = LIFO, push/pop
> - 힙 = 완전 이진 트리, 최솟값/최댓값 O(1) 접근
> - 차수(Degree) = 자식 수
> - 높이 = 최대 레벨
> - 중위 순회 BST = 오름차순 정렬
> - 포화 이진 트리 노드 수 = 2ⁿ - 1

## 테스트와 디버그

### 테스트 (Testing)

**개념**: 소프트웨어 결함 발견 및 품질 검증을 위한 실행 기반 검증 활동

---

#### 화이트박스 vs 블랙박스

| 구분 | 화이트박스 테스트 | 블랙박스 테스트 |
|------|------------------|-----------------|
| **관점** | 내부 구조·코드 기반 | 기능·명세 기반 |
| **대상** | 개발자 | 사용자·테스터 |
| **목적** | 코드 경로·분기 검증 | 입출력 기능 검증 |
| **종류** | 구문, 분기, 조건, 경로 커버리지 | 동등분할, 경계값, 원인-결과 |

#### 화이트박스 테스트 기법

| 기법 | 설명 |
|------|------|
| **구문(문장) 커버리지** | 모든 구문 최소 1회 실행 |
| **분기(결정) 커버리지** | 모든 분기(T/F) 최소 1회 실행 |
| **조건 커버리지** | 각 조건식의 T/F 최소 1회 실행 |
| **분기/조건 커버리지** | 분기 + 조건 모두 만족 |
| **경로 커버리지** | 가능한 모든 경로 실행 (가장 강력) |

> 강도: 경로 > 분기/조건 > 조건 > 분기 > 구문

#### 블랙박스 테스트 기법

| 기법 | 설명 |
|------|------|
| **동등분할 (Equivalence Partitioning)** | 입력값을 동등한 그룹으로 분류, 대표값 테스트 |
| **경계값 분석 (Boundary Value)** | 경계 근처 값(최소, 최대, 경계±1) 테스트 |
| **원인-결과 그래프** | 입력 조건(원인)과 출력(결과) 관계 그래프화 |
| **오류 예측** | 경험 기반 오류 발생 가능 부분 집중 테스트 |
| **비교 테스트** | 여러 버전 동일 입력으로 결과 비교 |

---

#### 테스트 레벨 (단계별)

| 레벨 | 설명 | 주체 |
|------|------|------|
| **단위 테스트** | 모듈·함수 개별 테스트 | 개발자 |
| **통합 테스트** | 모듈 간 인터페이스 테스트 | 개발자 |
| **시스템 테스트** | 전체 시스템 기능·비기능 테스트 | QA |
| **인수 테스트** | 사용자 요구사항 충족 여부 확인 | 사용자 |

#### 통합 테스트 방식

| 방식 | 설명 | 특징 |
|------|------|------|
| **빅뱅** | 모든 모듈 한번에 통합 | 오류 원인 파악 어려움 |
| **하향식 (Top-Down)** | 상위 모듈부터 통합, **스텁(Stub)** 사용 | 초기 동작 확인 용이 |
| **상향식 (Bottom-Up)** | 하위 모듈부터 통합, **드라이버(Driver)** 사용 | 하위 모듈 먼저 검증 |
| **샌드위치** | 하향식 + 상향식 병행 | 스텁 + 드라이버 모두 사용 |

> **스텁(Stub)**: 하위 모듈 대신하는 가짜 모듈 (하향식에서 사용)  
> **드라이버(Driver)**: 상위 모듈 대신하는 가짜 모듈 (상향식에서 사용)

---

#### 테스트 종류 (목적별)

| 종류 | 설명 |
|------|------|
| **기능 테스트** | 명세된 기능 동작 검증 |
| **성능 테스트** | 응답 시간, 처리량, 자원 사용량 측정 |
| **부하 테스트** | 한계 부하 상황에서 동작 검증 |
| **스트레스 테스트** | 한계 초과 부하로 장애 유발·복구 확인 |
| **회귀 테스트** | 변경 후 기존 기능 정상 동작 재확인 |
| **보안 테스트** | 취약점·접근제어 검증 |
| **사용성 테스트** | 사용자 편의성·UX 검증 |

---

### 디버그 (Debugging)

**개념**: 테스트에서 발견된 결함의 **원인을 찾아 수정**하는 과정  
※ 테스트 ≠ 디버그: 테스트는 결함 **발견**, 디버그는 결함 **제거**

---

#### 디버깅 기법

| 기법 | 설명 |
|------|------|
| **브루트 포스** | 메모리 덤프·출력문 삽입으로 무차별 탐색. 비효율적이나 가장 일반적 |
| **역추적 (Backtracking)** | 오류 발생 지점에서 역방향으로 코드 추적 |
| **원인 제거** | 이진 탐색 방식으로 원인 후보 범위 좁힘 |

#### 디버깅 절차

1. 오류 증상 파악
2. 오류 재현
3. 원인 위치 추적
4. 원인 분석 및 수정
5. 수정 후 재테스트 (회귀 테스트)

---

> **핵심 암기**
> - 화이트박스 = 내부 구조 기반, 커버리지로 강도 측정
> - 블랙박스 = 기능·명세 기반, 동등분할·경계값 대표 기법
> - 하향식 통합 → 스텁 / 상향식 통합 → 드라이버
> - 테스트 = 결함 발견 / 디버그 = 결함 제거

## 소스코드 품질 분석 도구

소프트웨어 소스코드의 결함·취약점·품질 문제를 발견하는 도구. **정적 도구**와 **동적 도구**로 구분.

---

### 정적 분석 도구 (Static Analysis Tool)

**프로그램을 실행하지 않고** 소스코드·바이트코드를 분석.

| 특징 | 내용 |
|------|------|
| **실행 여부** | 실행 없이 코드 분석 |
| **분석 시점** | 코딩 완료 후, 컴파일 전·후 |
| **발견 대상** | 코딩 규칙 위반, 보안 취약점, 미사용 변수, 복잡도 |
| **속도** | 빠름 (전체 코드 자동 검사) |
| **한계** | 실행 시 발생 오류 탐지 불가 |

#### 대표 도구

| 도구 | 언어 | 특징 |
|------|------|------|
| **pmd** | Java | 코딩 규칙 위반, 중복 코드 탐지 |
| **cppcheck** | C/C++ | 메모리 오류, 널 포인터, 버퍼 오버플로우 |
| **SonarQube** | 다중 언어 | 버그·취약점·코드 스멜 통합 분석 (CI 연동) |
| **FindBugs / SpotBugs** | Java | 바이트코드 분석, 버그 패턴 탐지 |
| **Checkstyle** | Java | 코딩 스타일·컨벤션 검사 |
| **ESLint** | JavaScript | 문법 오류, 스타일 위반 |
| **Pylint** | Python | 오류, 경고, 코딩 표준 검사 |

---

### 동적 분석 도구 (Dynamic Analysis Tool)

**프로그램을 실제 실행**하여 런타임 상태를 분석.

| 특징 | 내용 |
|------|------|
| **실행 여부** | 프로그램 실행 필수 |
| **분석 시점** | 실행 중 (Runtime) |
| **발견 대상** | 메모리 누수, 경쟁 조건, 실제 성능 병목, 런타임 오류 |
| **속도** | 느림 (실행 오버헤드 발생) |
| **한계** | 실행되지 않은 코드 분석 불가 |

#### 대표 도구

| 도구 | 특징 |
|------|------|
| **Valgrind** | C/C++ 메모리 누수·잘못된 접근 탐지 |
| **Purify** | 런타임 메모리 오류 탐지 (IBM) |
| **Insure++** | C/C++ 런타임 메모리·포인터 오류 |
| **Rational Quantify** | 성능 프로파일링, 병목 분석 |
| **JProfiler** | Java 힙 메모리·스레드 분석 |
| **VisualVM** | JVM 기반 앱 실시간 모니터링 |

---

### 정적 vs 동적 비교 요약

| 구분 | 정적 도구 | 동적 도구 |
|------|-----------|-----------|
| **실행** | 불필요 | 필요 |
| **분석 시점** | 컴파일 전·후 | 런타임 |
| **주요 탐지** | 코딩 결함, 보안 취약점 | 메모리 오류, 성능 문제 |
| **커버리지** | 전체 코드 | 실행된 경로만 |
| **속도** | 빠름 | 느림 |
| **대표 도구** | pmd, cppcheck, SonarQube | Valgrind, Purify |

> **핵심 암기**
> - 정적 = 실행 없이 코드 읽기 → pmd, cppcheck, SonarQube
> - 동적 = 실행하며 관찰 → Valgrind, Purify
> - 정적: 코딩 규칙·보안 취약점 / 동적: 메모리 누수·런타임 오류

## 소프트웨어 품질 관리 원칙

---

### 파레토 법칙 (Pareto's Law)

**"전체 결과의 80%는 전체 원인의 20%에서 발생한다"**

이탈리아 경제학자 Vilfredo Pareto의 80:20 법칙. 소프트웨어 품질 관리에 적용.

#### 소프트웨어에서의 의미

| 적용 영역 | 내용 |
|-----------|------|
| **결함 집중** | 소프트웨어 결함의 80%는 전체 모듈의 20%에서 발생 |
| **성능 병목** | 실행 시간의 80%는 코드의 20% 구간에서 소비 |
| **버그 재발** | 수정된 버그의 80%는 소수의 복잡한 모듈에 집중 |
| **테스트 집중** | 결함 다발 모듈에 테스트 자원 집중 투입 전략 근거 |

#### 품질 관리 활용

```
전체 모듈 100개 중 → 결함 유발 핵심 모듈 20개 집중 관리
전체 버그 100건 중 → 20%의 근본 원인 제거로 80% 해결
```

- **테스트 우선순위** 결정 기준: 결함 이력 多 모듈 집중
- **코드 리뷰 대상** 선정: 복잡도 높은 20% 모듈 우선
- **리팩토링 대상** 선정: 유지보수 비용 큰 소수 모듈

#### 관련 개념 비교

| 법칙 | 내용 | 소프트웨어 적용 |
|------|------|----------------|
| **파레토 법칙** | 80:20 비율로 결과 집중 | 결함 20% 모듈에 80% 집중 |
| **살충제 패러독스** | 동일 테스트 반복 시 결함 발견율 감소 | 다양한 테스트 기법 교체 필요 |
| **결함 집중 (Defect Clustering)** | 결함은 소수 모듈에 집중 | 파레토 법칙의 소프트웨어 표현 |

> **핵심 암기**
> - 파레토 법칙 = 80:20 법칙
> - 소프트웨어: 결함 80% → 전체 모듈 20%에서 발생
> - 활용: 결함 多 모듈에 테스트·리뷰 자원 집중
> - 결함 집중(Defect Clustering) = 파레토 법칙의 실무 적용

## 주요 프로토콜

---

### 보안 프로토콜

> IPSec / SSL·TLS / S-HTTP / HTTPS

**IPSec (IP Security)**
- 계층: 네트워크 (Layer 3) / 목적: IP 패킷 암호화·인증, VPN 구현
- AH(인증만) · ESP(암호화+인증) · IKE(키 교환)
- 전송 모드: 페이로드만 암호화 / 터널 모드: 패킷 전체 암호화 (VPN)

**SSL / TLS (Secure Sockets Layer / Transport Layer Security)**
- 계층: 전송~응용 사이 (Layer 4~7) / 목적: 채널 전체 암호화
- SSL 3.0 → TLS 1.0 → TLS 1.3 으로 발전
- 기밀성(대칭키) · 무결성(MAC) · 인증(X.509 인증서)
- HTTPS = HTTP + TLS / 포트 443

**S-HTTP (Secure HyperText Transfer Protocol)**
- 계층: 응용 (Layer 7) / 목적: HTTP 메시지 단위 개별 암호화·서명
- SSL = 채널 전체 암호화 / S-HTTP = 메시지 개별 암호화 (현재 거의 미사용)

| 구분 | SSL/TLS | S-HTTP |
|------|---------|--------|
| 암호화 단위 | 연결(세션) 전체 | 메시지 개별 |
| 계층 | 전송~응용 | 응용 |
| 사용 현황 | 광범위 (HTTPS) | 거의 미사용 |

---

### 메일 프로토콜

> SMTP / POP3 / IMAP

**SMTP (Simple Mail Transfer Protocol)** — 송신
- 포트: 25 (일반) · 587 (STARTTLS) · 465 (SMTPS)
- 발신자 → 메일 서버, 서버 간 전달. 푸시 방식

**POP3 (Post Office Protocol 3)** — 수신 + 삭제
- 포트: 110 (일반) · 995 (POP3S)
- 서버에서 다운로드 후 삭제 (기본). 단일 기기에 적합

**IMAP (Internet Message Access Protocol)** — 수신 + 서버 유지
- 포트: 143 (일반) · 993 (IMAPS)
- 서버에 메일 유지 → 다중 기기 동기화 가능

| 구분 | SMTP | POP3 | IMAP |
|------|------|------|------|
| 방향 | 송신 | 수신 | 수신 |
| 포트 | 25/587 | 110 | 143 |
| 서버 저장 | - | 삭제 | 유지 |
| 다중 기기 | - | 불편 | 가능 |

---

### 기타 주요 프로토콜

| 프로토콜 | 계층 | 포트 | 역할 |
|----------|------|------|------|
| **FTP** | 응용 | 20(데이터)/21(제어) | 파일 전송 |
| **SSH** | 응용 | 22 | 암호화 원격 접속 |
| **Telnet** | 응용 | 23 | 원격 접속 (암호화 없음) |
| **DNS** | 응용 | 53 | 도메인 → IP 변환 |
| **HTTP** | 응용 | 80 | 웹 통신 |
| **HTTPS** | 응용 | 443 | 암호화 웹 통신 |
| **SNMP** | 응용 | 161 | 네트워크 장비 관리 |
| **DHCP** | 응용 | 67/68 | IP 자동 할당 |
| **ARP** | 네트워크 | - | IP → MAC 주소 변환 |
| **ICMP** | 네트워크 | - | 오류 보고 (ping) |

---

> **핵심 암기**
> - IPSec = 네트워크 계층, VPN, AH(인증)/ESP(암호화+인증)
> - SSL/TLS = 채널 암호화, HTTPS에 사용, 포트 443
> - S-HTTP = 메시지 단위 암호화, 현재 거의 미사용
> - SMTP = 송신(25), POP3 = 수신+삭제(110), IMAP = 수신+유지(143)
> - SSH = 암호화 원격(22), Telnet = 비암호화 원격(23)

## 저작권 관리

---

### DRM (Digital Rights Management, 디지털 저작권 관리)

> 개념 / 구성 요소 / 흐름

디지털 콘텐츠의 **무단 복제·배포 방지** 및 사용 권한 통제 기술.

**개념**
- 콘텐츠 암호화 + 라이선스 기반 접근 제어
- 콘텐츠 생성~소비 전 과정에서 저작권자 권리 보호

**구성 요소**

| 구성 요소 | 역할 |
|-----------|------|
| **콘텐츠 제공자 (Contents Provider)** | 저작권자. 원본 콘텐츠 제공 |
| **콘텐츠 분배자 (Contents Distributor)** | 암호화된 콘텐츠 유통·배포 |
| **패키저 (Packager)** | 콘텐츠 암호화 + 메타데이터 패키징 |
| **보안 컨테이너 (Security Container)** | 암호화된 콘텐츠 저장 단위 |
| **클리어링 하우스 (Clearing House)** | 라이선스 발급·관리. 키 분배 |
| **DRM 컨트롤러** | 사용자 단에서 콘텐츠 사용 권한 제어 |
| **소비자 (Consumer)** | 라이선스 취득 후 콘텐츠 이용 |

**콘텐츠 흐름**

```
콘텐츠 제공자
    ↓ (원본)
패키저 → 암호화·패키징 → 보안 컨테이너
    ↓
콘텐츠 분배자 → 배포
    ↓
소비자 → 클리어링 하우스에 라이선스 요청
    ↓
DRM 컨트롤러 → 라이선스 확인 후 콘텐츠 복호화·재생
```

---

### 저작권 관련 기술 요소

> 워터마킹 / 핑거프린팅 / 암호화

**워터마킹 (Watermarking)**
- 콘텐츠에 저작권 정보(소유자 정보)를 **눈에 보이지 않게 삽입**
- 목적: 저작권 소유 증명, 불법 복제 추적
- 콘텐츠 변형 후에도 워터마크 유지

**핑거프린팅 (Fingerprinting)**
- 콘텐츠에 **구매자 정보**를 삽입
- 목적: 불법 유포자 식별·추적
- 워터마킹과 차이: 워터마킹=저작권자 정보 / 핑거프린팅=구매자 정보

| 구분 | 워터마킹 | 핑거프린팅 |
|------|----------|------------|
| 삽입 정보 | 저작권자·소유자 | 구매자·사용자 |
| 목적 | 소유권 증명 | 유포자 추적 |
| 가시성 | 비가시적 | 비가시적 |

**암호화 (Encryption)**
- 콘텐츠 자체를 암호화 → 라이선스(키) 없이 재생 불가
- DRM 핵심 기술

---

### 오픈소스 라이선스

> GPL / LGPL / MIT / Apache / BSD

**라이선스 비교**

| 라이선스 | 소스 공개 의무 | 상업적 이용 | 특징 |
|----------|--------------|------------|------|
| **GPL** | 강제 (파생물 포함) | 가능 | 카피레프트 가장 강함 |
| **LGPL** | 라이브러리 수정분만 공개 | 가능 | GPL 완화판. 링크 허용 |
| **MIT** | 없음 | 가능 | 가장 자유로움. 저작권 표시만 |
| **Apache 2.0** | 없음 | 가능 | 특허권 명시적 허용 |
| **BSD** | 없음 | 가능 | MIT와 유사. 광고 조항 여부로 구분 |

**카피레프트(Copyleft)**: 오픈소스 사용 시 파생 저작물도 동일 라이선스 적용 강제
- 강한 카피레프트: GPL
- 약한 카피레프트: LGPL
- 카피레프트 없음: MIT, Apache, BSD

> **핵심 암기**
> - DRM = 디지털 저작권 관리. 암호화 + 라이선스 기반
> - 클리어링 하우스 = 라이선스 발급·키 분배 기관
> - 워터마킹 = 저작권자 정보 삽입 / 핑거프린팅 = 구매자 정보 삽입
> - GPL = 카피레프트 강함 / MIT·Apache = 가장 자유로움
> - 패키저 = 콘텐츠 암호화·패키징 담당
