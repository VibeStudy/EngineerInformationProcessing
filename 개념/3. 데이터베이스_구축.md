## 정규화 (Normalization)

데이터 중복 제거, 삽입·삭제·갱신 이상(Anomaly) 방지를 위해 릴레이션을 분해하는 과정.

### 이상(Anomaly) 종류

| 이상 | 설명 |
|------|------|
| 삽입 이상 | 불필요한 데이터 함께 삽입해야 함 |
| 삭제 이상 | 원하지 않는 데이터까지 삭제됨 |
| 갱신 이상 | 중복 데이터 일부만 수정 시 불일치 발생 |

---

### 정규화 단계

#### 제1정규형 (1NF)
- 모든 속성 값이 **원자값(Atomic Value)**
- 반복 그룹, 다중값 속성 제거

#### 제2정규형 (2NF)
- 1NF 만족
- **완전 함수적 종속** — 기본키 전체에 종속 (부분 함수 종속 제거)
- 기본키가 복합키일 때 일부 컬럼에만 종속되는 속성 분리

#### 제3정규형 (3NF)
- 2NF 만족
- **이행적 함수 종속 제거** — A→B, B→C 이면 A→C 성립하는 것 제거
- 기본키가 아닌 속성 간 종속 제거

#### BCNF (Boyce-Codd Normal Form)
- 3NF 만족
- 모든 결정자가 **후보키** 여야 함
- 3NF보다 강한 조건 — 후보키가 여러 개이고 겹칠 때 적용

#### 제4정규형 (4NF)
- BCNF 만족
- **다치 종속(MVD, Multi-Valued Dependency)** 제거

#### 제5정규형 (5NF)
- 4NF 만족
- **조인 종속(Join Dependency)** 제거
- 무손실 분해 보장

---

### 정규화 단계별 예제 (동일 샘플 사용)

> **시나리오**: 수강신청 시스템  
> 학생이 과목을 수강하고, 교수가 과목을 담당하며, 강의실이 배정됨

---

#### 비정규형 (UNF) — 시작 데이터

| 학번 | 학생명 | 수강정보 (과목코드, 과목명, 담당교수, 강의실, 성적) |
|------|--------|------------------------------------------------------|
| 1001 | 김철수 | (CS101, C언어, 박교수, 101호, A), (CS102, 자바, 이교수, 102호, B) |
| 1002 | 이영희 | (CS101, C언어, 박교수, 101호, B), (CS103, DB, 김교수, 103호, A) |

문제: 수강정보가 다중값 → 원자값 아님

---

#### 1NF — 원자값 분리

| **학번** | **과목코드** | 학생명 | 과목명 | 담당교수 | 강의실 | 성적 |
|----------|-------------|--------|--------|----------|--------|------|
| 1001 | CS101 | 김철수 | C언어 | 박교수 | 101호 | A |
| 1001 | CS102 | 김철수 | 자바 | 이교수 | 102호 | B |
| 1002 | CS101 | 이영희 | C언어 | 박교수 | 101호 | B |
| 1002 | CS103 | 이영희 | DB | 김교수 | 103호 | A |

기본키: **(학번, 과목코드)**

문제점 (부분 함수 종속):
- `학번` → `학생명` (기본키 일부만으로 결정)
- `과목코드` → `과목명, 담당교수, 강의실` (기본키 일부만으로 결정)
- `(학번, 과목코드)` → `성적` (완전 종속 — OK)

---

#### 2NF — 부분 함수 종속 제거

**학생** 테이블

| **학번** | 학생명 |
|----------|--------|
| 1001 | 김철수 |
| 1002 | 이영희 |

**과목** 테이블

| **과목코드** | 과목명 | 담당교수 | 강의실 |
|-------------|--------|----------|--------|
| CS101 | C언어 | 박교수 | 101호 |
| CS102 | 자바 | 이교수 | 102호 |
| CS103 | DB | 김교수 | 103호 |

**수강** 테이블

| **학번** | **과목코드** | 성적 |
|----------|-------------|------|
| 1001 | CS101 | A |
| 1001 | CS102 | B |
| 1002 | CS101 | B |
| 1002 | CS103 | A |

문제점 (이행적 함수 종속 — 과목 테이블 내):
- `과목코드` → `담당교수` → `강의실`
- 박교수가 강의실 변경 시 CS101 행만 수정 → 갱신 이상

---

#### 3NF — 이행적 함수 종속 제거

**과목** 테이블 (분리)

| **과목코드** | 과목명 | 담당교수 |
|-------------|--------|----------|
| CS101 | C언어 | 박교수 |
| CS102 | 자바 | 이교수 |
| CS103 | DB | 김교수 |

**교수** 테이블 (신규)

| **담당교수** | 강의실 |
|-------------|--------|
| 박교수 | 101호 |
| 이교수 | 102호 |
| 김교수 | 103호 |

학생/수강 테이블은 그대로 유지.

---

#### BCNF — 결정자가 후보키 아닌 경우 제거

> **조건 변경**: 한 과목을 여러 교수가 담당 가능, 한 교수는 한 과목만 담당

**수강배정** 테이블 (3NF 상태)

| **학번** | **과목코드** | 담당교수 |
|----------|-------------|----------|
| 1001 | CS101 | 박교수 |
| 1001 | CS102 | 이교수 |
| 1002 | CS101 | 최교수 | ← CS101을 박교수·최교수 둘 다 담당
| 1002 | CS103 | 김교수 |

후보키: `(학번, 과목코드)`, `(학번, 담당교수)`  
함수 종속: `담당교수` → `과목코드` (담당교수는 후보키 아님 → **BCNF 위반**)

분리:

**교수담당** 테이블

| **담당교수** | 과목코드 |
|-------------|----------|
| 박교수 | CS101 |
| 이교수 | CS102 |
| 최교수 | CS101 |
| 김교수 | CS103 |

**학생수강** 테이블

| **학번** | **담당교수** |
|----------|-------------|
| 1001 | 박교수 |
| 1001 | 이교수 |
| 1002 | 최교수 |
| 1002 | 김교수 |

---

#### 4NF — 다치 종속(MVD) 제거

> **조건 추가**: 학생이 관심 언어와 취미를 각각 여러 개 등록

**학생_정보** 테이블 (BCNF 상태 — 다치 종속 존재)

| **학번** | **관심언어** | **취미** |
|----------|-------------|---------|
| 1001 | Python | 독서 |
| 1001 | Python | 게임 |
| 1001 | Java | 독서 |
| 1001 | Java | 게임 |

`학번 →→ 관심언어`, `학번 →→ 취미` — 독립적 다치 종속 → 조합 폭발

분리:

**학생_관심언어** 테이블

| **학번** | **관심언어** |
|----------|-------------|
| 1001 | Python |
| 1001 | Java |

**학생_취미** 테이블

| **학번** | **취미** |
|----------|---------|
| 1001 | 독서 |
| 1001 | 게임 |

---

#### 5NF — 조인 종속 제거

> **조건 추가**: 교수가 과목을 담당하고 해당 과목에 교재를 사용

**과목_교수_교재** 테이블 (4NF 상태 — 조인 종속 존재)

| **과목코드** | **담당교수** | **교재** |
|-------------|-------------|---------|
| CS101 | 박교수 | C기초 |
| CS101 | 최교수 | C기초 |
| CS101 | 박교수 | C심화 |
| CS102 | 이교수 | 자바완성 |

세 이진 관계로 무손실 분해:

**과목_교수** 테이블

| 과목코드 | 담당교수 |
|----------|----------|
| CS101 | 박교수 |
| CS101 | 최교수 |
| CS102 | 이교수 |

**과목_교재** 테이블

| 과목코드 | 교재 |
|----------|------|
| CS101 | C기초 |
| CS101 | C심화 |
| CS102 | 자바완성 |

**교수_교재** 테이블

| 담당교수 | 교재 |
|----------|------|
| 박교수 | C기초 |
| 박교수 | C심화 |
| 최교수 | C기초 |
| 이교수 | 자바완성 |

세 테이블 자연조인 시 원본과 동일하게 복원됨 → 무손실 분해 완료

### 정규화 단계 요약 암기표

| 단계 | 핵심 제거 대상 |
|------|---------------|
| 1NF | 원자값 아닌 속성 |
| 2NF | 부분 함수 종속 |
| 3NF | 이행적 함수 종속 |
| BCNF | 결정자가 후보키 아닌 함수 종속 |
| 4NF | 다치 종속 |
| 5NF | 조인 종속 |

---

### 함수적 종속(Functional Dependency)

- **완전 함수 종속**: X→Y에서 X 전체가 Y를 결정
- **부분 함수 종속**: X의 일부만으로도 Y를 결정 (복합키에서 발생)
- **이행적 함수 종속**: X→Y, Y→Z → X→Z (비키 속성이 다른 비키 속성 결정)

---

### 역정규화 (De-normalization)

- 성능 향상 목적으로 정규화된 릴레이션을 의도적으로 합침
- 조인 횟수 감소 → 조회 속도 향상
- 단점: 데이터 중복 증가, 이상 발생 가능성
