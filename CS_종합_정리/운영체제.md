## 운용기법 

* Batch Processing System 
  * 여러 작업 한번에 처리 
  * 작업 처리 시 결과 나올 때까지 대기 
  * 작업 중 다른 시스템 이용 불가 

* Multi processing system 
  * 여러 cpu에서 작업을 병렬적으로 진행 

* Multi Programming System 
  * 작업 단위로 cpu 스케줄링 진행 

* Real time processing system 
  * 작업에 대한 시간적 제약을 갖는 운용 방식 
  * hard real time: 제한시간 내 반드시 작업 완료 
  * soft real time: 작업이 완료되지 않아도됨

* Time sharing System 
  * 개선된 Multi programming System
  * 퀀텀 기간 동안 작업 실행

## 프로세스와 스레드 (6)

### 프로세스

* 프로세스(Process)
  * 실행 중인 프로그램으로, 실행 상태와 운영체제가 할당한 자원을 함께 관리하는 단위

  * 프로그램은 저장된 명령어와 데이터이며, 같은 프로그램을 여러 번 실행하면 서로 다른 프로세스가 될 수 있음

* 주소 공간과 자원
  * 각 프로세스는 일반적으로 독립된 가상 주소 공간을 가짐

  * 서로 같은 가상 주소를 사용하더라도 다른 물리 메모리를 가리킬 수 있음

  * 프로세스 간 데이터 교환에는 공유 메모리·파이프·메시지 큐 등 프로세스 간 통신(Inter-Process Communication, IPC)을 사용

### 프로세스 메모리 구성 (4)

* 코드 영역(Code, Text)
  * 실행할 기계어 명령어를 저장

* 데이터 영역(Data)
  * 전역 변수와 정적 변수를 저장

  * 초기화된 데이터와 초기값이 없거나 0으로 초기화되는 데이터의 영역을 구분하기도 함

* 힙 영역(Heap)
  * 실행 중 동적으로 할당하는 메모리 영역

  * 같은 프로세스의 스레드들이 공유하므로 동시 접근 시 동기화가 필요할 수 있음

* 스택 영역(Stack)
  * 함수 호출에 필요한 매개변수·복귀 정보·지역 변수 등을 저장하는 영역

  * 각 스레드는 자신의 호출 흐름을 관리할 스택을 가짐

> 위 구분은 일반적인 학습 모형이며, 실제 배치와 저장 방식은 운영체제·언어·컴파일러에 따라 달라질 수 있음

### 프로세스 제어 블록과 문맥 교환

* 프로세스 제어 블록(Process Control Block, PCB)
  * 운영체제가 프로세스를 관리하기 위해 유지하는 자료구조

  * 프로세스 식별자, 상태, 스케줄링 정보, 메모리 관리 정보, 입출력·자원 정보 등을 관리

  * 실행 재개에 필요한 문맥은 프로세스·스레드 관리 구조에 보관하며 구체적인 분리는 운영체제에 따라 다름

* 문맥 교환(Context Switch)
  * 현재 실행 흐름의 레지스터와 프로그램 카운터 등 문맥을 저장하고 다른 실행 흐름의 문맥을 복원하는 작업

  * 프로세스 사이뿐 아니라 같은 프로세스의 스레드 사이에서도 발생

  * 프로세스 간 전환은 주소 공간 전환이 추가될 수 있어 일반적으로 같은 프로세스 내 스레드 전환보다 부담이 큼

  * 사용자 모드와 커널 모드 사이의 전환만으로 반드시 다른 프로세스나 스레드로 문맥 교환되는 것은 아님

### 스레드와 공유 자원

* 스레드(Thread)
  * 프로세스 내부에서 독립적인 명령어 실행 흐름을 이루는 단위

  * 하나의 프로세스에는 하나 이상의 스레드가 존재할 수 있음

* 같은 프로세스의 스레드가 공유하는 것
  * 코드 영역, 전역·정적 변수가 있는 데이터 영역, 힙 영역

  * 프로세스의 주소 공간과 열린 파일 등 프로세스에 속한 자원

* 스레드마다 별도로 관리하는 것
  * 프로그램 카운터(Program Counter, PC)와 CPU 레지스터 문맥

  * 스택, 스레드 식별자, 스레드별 실행 상태

* 스택의 독립성과 메모리 보호
  * 스레드별 스택은 호출 흐름을 구분하기 위한 것이며 별도의 보호된 주소 공간을 뜻하지 않음

  * 같은 주소 공간이므로 유효한 주소를 공유하면 다른 스레드의 스택 데이터에도 접근할 수 있음

### 멀티프로세스와 멀티스레드 비교

* 멀티프로세스(Multiprocessing)
  * 여러 프로세스로 작업을 나누며, 일반적으로 주소 공간이 분리되어 장애를 격리하기 유리

  * 프로세스 간 통신과 자원 관리에 추가 비용이 발생할 수 있음

* 멀티스레드(Multithreading)
  * 한 프로세스 안의 여러 스레드로 작업을 나누며, 공유 메모리를 통해 데이터를 교환하기 쉬움

  * 공유 데이터의 경쟁 상태를 막기 위해 뮤텍스 등 동기화 수단이 필요할 수 있음

  * 한 스레드의 잘못된 메모리 접근 등으로 프로세스가 종료되면 같은 프로세스의 다른 스레드도 영향을 받음

* 동시성과 병렬성
  * 동시성(Concurrency): 여러 작업이 겹치는 기간에 진행되는 성질로, 하나의 CPU 코어에서도 번갈아 실행하여 구현 가능

  * 병렬성(Parallelism): 여러 작업을 여러 코어 등에서 실제로 동시에 실행하는 성질

  * 스레드를 늘린다고 항상 빨라지는 것은 아니며, 동기화·문맥 교환 비용과 실행 환경의 제약을 고려

### 사용자 수준 스레드와 커널 수준 스레드

* 사용자 수준 스레드(User-Level Thread)
  * 사용자 공간의 라이브러리나 실행 환경이 관리하는 스레드

  * 여러 사용자 스레드를 하나의 커널 스레드에 연결하는 다대일 모형에서는 한 스레드의 블로킹 시스템 호출이 전체 실행을 막을 수 있음

  * 다대일 모형은 여러 CPU 코어에 사용자 스레드를 동시에 배정할 수 없음

* 커널 수준 스레드(Kernel-Level Thread)
  * 운영체제 커널이 인식하고 스케줄링하는 스레드

  * 같은 프로세스의 다른 커널 스레드는 한 스레드의 대기 중에도 실행 가능

  * 사용 가능한 코어와 스케줄링 조건에 따라 여러 스레드의 병렬 실행 가능

* 매핑 모형
  * 다대일: 여러 사용자 스레드 → 하나의 커널 스레드

  * 일대일: 사용자 스레드 하나 → 커널 스레드 하나

  * 다대다: 여러 사용자 스레드 → 여러 커널 스레드

* 암기 핵심
  * 프로세스: 자원·주소 공간 관리의 기본 단위

  * 스레드: 프로세스 내부의 실행 흐름

  * 공유: 코드·데이터·힙·열린 파일

  * 개별: PC·레지스터 문맥·스택

## 스케줄링 (3)

### 프로세스 상태 (5)

* 생성(New)
  * 프로세스가 생성되어 운영체제가 프로세스 제어 블록(Process Control Block)을 만들고 자원을 할당하는 상태

* 준비(Ready)
  * 실행에 필요한 자원은 준비되었으나 CPU 할당을 기다리는 상태

* 실행(Running)
  * CPU를 할당받아 명령어를 실행하는 상태

* 대기(Waiting, Blocked)
  * 입출력 완료나 이벤트 발생을 기다려 CPU를 사용할 수 없는 상태

* 종료(Terminated)
  * 실행을 완료하거나 강제 종료되어 운영체제가 자원을 회수하는 상태

* 상태 전이

```
생성 → 준비 → 실행 → 종료
          ↑    ↓
     입출력 완료  입출력 요청
          └── 대기 ──┘
```

* 전이 원인
  * 준비 → 실행: 디스패처가 CPU 할당

  * 실행 → 준비: 시간 할당량 만료 또는 높은 우선순위 프로세스에 의해 선점

  * 실행 → 대기: 입출력 요청 또는 이벤트 대기

  * 대기 → 준비: 입출력 완료 또는 기다리던 이벤트 발생

### 비선점형 알고리즘

> 실행 중인 프로세스를 강제로 빼앗지 않음. 문맥 교환 오버헤드 적음.

#### FCFS (First Come First Served)

* 도착 순서대로 처리

* 장점: 구현 단순, 공평

* 단점: **convoy effect** — 긴 프로세스가 짧은 프로세스를 오래 대기시킴

#### SJF (Shortest Job First)

* 버스트 시간 가장 짧은 프로세스 먼저

* **평균 대기 시간 최소** (최적 알고리즘)

* 단점: 기아(Starvation) 발생 — 긴 프로세스 무한 대기 가능

#### HRN (Highest Response Ratio Next)

* SJF의 기아 문제 보완

* 우선순위 계산식: **(대기 시간 + 버스트 시간) / 버스트 시간**

* 값 클수록 먼저 실행 → 오래 기다린 프로세스 우선순위 상승

#### 우선순위 (Priority)

* 우선순위 값이 높은 프로세스 먼저

* 단점: 기아 발생 → **에이징(Aging)** 으로 해결 (대기 시간 길수록 우선순위 증가)

### 선점형 알고리즘

> 실행 중인 프로세스를 강제로 중단시키고 다른 프로세스에 CPU 할당 가능.

#### RR (Round Robin)

* 각 프로세스에 **시간 할당량(Time Quantum)** 부여, 순환 처리

* 시간 할당량 초과 시 준비 큐 맨 뒤로 이동

* 시간 할당량 크면 → FCFS에 수렴, 작으면 → 문맥 교환 오버헤드 증가

* 시분할 시스템에 적합

#### SRT (Shortest Remaining Time)

* SJF의 선점형 버전

* 새 프로세스 도착 시 잔여 버스트 시간 비교 → 더 짧으면 선점

* 기아 발생 가능

#### 다단계 큐 (Multilevel Queue)

* 프로세스를 여러 큐로 분류, 각 큐마다 다른 스케줄링 알고리즘 적용

* 큐 간 이동 불가

## 기억장치 관리

### 가상기억장치

* 가상기억장치
  * 보조기억장치의 일부를 주기억장치처럼 사용할 수 있게 하는 기억장치 관리 기법
  * 실제 주기억장치보다 큰 프로그램을 실행할 수 있음
  * 프로그램 전체를 한 번에 적재하지 않고 필요한 부분만 주기억장치에 적재

* 페이징(Paging)
  * 가상 기억 공간을 일정한 크기의 페이지(Page)로, 주기억장치를 같은 크기의 프레임(Frame)으로 나누어 관리
  * 페이지 단위로 주기억장치와 보조기억장치 사이에서 적재·교체

* 장점
  * 주기억장치 용량보다 큰 프로그램 실행 가능
  * 다중 프로그래밍 정도 향상
  * 주기억장치 이용률 향상

* 단점
  * 주소 변환 오버헤드 발생
  * 페이지 부재(Page Fault)가 많으면 성능 저하
  * 스래싱(Thrashing) 발생 가능

### 지역성

* 지역성(Locality)
  * 프로세스가 실행 중 특정 시간 동안 일부 주소 영역을 집중적으로 참조하는 성질
  * 가상기억장치, 캐시 메모리, 페이지 교체 알고리즘의 이론적 근거

* 시간 지역성(Temporal Locality)
  * 최근 참조한 데이터나 명령어를 가까운 미래에 다시 참조할 가능성이 높은 성질
  * 반복문, 스택, 카운터 변수, 부프로그램

* 공간 지역성(Spatial Locality)
  * 참조한 주소와 인접한 주소를 가까운 미래에 참조할 가능성이 높은 성질
  * 배열 순회, 명령어 순차 실행

* 순차 지역성(Sequential Locality)
  * 명령어가 저장된 순서대로 순차적으로 실행되는 성질
  * 공간 지역성의 특수한 형태로 볼 수 있음

* 지역성 활용
  * 자주 참조될 가능성이 높은 데이터나 페이지를 주기억장치나 캐시에 유지
  * 페이지 부재 감소와 메모리 접근 속도 향상에 도움

### 워킹셋

* 워킹셋(Working Set)
  * 프로세스가 일정 시간 동안 참조한 페이지들의 집합
  * 지역성을 만족하는 현재 실행 구간의 페이지 집합을 의미

* 워킹셋 윈도우(Working Set Window)
  * 워킹셋을 측정하는 시간 또는 참조 횟수 범위
  * 윈도우가 너무 작으면 필요한 페이지를 빠뜨리고, 너무 크면 불필요한 페이지까지 포함

* 활용
  * 각 프로세스의 워킹셋만큼 프레임을 할당해 페이지 부재와 스래싱을 줄임

### 페이지 부재

* 페이지 부재(Page Fault)
  * 실행에 필요한 페이지가 주기억장치에 없어 보조기억장치에서 가져와야 하는 상태
  * 페이지 부재 처리 동안 프로세스는 입출력 완료까지 대기

* 처리 과정
  * 페이지 부재 발생 → 빈 프레임 확인 또는 페이지 교체 대상 선정 → 보조기억장치에서 페이지 적재 → 페이지 테이블 갱신 → 명령 재실행

* 페이지 부재율(Page Fault Rate)
  * 전체 페이지 참조 횟수 중 페이지 부재가 발생한 비율
  * 페이지 부재율 증가 → 디스크 입출력 증가 → 시스템 성능 저하

### 프리페이징

* 프리페이징(Prepaging)
  * 앞으로 참조할 가능성이 높은 페이지를 실제 요청 전에 미리 주기억장치에 적재하는 기법
  * 지역성을 이용해 페이지 부재율과 초기 실행 지연을 줄임

* 주의점
  * 예측이 틀리면 사용하지 않을 페이지를 적재해 입출력과 메모리를 낭비

### 스래싱

* 스래싱(Thrashing)
  * 페이지 부재가 지나치게 자주 발생해 CPU보다 페이지 교체를 위한 입출력에 대부분의 시간을 쓰는 현상

* 발생 원인
  * 프로세스에 할당된 프레임 수가 워킹셋보다 적음
  * 다중 프로그래밍 정도가 너무 높아 프로세스당 메모리 할당량이 부족

* 해결 방법
  * 워킹셋 기준으로 충분한 프레임 할당
  * 페이지 부재 빈도(Page Fault Frequency)를 기준으로 다중 프로그래밍 정도 조절
  * 다중 프로그래밍 정도 감소 또는 주기억장치 증설

## 미들웨어

### 개념

* 분산 컴퓨팅 환경에서 서로 다른 기종 간의 하드웨어나 프로토콜, 통신 환경 등을 연결하여 운영체제와 응용 프로그램, 또는 서버와 클라이언트 사이에서 원만한 통신이 이루어지도록 다양한 서비스를 제공

* 표준화된 인터페이스를 제공해 시스템 간의 데이터 교환의 일관성 보장 

* 위치 투명성 제공. 시스템의 위치를 몰라도 논리적인 명칭만으로 액세스 가능. 

* 사용자는 미들웨어 내부 동작을 확인하려면 별도의 응용 소프트웨어 필요 

* 1:1, 1:N, N:M 등 형태로 연결 가능 

### 미들웨어 종류

* DB Middleware; Database Middleware
  * 응용 프로그램과 데이터베이스 사이에서 데이터 접근을 중개
  * 데이터베이스 연결 관리, 질의 처리, 트랜잭션 처리 지원

* MOM; Message Oriented Middleware
  * 메시지 큐를 이용해 응용 프로그램 사이의 비동기 통신 지원
  * 송신자와 수신자가 동시에 동작하지 않아도 메시지 전달 가능

* ORB; Object Request Broker
  * 분산 객체 사이의 요청과 응답을 중개
  * 객체 위치, 구현 언어, 실행 환경 차이를 감춤

* RPC; Remote Procedure Call
  * 원격 시스템의 프로시저를 로컬 프로시저처럼 호출하게 하는 미들웨어
  * 네트워크 통신 과정을 감추고 분산 프로그램 개발 지원

* TP Monitor; Transaction Processing Monitor
  * 다수 사용자의 트랜잭션을 효율적으로 처리하고 관리
  * 부하 분산, 자원 관리, 트랜잭션 무결성 보장 지원

* WAS; Web Application Server
  * 웹 서버와 데이터베이스 사이에서 동적 웹 애플리케이션 실행 지원
  * 세션 관리, 트랜잭션 처리, 비즈니스 로직 수행 지원

## 파일 시스템 (3)

### 순차 파일(Sequential File)

* 레코드를 논리적 순서에 따라 물리적으로 연속 저장

* 순차 접근 저장 장치(SASD; Sequential Access Storage Device) 사용
  * 저장된 순서대로 탐색해 데이터 접근
  * 예: 자기 테이프

* 장점: 구조 단순, 저장 매체 효율 높음, 순차 처리 속도 빠름

* 단점: 특정 레코드 검색 시 처음부터 순서대로 탐색, 삽입·삭제 비효율 

* 레코드들이 순차적으로 처리되어 일괄 처리에 적합

### 직접 파일(Direct File)

* 해시 함수로 레코드 주소 계산하여 직접 접근

* 직접 접근 저장 장치(DASD; Direct Access Storage Device) 사용
  * 데이터 위치를 지정해 원하는 레코드에 직접 접근
  * 예: 하드 디스크(HDD), SSD, 자기 디스크

* 임의 접근(Random Access) 가능, 검색 속도 빠름

* 충돌(Collision) 발생 시 오버플로 처리 필요

### 색인 순차 파일(Indexed Sequential File)

* 순차 파일 + 색인(Index) 구조 결합

* 구성: 기본 구역(Prime Area) + 색인 구역(Index Area) + 오버플로 구역(Overflow Area)

* 순차 처리와 직접 처리 모두 가능

* ISAM(Indexed Sequential Access Method) 대표적

## 운영체제 명령어 및 로그 (3)

* `COPY`: 파일 복사

* `DEL`: 파일 삭제

* `TYPE`: 텍스트 파일 내용 출력

* `REN`: 파일 이름 변경

* `MD`: 디렉터리 생성

* `CD`: 현재 디렉터리 변경

* `CLS`: 화면 지우기

* `ATTRIB`: 파일 속성 표시 또는 변경

* `FIND`: 파일에서 문자열 검색

* `CHKDSK`: 디스크 상태 검사

* `FORMAT`: 디스크 초기화

* `MOVE`: 파일 이동 또는 이름 변경

### UNIX/Linux 명령어

* `cat`: 파일 내용 출력

* `cd`: 현재 디렉터리 변경

* `chmod`: 파일이나 디렉터리의 접근 권한 변경

* `chown`: 파일이나 디렉터리의 소유자 변경

* `cp`: 파일 복사

* `rm`: 파일 삭제

* `find`: 파일이나 디렉터리 검색

* `fsck`: 파일 시스템 검사 및 복구

* `kill`: 프로세스에 시그널 전송

* `fork`: 새로운 프로세스 생성

* `killall`: 프로세스 이름으로 프로세스 종료

* `ls`: 현재 디렉터리의 파일과 하위 디렉터리 목록 출력

* `mkdir`: 디렉터리 생성

* `rmdir`: 빈 디렉터리 삭제

* `uname`: 시스템 정보 출력

* `mv`: 파일 이동 또는 이름 변경

* `ps`: 현재 실행 중인 프로세스 상태 출력

* `pwd`: 현재 작업 디렉터리 경로 출력

* `top`: 프로세스와 시스템 자원 사용 현황 실시간 출력

* `who`: 현재 로그인한 사용자 정보 출력

### 리눅스 주요 로그 및 관련 파일 (14)

* `/dev/console`
  * 시스템 콘솔과 입출력을 연결하는 문자 장치 파일
  * 부팅 메시지와 커널 오류가 표시될 수 있으나, 로그를 저장하는 파일은 아님

* `/var/log/messages`
  * 시스템 전반의 일반 메시지와 오류 기록
  * RHEL(Red Hat Enterprise Linux), CentOS 계열에서 주로 사용

* `/var/log/syslog`
  * 시스템 전반의 일반 메시지와 오류 기록
  * Debian, Ubuntu 계열에서 `/var/log/messages` 대신 주로 사용

* `/var/log/secure`
  * 로그인, 인증, 권한 상승(`sudo`) 등 보안 관련 기록
  * RHEL, CentOS 계열에서 주로 사용

* `/var/log/auth.log`
  * 로그인, 인증, 권한 상승(`sudo`) 등 보안 관련 기록
  * Debian, Ubuntu 계열에서 `/var/log/secure` 대신 주로 사용

* `/var/log/boot.log`
  * 부팅 과정에서 시작한 서비스와 오류 기록

* `/var/log/dmesg`
  * 커널이 부팅 중 출력한 메시지 기록
  * 하드웨어 인식, 장치 드라이버, 커널 오류 확인에 사용

* `/var/log/cron`
  * `cron` 작업의 실행 기록
  * RHEL, CentOS 계열에서 주로 사용하며 Debian, Ubuntu 계열은 `/var/log/syslog`에 기록될 수 있음

* `/var/log/wtmp`
  * 사용자 로그인·로그아웃과 시스템 부팅·종료 이력 기록
  * `last` 명령어로 확인

* `/var/log/btmp`
  * 로그인 실패 이력 기록
  * `lastb` 명령어로 확인

* `/var/run/utmp`
  * 현재 로그인한 사용자와 터미널 세션 정보 기록
  * `who`, `w` 명령어로 확인

* `/var/log/lastlog`
  * 사용자별 마지막 로그인 시간과 터미널 정보 기록
  * `lastlog` 명령어로 확인

* `/var/log/maillog`
  * 메일 서버의 송수신, 오류 등 관련 기록
  * RHEL, CentOS 계열에서 주로 사용

* `/var/log/xferlog`
  * FTP(File Transfer Protocol) 서버의 파일 전송 기록
  * FTP 서버 설정 시 생성되며, 기본 로그 파일이 아닐 수 있음
