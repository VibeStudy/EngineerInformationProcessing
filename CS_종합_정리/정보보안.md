## 공격 방법 (4)

### DoS

* DDoS
    * 여러 대의 좀비 PC나 봇넷을 이용해 동시에 대량 트래픽을 보내는 분산 서비스 거부 공격

    * 대응: 트래픽 분산

* Land
    * 출발지 IP와 목적지 IP를 모두 피해자 IP로 설정해 패킷을 보내는 공격

    * 피해 시스템이 자기 자신에게 응답하면서 자원 소모 또는 장애 발생

    * 대응: 출발지와 목적지가 같은 패킷 차단

* Ping of Death
    * 허용 크기보다 큰 ICMP 패킷을 전송해 시스템 오류를 유발하는 공격

    * 패킷 재조립 과정에서 버퍼 오버플로가 발생할 수 있음

    * 대응: 비정상 ICMP 패킷 차단

* SYN Flooding
    * TCP 3-Way Handshake 과정에서 SYN 패킷을 대량 전송하는 공격

    * 서버가 SYN-ACK 응답 후 ACK를 기다리며 연결 자원을 소모

    * 대응: 연결 대기 시간 단축, 비정상 SYN 패킷 필터링

* Smurfing
    * 공격자가 출발지 IP를 피해자 IP로 위조해 브로드캐스트 주소로 ICMP 요청을 전송하는 공격

    * 네트워크의 여러 호스트가 피해자에게 ICMP 응답을 보내 트래픽 폭주 발생

    * 대응: 브로드캐스트 ICMP 차단, 출발지 IP 위조 방지

* TearDrop
    * IP 패킷 조각의 오프셋 값을 비정상적으로 조작해 전송하는 공격

    * 수신 시스템이 패킷을 재조립하는 과정에서 오류 또는 장애 발생

    * 대응: 비정상 조각 패킷 폐기

### 네트워크 침해 공격 

* APT(Advanced Persistent Threat)
    * 악성코드가 포함된 이메일 지속적 발송 

    * 악성코드에 감염된 P2P 사이트 접속 유도 

* Brute Force Attack
    * 가능한 값을 모두 대입해 비밀번호나 암호키를 알아내는 공격

* Evil Twin Attack
    * 정상 무선 AP와 비슷한 이름의 가짜 AP를 만들어 사용자를 접속시키는 유도

    * 사용자의 계정 정보, 세션 정보, 통신 내용을 탈취 가능

* Phishing
    * 정상 기관이나 서비스를 사칭해 개인정보나 금융 정보를 탈취하는 공격

* Ping Flood
    * 사이트에 많은 ICMP 메시지 송신

    * 응답으로 인해 시스템 자원 모두 사용

* Qshing
    * QR 코드와 피싱을 결합한 공격

* Smishing
    * 문자 메시지(SMS)와 피싱을 결합한 공격

    * 앱 설치 유도 후 정보 탈취 

* Spear Phishing
    * 사회 공학 기법. 
    * 대상에게 일반적인 메일 보내 본문 링크 / 첨부 파일 클릭 유도

* Switch Jamming
    * 스위치의 MAC 주소 테이블을 가짜 MAC 주소로 가득 채우는 공격

* 세션 하이재킹(Session Hijacking)
  * 정상 사용자의 세션 ID 또는 TCP 시퀀스 번호를 탈취하여, 사용자로 위장해 서버에 접속하는 공격

  * 탐지: 시퀀스 번호 불일치, ACK Storm, 패킷 유실·재전송 증가 등을 확인

### 네트워크 도청·위조 및 중간자 공격 (5)

* 스니핑(Sniffing)
  * 네트워크를 흐르는 패킷을 가로채어 내용을 엿보는 공격

  * 무차별 모드(Promiscuous Mode) 등의 방식으로 같은 네트워크 구간의 패킷을 수집

  * 평문 계정 정보, 개인정보, 세션 쿠키가 노출될 수 있음

  * 대응: HTTPS·SSH·VPN 등 통신 암호화, 스위치 사용, 비정상 무차별 모드 탐지

* IP 스푸핑(IP Spoofing)
  * 패킷의 출발지 IP 주소를 신뢰할 수 있는 호스트의 주소로 위조하는 공격

  * IP 주소 기반 접근 제어 또는 신뢰 관계를 우회하려고 위조 패킷을 전송

  * 접근 통제 우회, 반사·증폭 DDoS의 출발지 은닉에 악용될 수 있음

  * 대응: 수신·송신 패킷의 출발지 주소 검증(Ingress/Egress Filtering), IP만으로 인증하지 않음

* ARP 스푸핑(ARP Spoofing)
  * 공격자가 위조한 ARP 응답을 보내 IP 주소와 MAC 주소의 연결 정보를 변조하는 공격

  * 피해자의 패킷이 공격자의 MAC 주소로 전달되도록 ARP 캐시를 오염시킴

  * 내부망 통신 도청·변조, 세션 탈취, 서비스 장애가 발생할 수 있음

  * 대응: 정적 ARP 설정, ARP 검사 기능, 스위치 포트 보안, 중요 통신 암호화

* DNS 스푸핑(DNS Spoofing)
  * 도메인 이름에 대한 DNS 응답을 위조하여 사용자를 가짜 IP 주소로 연결하는 공격

  * DNS 캐시 오염 또는 위조 응답을 이용해 정상 도메인의 이름 해석 결과를 바꿈

  * 피싱 사이트 유도, 계정·금융 정보 탈취, 악성코드 유포가 발생할 수 있음

  * 대응: DNSSEC 적용, 신뢰할 수 있는 DNS 서버 사용, HTTPS 인증서 경고 확인

* MITM(Man-In-The-Middle)
  * 통신하는 두 당사자 사이에 공격자가 끼어들어 메시지를 도청하거나 변조하는 공격

  * ARP 스푸핑, 가짜 Wi-Fi AP, DNS 스푸핑 등으로 통신 경로를 공격자에게 우회시킴

  * 계정 정보·거래 정보 탈취, 전송 데이터 변조, 세션 탈취가 발생할 수 있음

  * 대응: TLS 인증서 검증, HTTPS·VPN 사용, 공용 Wi-Fi에서 중요 거래 자제, ARP·DNS 위조 방지

### 악성코드 및 시스템 침해 공격

* Back Door 
  * 편의를 위해 시스템 보안을 제거해놓은 접근 방법 
  * 방지: 무결성 검사, 열린 포트 확인, 로그 분석

* Botnet 
  * 감염된 컴퓨터들이 네트워크로 연결된 형태  

* C&C 
  * 좀비 PC에 명령을 내리고 악성코드를 제어하기 위한 서버

* Keylogger Attack
  * 컴퓨터 사용자의 키보드 움직임을 탐지해 개인정보를 탈취하는 공격

* Pharming
  * 가짜 사이트로 접속을 유도해 개인정보를 탈취하는 공격

* Ransomware 
  * 문서/파일을 암호해 사용자가 열지 못하게 하는 공격 
  * 해독 조건으로 금전 요구 

* Trojan Horse 
  * 정상 프로그램으로 위장 후 활성화 될 때 부작용을 일으키는 공격 

* Worm
  * 네트워크에서 자신을 복제해 시스템 부하를 높이는 공격

* Zero-Day Attack
  * 보안 취약점이 발견되었을 때 즉시 공격 

* Zombie PC
  * 악성코드에 감염된 컴퓨터. C&C, DDoS 등에 이용

## 세션 보안 (3)

### 세션 통제 개요

* 세션(Session)
  * 서버와 클라이언트 간 연결을 의미하며, 연결이 유지되는 동안 사용자별 상태와 정보를 관리하는 방식

  * 서버는 세션 ID를 기준으로 사용자 인증 상태, 권한, 작업 정보를 구분하여 관리

* 세션 통제(Session Control)
  * 세션의 연결·해제와 그 과정에서 발생하는 정보를 관리하는 활동

  * 소프트웨어 개발 과정의 요구사항 분석 및 설계 단계에서 점검해야 하는 보안 항목

* 불충분한 세션 관리
  * 일정한 규칙이 있는 세션 ID를 발급하거나 세션 타임아웃을 과도하게 길게 설정할 때 발생하는 취약점

  * 공격자가 세션 하이재킹으로 획득한 세션 ID를 사용해 비인가 기능을 이용하거나 중요 정보에 접근할 수 있음

### 세션 설계 시 고려 사항

* 로그아웃
  * 시스템의 모든 페이지에서 로그아웃할 수 있도록 사용자 인터페이스를 구성

  * 로그아웃 요청 시 해당 세션을 완전히 제거

* 세션 만료
  * 중요도가 높은 서비스는 2~5분, 낮은 서비스는 15~30분을 기준으로 세션 타임아웃을 설정

  * 기존 세션이 종료되지 않은 상태에서는 새 세션이 생성되지 않도록 설계

* 중복 로그인
  * 중복 로그인을 허용하지 않는 경우, 클라이언트의 중복 접속에 대한 세션 관리 정책을 수립

* 비밀번호 변경
  * 비밀번호 변경 시 활성화된 세션을 삭제하고 새 세션을 할당

### 세션 ID 관리

* 안전한 생성
  * 안전한 서버에서 최소 128비트 길이로 생성

  * 예측이 불가능하도록 안전한 난수 알고리즘을 적용

* 노출 방지
  * 세션 ID가 노출될 수 있는 URL Rewrite 기능을 사용하지 않도록 설계

* 재할당
  * 로그인 시 로그인 전의 세션 ID를 삭제하고 새 세션 ID를 할당

  * 장기간 접속 중인 세션 ID는 주기적으로 재할당되도록 설계


## 접근 제어 (2)

### 접근 제어 모델

* DAC(Discretionary Access Control)
  * 임의 접근 제어
  * 자원 소유자가 다른 사용자에게 접근 권한을 부여하거나 회수하는 방식
  * 권한 관리가 유연하지만 권한 전파로 보안 통제가 약해질 수 있음

* MAC(Mandatory Access Control)
  * 강제 접근 제어
  * 보안 등급과 정책에 따라 시스템이 접근을 강제로 통제하는 방식
  * 사용자가 임의로 권한을 변경할 수 없어 높은 보안이 필요한 환경에 적합

* RBAC(Role-Based Access Control)
  * 역할 기반 접근 제어
  * 사용자에게 직접 권한을 주지 않고 역할(Role)에 권한을 부여하는 방식
  * 조직의 직무나 책임 단위로 권한을 관리하기 쉬움

### 인가(Authorization)

* OAuth(Open Authorization)
  * 사용자가 자신의 비밀번호를 제3자 애플리케이션에 제공하지 않고, 특정 자원에 대한 제한된 접근 권한을 위임하는 표준

  * 접근 토큰(Access Token)을 사용해 인가를 처리하며, 인증 기능은 OpenID Connect(OIDC) 등 별도 계층에서 제공

## 보안 원칙 및 개발 보안 (4)

### 보안의 5대 요소 (5)

* 기밀성(Confidentiality)
  * 인가된 사용자만 정보에 접근할 수 있도록 보장하는 성질

  * 접근 제어, 암호화 등을 통해 정보 유출을 방지

* 무결성(Integrity)
  * 정보가 인가되지 않은 방법으로 변경·삭제·훼손되지 않도록 정확성과 완전성을 유지하는 성질

  * 해시 함수, 전자 서명, 접근 제어 등을 활용

* 가용성(Availability)
  * 인가된 사용자가 필요할 때 정보와 시스템 자원에 지체 없이 접근하여 사용할 수 있도록 보장하는 성질

  * 이중화, 백업, 장애 복구, DDoS 대응 등을 통해 확보

* 인증(Authentication)
  * 시스템에 접근하거나 거래를 요청한 주체가 주장하는 신원과 일치하는지 확인하는 과정

  * 비밀번호, OTP(One-Time Password), 생체 인증, 디지털 인증서 등을 사용

* 부인 방지(Non-repudiation)
  * 송신자 또는 수신자가 메시지 송수신이나 거래 사실을 나중에 부인하지 못하도록 보장하는 성질

  * 전자 서명, 타임스탬프, 감사 로그 등을 활용

### 인증 방식 (5)

* 지식 기반 인증(Knowledge-based Authentication)
  * 사용자만 알고 있는 정보를 사용해 신원을 확인하는 방식

  * 비밀번호, PIN(Personal Identification Number), 보안 질문 등이 해당

* 소유 기반 인증(Possession-based Authentication)
  * 사용자가 소유한 물리적 또는 디지털 수단으로 신원을 확인하는 방식

  * 스마트 카드, 보안 토큰, OTP 생성기, 휴대전화 인증 등이 해당

* 생체 기반 인증(Inherence-based Authentication)
  * 사용자의 고유한 신체적·행동적 특성을 이용해 신원을 확인하는 방식

  * 지문, 얼굴, 홍채, 음성, 서명 등이 해당

* 행위 기반 인증(Behavior-based Authentication)
  * 사용자의 평소 행동 패턴을 분석하여 신원을 확인하는 방식

  * 키보드 입력 속도·리듬, 마우스 움직임, 화면 조작 습관 등이 해당

* 위치 기반 인증(Location-based Authentication)
  * 사용자의 접속 위치 정보를 기준으로 신원을 확인하거나 추가 인증을 요구하는 방식

  * GPS, IP 주소, 접속 국가·지역 등을 활용

### Secure SDLC

* Secure SDLC(Secure Software Development Life Cycle)
  * 소프트웨어 개발 생명주기(SDLC)에 보안 활동을 통합하는 개발 방법론

  * 요구사항 분석 → 설계 → 구현 → 테스트 → 유지보수 전 단계에서 보안 취약점을 예방·발견·개선

  * 개발 완료 후 보안을 덧붙이는 방식보다 취약점 수정 비용과 위험을 줄일 수 있음

* 단계별 보안 활동
  * 요구사항 분석: 보안 요구사항과 준수해야 할 법·정책을 정의

  * 설계: 보안 아키텍처를 설계하고 위협을 분석하여 대응 방안을 수립

  * 구현: 시큐어 코딩을 적용하고 소스 코드의 보안 취약점을 점검

  * 테스트: 취약점 분석, 보안 테스트, 모의 해킹으로 취약점을 검증

  * 유지보수: 보안 패치를 적용하고 로그·취약점을 지속적으로 관리

### Secure SDLC 방법론 (2)

* CLASP(Comprehensive, Lightweight Application Security Process)
  * 개발 생명주기 초기부터 보안을 적용하기 위한 경량 애플리케이션 보안 프로세스

  * 역할 기반 보안 활동을 제시하여 개발자, 보안 담당자, 테스터가 각 단계에서 수행할 작업을 명확히 함

* Seven Touchpoints
  * 소프트웨어 개발 과정에 보안을 통합하기 위한 7개의 핵심 활동을 제시한 방법론

  * 보안 요구사항 정의, 악용 사례(Abuse Case) 작성, 위험 분석, 코드 검토, 보안 테스트, 침투 테스트, 보안 운영을 포함

## 보안 위험 관리 및 침해사고 대응 (3)

### 보안 위험관리 기본 개념 (4)

* 자산(Asset)
  * 조직이 보호해야 하는 가치 있는 대상

  * 고객 정보, 금융 거래 데이터, 서버, 애플리케이션, 업무 인력 등이 해당

* 위협(Threat)
  * 자산에 피해를 줄 수 있는 잠재적 원인이나 행위

  * 해커의 공격, 악성코드, 내부자 실수, 화재·정전 등이 해당

* 취약점(Vulnerability)
  * 위협이 악용할 수 있는 자산·시스템·절차의 약점

  * 미패치 서버, 약한 비밀번호, 과도한 접근 권한 등이 해당

* 위험(Risk)
  * 위협이 취약점을 이용하여 자산에 피해를 줄 가능성과 그 영향

  * 자산에 취약점이 존재하고 위협이 이를 이용할 가능성이 있을 때 위험이 발생

  * 예: 고객 정보 서버에 미패치 취약점이 있으면, 외부 공격자가 이를 악용해 정보 유출을 일으킬 위험이 있음

### 침해사고 대응 절차 (6)

* 준비
  * 대응 조직·연락망·절차를 마련하고, 로그 수집·백업·보안 도구를 사전에 갖춤

* 탐지 및 분석
  * 경보와 로그를 확인하여 침해 여부, 공격 범위, 원인과 영향을 분석

* 차단 또는 격리
  * 악성 IP·계정을 차단하고 감염 시스템을 네트워크에서 분리하여 확산을 막음

* 제거
  * 악성코드, 취약한 계정, 공격자가 남긴 설정·파일을 제거하고 취약점을 패치

* 복구
  * 안전한 백업과 검증된 설정을 이용해 서비스를 정상화하고 재발 징후를 모니터링

* 사후 분석
  * 사고 원인과 대응 결과를 검토하고, 정책·통제·교육·대응 절차를 개선

### 업무 연속성과 재해 복구 (4)

* BCP(Business Continuity Plan)
  * 재해·장애·침해사고 중에도 핵심 업무를 지속하기 위한 전사적 업무 연속성 계획

  * 대체 인력·업무 절차·대체 사업장·의사소통 체계까지 포함

* DRP(Disaster Recovery Plan)
  * 재해로 중단된 IT 시스템과 데이터를 복구하여 서비스를 재개하기 위한 계획

  * 백업, 이중화, 재해복구센터, 복구 절차 등 BCP의 IT 복구 영역에 해당

* RTO(Recovery Time Objective)
  * 장애 발생 후 서비스를 복구해야 하는 목표 시간

  * RTO가 4시간이면 장애 후 4시간 안에 서비스를 복구해야 함

* RPO(Recovery Point Objective)
  * 복구 시 허용할 수 있는 데이터 손실의 최대 시점 또는 시간 간격

  * RPO가 1시간이면 최대 1시간 전 데이터까지의 손실을 허용하므로 최소 1시간마다 백업이 필요

* 비교
  * BCP는 업무 전체의 지속 계획, DRP는 IT 시스템 복구 계획

  * RTO는 복구에 걸리는 시간 목표, RPO는 허용 가능한 데이터 손실 범위

## 보안 아키텍처 및 프레임워크 (2)

### 보안 아키텍처(Security Architecture)

* 정보 시스템의 무결성, 가용성, 기밀성을 확보하기 위해 보안 요소와 보안 체계의 관계를 정의한 구조

* 관리적·물리적·기술적 보안 개념을 수립하여 보안 관리 역량을 높이고 일관된 보안 수준을 유지

* 보안 수준과 보안 요구사항이 변해도 기본 보안 아키텍처를 크게 수정하지 않고 변화·추가 사항을 수용할 수 있어야 함

* ITU-T X.805
  * 보안 아키텍처 모델의 대표적인 표준

* 보안 영역 (3)
  * 관리적 보안
    * 정보보호 정책·조직, 정보 자산 분류, 정보보호 교육·훈련, 인적 보안, 업무 연속성 관리 등을 정의

  * 물리적 보안
    * 건물·사무실 출입 통제, 전산실 관리, 정보 시스템 보호 시설, 재해 복구 센터 운영 등을 정의

  * 기술적 보안
    * 사용자 인증, 접근 제어, PC·서버·네트워크·응용 프로그램·데이터베이스 보안 지침을 정의

### 보안 프레임워크(Security Framework)

* 안전한 정보 시스템 환경을 유지하고 보안 수준을 향상하기 위한 보안 관리의 뼈대와 체계

* ISO 27001
  * 정보보안 관리 시스템(ISMS; Information Security Management System)을 위한 국제 표준이자 대표적인 보안 프레임워크

  * 영국 표준 BS 7799를 기반으로 발전했으며, 조직의 정보보안 관리 규격을 정의하여 심사·인증에 활용

## Secure Coding (6)

### 보안 기능 개요

* 보안 기능
  * 소프트웨어 구현 단계에서 인증, 접근 제어, 기밀성, 암호화 등을 올바르게 구현하기 위한 기능과 보안 점검 항목

  * 서비스 환경과 처리 대상 데이터에 맞게 구현해야 함

* 적용 원칙
  * 사용자와 데이터의 중요도에 따라 차별화된 인증 방안을 적용

  * 인증된 사용자에게도 기능과 데이터별로 필요한 접근 권한만 부여하고, 인가되지 않은 접근을 차단

  * 개인정보·인증 정보 등 중요 정보는 변조·삭제·오남용을 방지하도록 안전한 암호화 기술을 적용

### 보안 기능의 보안 약점 (6)

* 적절한 인증 없이 중요 기능 허용
  * 인증 과정을 우회해 중요 정보 또는 기능에 접근·변경할 수 있는 취약점

  * 중요 기능을 수행하는 페이지는 재인증을 요구하여 방지

* 부적절한 인가
  * 접근 제어가 없는 실행 경로를 통해 정보 또는 권한을 탈취할 수 있는 취약점

  * 모든 실행 경로에서 접근 권한을 검사하고 최소 권한을 부여하여 방지

* 중요 자원에 대한 잘못된 권한 설정
  * 잘못된 권한 설정으로 중요 자원에 접근하거나 임의로 사용할 수 있는 취약점

  * 중요 자원은 관리자 등 필요한 사용자만 읽기·쓰기 권한을 갖도록 설정하고 접근 여부를 점검

* 취약한 암호화 알고리즘 사용
  * 취약한 알고리즘이나 암호 모듈을 사용하면 환경 설정 파일을 해독하여 중요 정보를 탈취할 수 있음

  * 검증된 안전한 암호화 알고리즘과 암호 모듈을 사용

* 중요 정보 평문 저장 및 전송
  * 평문 데이터를 탈취하면 중요 정보를 획득할 수 있는 취약점

  * 중요 정보는 저장·전송 시 암호화하고 HTTPS 또는 SSL 같은 보안 채널을 사용

* 하드코드된 비밀번호
  * 소스 코드에 포함된 비밀번호나 기본 비밀번호를 악용해 관리자 권한을 탈취할 수 있는 취약점

  * 비밀번호는 암호화해 별도 파일에 저장하고, 기본 비밀번호·기본 키의 사용을 피함

### OWASP(Open Web Application Security Project)

* 웹 애플리케이션 보안 취약점과 대응 방안을 연구하는 비영리 단체

* OWASP Top 10은 웹 애플리케이션에서 위험도가 높은 주요 취약점과 대응 방향을 정리한 목록

### 입력 데이터 조작 

* SQL Injection 
    * 입력란에 SQL 코드를 넣으면 DB가 그것을 명령으로 실행함

    * 인증 우회, 데이터 조회·변조·삭제, 관리자 권한 탈취 가능

    * 대응: 준비된 구문(Prepared Statement), 파라미터 바인딩, 입력값 검증

* URL 주소 연결
    * 사용자 입력값으로 이동할 URL을 직접 결정할 때 피싱 사이트로 이동

    * 대응: 화이트리스트 관리

* 경로 조작 및 자원 삽입 
    * 데이터 입출력 경로를 조작해 서버 자원 수정 삭제 

    * `../` 같은 경로 순회 문자열로 허용되지 않은 파일에 접근

    * 시스템 파일 조회, 설정 파일 유출, 임의 파일 삭제 가능

    * 대응: 허용된 경로만 사용, 파일명 화이트리스트 검증, 절대 경로 변환 후 접근 범위 확인

* 메모리 오버플로
    * 할당된 메모리 범위를 초과해 데이터를 기록하는 취약점

    * 대응: 메모리 버퍼 크기 설정

* 운영체제 명령어 삽입 
    * 사용자 입력값이 운영체제 명령어 실행 구문에 포함될 때 발생

    * 대응: 외부 입력을 명령어에 직접 연결하지 않음, 허용값 목록 검증

* 위험한 파일 업로드 
    * 공격자가 실행 가능한 파일을 서버에 업로드해 실행하는 공격

    * 대응: 확장자·MIME 타입 검증, 저장 파일명 암호화

* 크로스사이트 스크립팅(XSS; Cross-Site Scripting)
    * 웹 페이지에 악성 스크립트를 삽입해 사용자의 브라우저에서 실행하는 공격

    * 쿠키 탈취, 세션 탈취, 피싱 페이지 유도 가능

    * 대응: 출력값 이스케이프


### 입력 데이터 조작 예시 

* SQL Injection 
    * **공격 원리**

    서버가 아이디·비밀번호를 이렇게 조합한다고 가정:
    ```sql
    SELECT * FROM users WHERE id='[입력]' AND pw='[입력]'
    ```

    * **공격 유형 1: 로그인 우회**

    아이디 입력란에 `' OR '1'='1` 입력 시:
    ```sql
    SELECT * FROM users WHERE id='' OR '1'='1' AND pw='...'
    ```
    * `'1'='1'`은 항상 참 → WHERE 조건 전체가 참
    * 비밀번호 몰라도 로그인 성공

    * **공격 유형 2: 데이터 추출 (UNION 공격)**

    ```sql
    ' UNION SELECT id, pw FROM users --
    ```
    * `UNION`: 두 SELECT 결과를 합쳐 반환
    * 원래 쿼리 결과에 `users` 테이블 전체를 붙여서 화면에 출력
    * `--`: 뒤따라오는 SQL을 전부 주석 처리 → 나머지 조건 무력화
    * 결과: DB의 아이디·비밀번호 전부 노출

    * **피해**: 인증 우회, 데이터 유출·변조·삭제, DB 서버 장악

    * **대응 방법**

    | 방법 | 이유 |
    |------|------|
    | 준비된 구문(Prepared Statement) / 파라미터 바인딩 | 입력값을 "데이터"로만 처리, SQL 명령으로 해석 안 함 |
    | 특수문자 이스케이프 | `'` → `\'` 변환, SQL 구조 깨는 문자 무력화 |
    | 입력값 유효성 검사 | 허용된 형식(숫자·영문 등)만 통과 |
    | 최소 권한 DB 계정 사용 | 해킹당해도 SELECT만 가능 → DELETE·DROP 불가 |
    | ORM 사용 | 프레임워크가 안전한 쿼리 자동 생성 |

### CSRF와 XSS

* CSRF(Cross-Site Request Forgery)
  * 로그인되어 인증 쿠키를 가진 사용자의 브라우저가 의도하지 않은 요청을 보내도록 만드는 공격

  * 공격자는 게시글·메일 등에 송금 또는 비밀번호 변경 요청이 포함된 링크·폼을 심어, 인증된 사용자가 이를 열게 함

  * 사용자의 권한으로 계좌 이체, 개인정보 변경, 권한 변경 같은 중요 작업이 실행될 수 있음

  * 대응: 요청마다 예측 불가능한 CSRF Token 검증, SameSite Cookie 설정, 중요 작업 시 비밀번호·OTP 재인증

* XSS와 CSRF 차이
  * XSS는 취약한 웹 페이지에 악성 스크립트를 주입하여 사용자의 브라우저에서 실행하는 공격

  * CSRF는 스크립트 실행이 필수는 아니며, 이미 인증된 사용자의 권한을 이용해 서버에 요청을 보내는 공격

  * XSS는 출력값 이스케이프와 콘텐츠 보안 정책(CSP)으로, CSRF는 토큰 검증과 SameSite Cookie로 주로 대응

## 암호화

* 평문(Plaintext)을 암호문(Ciphertext)으로 변환하여 무단 접근 차단

### 대칭키 암호화

* 암호화·복호화에 동일한 키 사용
* 속도 빠름. 키 배송 문제(수신자에게 키를 안전하게 전달하기 어려움)

* AES; Advanced Encryption Standard: 128/192/256비트 키. 현재 표준. 빠르고 안전
* ARIA: 한국 국가표준(국정원). 128/192/256비트 키
* DES; Data Encryption Standard: 56비트 키. 현재 안전하지 않음
* SEED: 한국 표준(KISA). 128/256비트 키

### 비대칭키 암호화

* 공개키(Public Key)로 암호화, 개인키(Private Key)로 복호화
* 키의 분배 용이
* 복잡한 알고리즘. 느린 속도.
* 키 배송 문제 해결. 속도 느림 → 실제론 대칭키 교환 용도로 사용

* DSA; Digital Signature Algorithm: 디지털 서명 전용. 암호화 불가
* ECC; Elliptic Curve Cryptography: 타원곡선 이론 기반. RSA보다 짧은 키로 동일 보안 수준
* Rabin: 소인수 분해 기반. RSA 변형. 복호화 시 4개의 후보 평문 중 선택 필요
* RSA: 소인수 분해 문제 기반. 가장 널리 사용

### 해시 함수

* 임의 길이 입력 → 고정 길이 출력(해시값). 단방향 — 복호화 불가
* 무결성 검증, 비밀번호 저장, 디지털 서명에 활용

* MD5; Message Digest 5: 128비트 출력. 충돌 취약점 발견 → 보안 용도 사용 금지
* N-Hash: NTT 개발. FEAL 블록 암호 기반. 현재 취약점으로 사용 안 함
* SHA-1; Secure Hash Algorithm 1: 160비트 출력. 취약점 발견 → 폐기 권고
* SHA-256; Secure Hash Algorithm 256: 256비트 출력. 현재 가장 널리 사용되는 표준
* SHA-3; Secure Hash Algorithm 3: SHA-2와 다른 알고리즘(Keccak). NIST 표준
* SNEFRU: Ralph Merkle 설계. 128/256비트 출력. 차분 공격에 취약하여 현재 사용 안 함

### 솔트(Salt)

* 해시 함수에 입력하기 전 원문에 추가하는 임의의 랜덤값
* 목적: 동일한 비밀번호라도 다른 해시값 생성 → 레인보우 테이블 공격 방지
* 솔트는 해시값과 함께 DB에 저장. 비밀이 아님
* 예: `hash("password" + "a3f9x2")` → 사용자마다 다른 솔트 적용

### 전자서명·PKI·디지털 인증서

* 전자서명(Digital Signature)
  * 전자 문서의 송신자를 확인하고 문서가 변조되지 않았음을 검증하는 기술

  * 생성: 메시지 → 해시값 생성 → 송신자의 개인키로 해시값에 서명

  * 검증: 수신자가 송신자의 공개키로 서명을 검증하고, 수신한 메시지의 해시값과 비교

  * 제공 기능: 메시지 무결성, 송신자 인증, 부인 방지

  * 전자서명 자체는 메시지를 암호화하지 않으므로 기밀성을 제공하지 않음

* PKI(Public Key Infrastructure)
  * 공개키의 생성·배포·검증·폐기를 신뢰할 수 있게 관리하는 공개키 기반 구조

  * 공개키가 실제 소유자의 것인지 확인할 수 있게 하여 공개키 암호와 전자서명의 신뢰성을 높임

* CA(Certificate Authority)
  * 사용자의 신원을 확인한 뒤 디지털 인증서를 발급·관리하는 신뢰 기관

* 디지털 인증서(Digital Certificate)
  * 공개키, 소유자 정보, 유효 기간 등을 CA의 전자서명으로 묶은 전자 문서

  * 서버의 공개키와 신원을 연결하여 통신 상대가 진짜 서버인지 검증하는 데 사용

### SSL/TLS와 HTTPS

* SSL/TLS(Secure Sockets Layer/Transport Layer Security)
  * 클라이언트와 서버 사이의 통신 구간을 암호화하고 서버 신원을 검증하는 보안 프로토콜

  * SSL은 이전 규격이며 현재는 TLS를 사용; 일반적으로 SSL/TLS라고 함께 부름

* TLS Handshake
  * 클라이언트와 서버가 서버 인증서를 검증하고, 안전한 세션키를 합의하는 초기 연결 과정

  * 공개키 암호 방식은 서버 인증과 세션키 교환에 사용하고, 이후 실제 데이터는 빠른 대칭키 암호 방식으로 암호화

* HTTPS(HyperText Transfer Protocol Secure)
  * HTTP에 TLS를 적용한 웹 통신 방식

  * 통신 도청·변조와 가짜 서버 접속 위험을 줄이며, 브라우저는 서버 인증서 검증 결과를 바탕으로 연결을 신뢰

### 안전한 비밀번호 저장

* 사전 공격(Dictionary Attack)
  * 자주 쓰이는 비밀번호, 단어, 유출된 비밀번호 목록을 순차 대입하는 공격

  * 길고 예측하기 어려운 비밀번호와 다중 인증을 사용하여 피해를 줄임

* 레인보우 테이블 공격(Rainbow Table Attack)
  * 미리 계산한 평문과 해시값의 대응표를 이용하여 탈취한 해시값에서 원래 비밀번호를 찾는 공격

  * 사용자별 Salt를 추가하면 같은 비밀번호도 서로 다른 해시값이 되어 미리 만든 테이블을 재사용하기 어려움

* 반복 해싱(Key Stretching)
  * 비밀번호와 Salt를 여러 번 해싱하여 하나의 비밀번호 검증에 필요한 계산 비용을 높이는 방법

  * 공격자의 대량 대입 속도를 낮추며, bcrypt·scrypt·Argon2 같은 비밀번호 해시 함수를 사용할 수 있음

* 저장 원칙
  * 비밀번호는 평문으로 저장하면 DB 유출 시 즉시 노출되고, 일반 암호화는 복호화 키가 유출되면 원문이 모두 노출될 수 있음

  * 비밀번호는 Salt와 단방향 해시 기반의 느린 비밀번호 해시 함수로 저장하고, 로그인 시 입력값을 같은 방식으로 계산해 비교

## 보안 솔루션 및 기술 (21)

### 방화벽(Firewall)

* 기업이나 조직 내부의 네트워크와 인터넷 간에 전송되는 정보를 선별하여 수용·거부·수정하는 기능을 가진 침입 차단 시스템

* 내부 네트워크에서 외부로 나가는 패킷은 그대로 통과시키고, 외부에서 내부 네트워크로 들어오는 패킷은 내용을 엄밀히 확인하여 인증된 패킷만 통과시키는 구조

### TCP 래퍼(TCP Wrapper)

* 외부 컴퓨터의 접속 요청을 확인하여 인가된 호스트의 접속만 허용하고 나머지는 차단하는 보안 도구

* 비인가 사용자가 네트워크 서비스에 접근해 다른 사용자의 계정·로그 정보를 악용하는 것을 방지하는 호스트 기반 방화벽 역할

### IDS(Intrusion Detection System)

* 컴퓨터 시스템의 비정상적인 사용, 오용, 남용 등을 실시간으로 탐지하는 시스템

* 오용 탐지(Misuse Detection)
  * 미리 입력해 둔 공격 패턴이 감지되면 이를 알려줌

* 이상 탐지(Anomaly Detection)
  * 평균적인 시스템 상태를 기준으로 비정상적인 행위나 자원 사용이 감지되면 이를 알려줌

### IPS(Intrusion Prevention System)

* 비정상적인 트래픽을 능동적으로 차단하고 격리하는 등의 방어 조치를 취하는 보안 솔루션

* 방화벽과 침입 탐지 시스템을 결합한 것

* 방화벽과 침입 탐지 기능으로 패킷을 하나씩 검사한 후 비정상적인 패킷이 탐지되면 방화벽 기능으로 해당 패킷을 차단

### DPI(Deep Packet Inspection)

* OSI 7계층의 프로토콜 정보를 분석하여 침입·해킹 시도를 탐지하고 트래픽을 제어하는 기술

### 허니팟(Honeypot)

* 공격자가 접근하도록 유도하기 위해 의도적으로 배치한 가짜 시스템·서비스·데이터

* 정상 사용자가 없으므로 발생한 접근·행위는 공격 징후로 판단하고 공격 기법·악성코드 정보를 수집

* IDS·IPS를 보완하는 수단이며, 실제 시스템 보호 수단을 대체하지 않음

### DLP(Data Loss Prevention)

* 내부 정보의 외부 유출을 방지하는 보안 솔루션

* 사내 직원이 사용하는 PC와 네트워크상의 모든 정보를 검색하고, 메일·메신저·웹하드·네트워크 프린터 등의 사용자 행위를 탐지·통제하여 외부 유출을 사전에 방지

### 웹 방화벽(Web Firewall)

* 일반 방화벽이 탐지하지 못하는 SQL 삽입 공격, Cross-Site Scripting(XSS) 등의 웹 기반 공격을 방어할 목적으로 만들어진 웹 서버에 특화된 방화벽

* 웹 관련 공격을 감시하고 공격이 웹 서버에 도달하기 전에 차단

### VPN(Virtual Private Network)

* 인터넷 등 통신 사업자의 공중 네트워크와 암호화 기술을 이용하여 사용자가 마치 자신의 전용 회선을 사용하는 것처럼 해주는 보안 솔루션

* SSL VPN
  * PC에 VPN Client 프로그램을 설치하여 VPN 서버에 접속하는 방식
  * 암호화를 위해 SSL 프로토콜 사용

* IPSec VPN
  * VPN 서버가 설치된 각각의 네트워크를 서로 연결하는 방식
  * 암호화를 위해 IPSec 프로토콜 사용

### NAC(Network Access Control)

* 네트워크에 접속하는 내부 PC의 MAC 주소를 IP 관리 시스템에 등록한 후 일관된 보안 관리 기능을 제공하는 보안 솔루션

* 내부 PC의 소프트웨어 사용 현황을 관리하여 불법적인 소프트웨어 설치를 방지

### SIEM(Security Information and Event Management)

* 다양한 장비에서 발생하는 로그 및 보안 이벤트를 통합하여 관리하는 빅데이터 기반의 보안 솔루션

* 방화벽, IDS, IPS, 웹 방화벽, VPN 등에서 발생한 로그 및 보안 이벤트를 통합하여 관리함으로써 비용 및 자원을 절약

* 장기간의 로그 및 보안 이벤트를 수집 및 검색할 수 있는 빅데이터 기반의 통합 로그 수집 시스템

### SSH(Secure Shell)

* 다른 컴퓨터에 로그인, 원격 명령 실행, 파일 복사 등을 수행할 수 있도록 다양한 기능을 지원하는 프로토콜 또는 이를 이용한 응용 프로그램

* 데이터 암호화와 강력한 인증 방법으로 보안성이 낮은 네트워크에서도 안전하게 통신

* 키(Key)를 통한 인증 방법을 사용하려면 사전에 클라이언트의 공개키를 서버에 등록해야 함

* 기본 포트: 22번

### Secure OS

* 운영체제(OS; Operating System)에 보안 기능을 통합하여 시스템 자원과 정보를 보호하는 운영체제

* 보안 정책에 따라 사용자·프로세스의 자원 접근을 통제하고, 비인가 접근과 권한 오남용을 방지

* 보안 커널(Security Kernel)
  * 운영체제 내부에서 접근 통제 정책을 강제하는 핵심 구성 요소

  * 모든 자원 접근을 검사하여 인가된 요청만 허용

* 핵심 기능
  * 식별·인증, 임의·강제 접근 통제, 객체 재사용 보호, 완전한 조정, 신뢰 경로, 감사 및 감사기록 축소

* 분리 기법 (4)
  * 암호적 분리
    * 자원 또는 데이터를 암호화하여, 복호화 권한이나 키가 있는 주체만 접근하도록 분리하는 방식

  * 논리적 분리
    * 하나의 시스템 안에서 접근 제어 정책, 권한, 주소 공간 등을 이용해 사용자·프로세스·데이터를 분리하는 방식

  * 시간적 분리
    * 동일한 자원을 서로 다른 사용자나 프로세스가 서로 다른 시간대에 사용하도록 하여 분리하는 방식

  * 물리적 분리
    * 서버, 저장장치, 네트워크 등 하드웨어 자원을 물리적으로 분리하여 공유를 차단하는 방식

### StackGuard

* 스택 버퍼 오버플로 공격을 방어하는 컴파일러 기반 보안 기법

* 반환 주소 앞에 카나리(Canary) 값을 저장하고, 함수 종료 전 값이 변경되었는지 검사

* 카나리 값이 변경되면 버퍼 오버플로가 발생한 것으로 판단하여 프로그램 실행을 중단

### Tamper Proofing

* 소프트웨어의 위·변조가 발생할 경우 소프트웨어를 오작동하게 만들어 악용을 방지하는 기술

* 해시 함수(Hash Function), 핑거 프린트(Fingerprint), 워터마킹(Watermarking) 등의 보안 요소를 생성하여 소프트웨어에 삽입하고, 실행 코드를 난독화하며, 실행 시 원본 비교 및 데이터 확인을 수행하여 소프트웨어를 보호

### DLT(Distributed Ledger Technology)

* 중앙 관리자나 중앙 데이터 저장소 없이 P2P(Peer-to-Peer) 네트워크의 참여자가 거래 기록을 분산 저장

* 거래 발생 시 이를 지속적으로 갱신하는 디지털 원장

* 블록체인이 대표적

### QKD(Quantum Key Distribution)

* 양자 통신을 위해 비밀키를 분배하여 관리하는 기술 

* 두 시스템이 암호 알고리즘 동작을 위한 비밀키를 안전하게 공유하기 위해 양자 암호키 분배 시스템을 설치하여 운용하는 방식으로 활용

### PET(Privacy-Enhancing Technology)

* 암호화, 익명화 등 개인정보를 보호하는 기술에서 사용자가 직접 통제하기 위한 기술까지 여러 프라이버시 보호 기술 통칭

### PIA(Privacy Impact Assessment)

* 개인정보를 처리하는 신규 정보시스템을 도입하거나 기존 시스템을 크게 변경할 때, 구축·운영이 정보 주체의 사생활에 미칠 영향을 사전에 조사·분석·평가하는 제도

### BitLocker

* Windows 7부터 지원되기 시작한 Windows 전용의 볼륨 암호화 기능 

* TPM, AES-128 알고리즘 사용

## 저작권 보호

### DRM 구성요소

* DRM(Digital Rights Management)
* 디지털 콘텐츠의 무단 복제·배포를 방지하고 저작권자의 권리를 보호하는 기술

* DRM 컨트롤러: 사용자 단말에서 라이선스 검증 후 콘텐츠 복호화·실행
* 보안 컨테이너: 암호화된 콘텐츠 저장 단위
* 콘텐츠 분배자(Contents Distributor): 암호화된 콘텐츠 유통·배포
* 콘텐츠 제공자(Contents Provider): 원본 콘텐츠 제공. 저작권자
* 클리어링 하우스(Clearing House): 라이선스 발급·관리. 사용 권한 및 조건 제어
* 패키저(Packager): 콘텐츠를 암호화하고 메타데이터와 함께 패키징


### DRM 기술

* 암호화: 콘텐츠 무단 접근 차단
* 암호화 파일 생성: 원본 콘텐츠를 암호화하여 보안 컨테이너로 패키징
* 식별 기술: 콘텐츠·사용자·디바이스에 고유 ID 부여. 워터마킹·핑거프린팅 포함
* 인증: 콘텐츠 요청 사용자·디바이스의 신원 확인 후 라이선스 발급
* 저작권 표현: 사용 조건(재생 횟수, 기간, 복사 허용 여부 등)을 라이선스로 명시
* 정책 관리: 콘텐츠별 접근·사용 정책 설정 및 집행
* 크랙 방지: 역공학·디버깅·우회 시도 탐지 및 차단
* 키 관리: 암호화·복호화에 사용되는 키 생성·배포·폐기 관리

### 소프트웨어 에스크로(Software Escrow)

* 소프트웨어 개발자가 소스 코드, 기술 문서 등을 신뢰할 수 있는 제3자에게 임치하는 제도

* 개발사 파산, 유지보수 중단, 계약 위반 등 사전에 정한 조건이 발생하면 사용자에게 임치물을 제공

* 사용자가 소프트웨어를 계속 유지보수·운영할 수 있게 하며, 개발사의 영업 비밀과 사용자의 지속 운영권을 함께 보호

## 개념/단어

### OTP

* One-Time Password. 한 번만 사용할 수 있는 일회용 비밀번호

* 매번 다른 인증 값을 생성하여 고정 비밀번호가 탈취되어도 재사용 공격을 어렵게 함

* 시간 기반 OTP(TOTP; Time-based One-Time Password)는 일정 시간마다 새로운 번호를 생성

* 이벤트 기반 OTP(HOTP; HMAC-based One-Time Password)는 인증 요청이나 버튼 입력 같은 이벤트마다 새로운 번호를 생성

* 로그인, 금융 거래, 관리자 접근 등에서 2단계 인증 수단으로 사용
