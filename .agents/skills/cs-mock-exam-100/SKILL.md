# 전산 모의시험 100문항 생성

한국어 5지선다형 단일정답 100문항을 작성한다.

## 출제 설계

출제 전에 적용되는 AGENTS.md와 필요한 문서만 확인한다. 기존 자료는 용어와 학습 범위를 확인하는 데 활용하고, 기존 문제의 숫자나 이름만 바꿔 재사용하지 않는다. 별도 요청이 없으면 문제는 새로 만든다.

기본 출제 범위는 아래 9개 영역이다. 사용자가 영역 포함·제외 또는 비율을 지정하면 이를 우선한다. 제외 요청은 해당 요청에만 적용하며, 별도 요청이 없으면 정보전송과 정보통신기기를 통합한 정보통신도 포함한다.

활성 영역 수를 k라 할 때 각 영역에 `100 // k`문항을 배정하고 나머지 `100 % k`문항은 표 순서대로 한 문항씩 추가한다. 회차를 지정하면 활성 영역 순서를 유지한 채 추가 배정 시작 위치를 회차마다 한 칸씩 순환한다(1회차는 첫 영역). 사용자 지정 비율이 있으면 이를 우선하되 합계는 100문항으로 맞춘다.

- 기본 9개 영역: 네트워크 12문항, 나머지 각 11문항, 총 100문항.

네트워크는 프로토콜·주소·통신 동작을, 정보통신은 신호·물리계층·전송 이론과 통신 장치의 구성·역할·동작 원리를 중심으로 구분한다. 정보통신에서는 전송 이론·계산·기기 동작을 고르게 포함하고, 부호화·변조·다중화는 하나의 통합 범위로 다룬다. 자료구조·알고리즘은 자료 표현·풀이 전략·복잡도, 프로그래밍은 언어 문법·실행 의미를 중심으로 나눈다. 컴퓨터구조는 하드웨어 구성·동작·성능, 운영체제는 프로세스·자원 관리 정책을 중심으로 구분한다. 캐시 주소 분해·CPU 성능·파이프라인·DMA는 컴퓨터구조, 페이지 교체·프로세스 스케줄링·가상 메모리 관리 정책은 운영체제로 배정한다. 경계에 걸친 문항은 주된 평가 개념 하나에만 배정한다.

각 영역에서 최소 4개 세부 주제를 다루고 같은 개념을 사실상 반복하는 문제를 피한다. 기본 난도는 하 30·중 50·상 20문항이며, 각 영역에 세 난도를 포함한다. 단순 정의 암기에 치우치지 않게 적용·추론·계산·코드 추적 문제를 함께 구성한다. 상 난도는 지엽적 용어보다 여러 개념의 적용으로 만든다. 난도는 출제자의 추정치임을 명시한다.

작성 중 문항 번호, 영역, 세부 주제, 난도, 정답은 내부 출제표로 관리하고 별도 파일로 저장하지 않는다. 영역 문항 수와 난도 총합을 모두 맞춘 뒤 출력한다. 기본 배열은 위 표의 영역 순서대로 같은 영역의 문제를 연속 배치한다. 각 영역 시작에는 `## 네트워크`처럼 영역명을 제목으로 표시한다. 영역이 바뀌어도 문항 번호는 다시 시작하지 않고 1~100으로 연속 부여한다. 문제지에는 난도·정답 힌트를 표시하지 않는다. 사용자가 영역 혼합형을 명시적으로 요청하면 그 배열을 따르되 각 문항에 영역명을 표시한다.

프로그래밍은 기초 문법과 출력 추적뿐 아니라 다형성에 따른 메서드 호출·필드 접근, 언어별 키워드의 의미와 적용, 동시성 등도 출제 범위에 포함한다. 특정 개념이나 키워드를 매회 필수로 고정하지 않고 요청 범위와 문항 수에 맞춰 고르게 선정한다.

## 문항 품질

- 각 문항에는 정답이 정확히 하나만 있어야 한다. 오답은 흔한 오개념이나 계산 실수를 반영하되 다른 조건에서 정답이 되는 표현을 방치하지 않는다.
- SQL은 테이블·데이터·NULL·중복 및 필요한 방언을 명시한다. 정렬 결과를 묻는다면 ORDER BY를 명시한다.
- C의 미정의 동작, Java 평가 순서, Python 참조·가변성 등 언어별 의미를 확인한다. 미정의 동작을 확정 출력값으로 출제하지 않는다.
- 언어별 키워드와 동시성의 보장은 명세에 따라 확인하고, 실행 순서에 따라 달라지는 결과를 하나로 단정하지 않는다.
- 컴퓨터구조 계산은 비트 폭·부호 표현·바이트 주소 여부를 명시한다. 캐시는 용량의 데이터 영역 기준 여부·블록 크기·연관도·초기 상태를, CPU 성능과 파이프라인은 클록·CPI·단계 수·정지 및 분기 비용 중 답에 영향을 주는 조건을 명시한다.
- 계산 문제는 단위, 반올림, 초기 상태 및 알고리즘의 동률 처리 조건을 명시한다. KB/KiB, bit/byte, 로그 밑, 오버헤드 포함 여부가 답에 영향을 주면 밝힌다.
- 계산·SQL·코드 추적은 가능한 경우 작은 실행이나 독립적인 재계산으로 검증한다. 실행 환경이 없으면 수작업 추적 후 실제 실행 여부를 정확히 보고한다.
- 변동 가능한 법규·표준·버전이나 확신하기 어려운 사실을 사용하면 공식 문서로 확인하고 필요한 근거는 문제지 안에 남긴다. 외부 확인이 불가능하면 안정적인 기초 개념으로 대체한다. 출처나 기출 연도를 만들지 않는다.
- 정답 위치는 기본적으로 ①~⑤ 각 20개로 균형을 맞추고 규칙적인 순환을 피한다. 숫자·시간순 등 자연스러운 선지 순서를 훼손하지 말고 다른 문항에서 조정한다. 선지 재배열 후 정답을 다시 맞춘다.

## 결과물

결과물은 `문제지.md` 한 파일뿐이다.
정답은 각 문항의 선지 아래에 `> **정답: ②**` 형식으로 표시한다.

문제지에는 제목, 총 100문항, 문항당 1점·총 100점, 응시 안내를 포함한다. 기본 권장 시간은 100분으로 쓰되 공식 시험 시간이라고 표현하지 않는다. 각 영역 시작에 영역 제목을 넣고 해당 영역의 문제를 연속 배치한다. 문제 사이에는 `---`를 쓰고 선지마다 빈 줄을 둔다.

```markdown
## 네트워크

### 1

Q. 문제 내용

① 선지

② 선지

③ 선지

④ 선지

⑤ 선지

> **정답: ②**

---
```

영역별 문항 수, 난도별 문항 수, 정답 위치별 문항 수는 내부적으로 집계해 검증한다. 별도 집계 파일은 만들지 않고 최종 응답에 검증 결과를 짧게 알린다.

## 완료 전 확인

정확히 100문항인지, 번호 누락·중복이 없는지, 모든 문제에 ①~⑤ 다섯 선지가 있는지, 영역별 문항 수가 활성 영역과 사용자 지정 조건에 따른 배정과 일치하는지, 제외 영역이 출제되지 않았는지, 난도 합계와 정답 분포가 계획과 일치하는지 확인한다. 기본 배열에서는 같은 영역의 문항이 하나의 연속 구간에 모여 있고, 각 구간의 영역 제목이 실제 문항 영역과 일치하는지 확인한다. 각 문항에 표시한 정답이 최종 선지 순서와 일치하는지 검토한다. 조건 누락·복수정답·중복 문제·다른 문항의 정답 노출을 수정한다. 분량 때문에 문항이나 정답을 생략하거나 자리표시자로 남기지 않는다. 결과 폴더에 요청한 문제지 한 파일만 생성했는지 확인한다. 최종 응답에는 결과물 경로와 실제 수행한 검증, 적용 문서 ID를 간단히 알린다.
